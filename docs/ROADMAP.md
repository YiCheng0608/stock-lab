# 產品路線與能力邊界

本文件管理產品方向及未完成核心，已驗能力見[目前產品能力](CAPABILITIES.md)；版本任務在 GitHub milestone，排序與狀態在 Issues／Projects（入口見[工作手冊](WORKFLOW.md#欄位與唯一來源)）。流程依 [AGENTS](../AGENTS.md)。

## V2 方向

使用者 2026-11-11 核定（雲端 session 的架構檢視後；統籌記入 [#1](https://github.com/YiCheng0608/stock-lab/issues/1) 決策索引）。V1 做到每天產出一份名單；V2 的目標是：**每一檔被選出來的股票都說得出依據，而且依據有歷史數字支持。** 產品定位不變：以資料與情報選出下一個交易日可以考慮進場的股票，並給進場區、停損與目標價位。產品保留進場區、停損、目標價，但只顯示通過驗證的策略的點位（點位必須是登記的假設定義的一部分）；驗證過之前，現行規則的點位照常顯示、頁面不加研究狀態標示（使用者 2026-11-15 決定 [#1 6880591509](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6880591509)、[6881297699](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6881297699)，統籌定案 [6880927520](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6880927520)、[#721 6881306136](https://github.com/YiCheng0608/stock-lab/issues/721#issuecomment-6881306136)）。月營收、財報等基本面可以成為條件，但每一項都先有證據才納入。什麼算證據、研究怎麼做見[策略證據](spec/evidence.md)。

| 階段 | 完成後使用者得到什麼 | 內容 | 前提 |
| --- | --- | --- | --- |
| 一、知道現況 | 知道現在這套名單有沒有贏過大盤、每個條件有沒有用 | 候選成績單（上線以來的名單對同日母體與加權指數的事後表現）；特徵證據（現行條件與價量、籌碼、月營收、季報 EPS 各特徵的預測力）。[#619](https://github.com/YiCheng0608/stock-lab/issues/619) | 無 |
| 二、依證據重做選股與進出場 | 名單的排序與進出場規則有數字依據 | 評分改版（權重依證據訂；沒有證據的分項拿掉或只顯示；有證據的特徵加入，升版）；出場規則研究（固定目標一出場對比移動停利與時間出場）；組合層級回測（每天買前 N 檔、持有 K 天的資金曲線對加權指數，含實際成本與漲停買不到）；歷史回補到 5 年以上 | 階段一的結果；歷史回補的範圍與來源由使用者另行決定 |
| 三、把依據做進產品 | 在畫面上看得到每一檔為什麼被選、這套系統最近準不準、買了之後該怎麼辦 | 每檔候選的理由旁標示有無歷史證據；成績單做成頁面、每月更新；持倉管理（續抱、減碼、出場的每日提示） | 階段二 |

### 階段一的成功標準

跑之前固定，看完結果不改（[研究規則](spec/evidence.md#研究規則)第 3 條）。數字出自[候選成績單](spec/evidence.md#兩個問題兩個工具)，t 值是該文件定義的保守值。

| 判定 | 條件 |
| --- | --- |
| 名單有效 | 候選累積至少 60 個交易日；T+20 對同日母體平均的超額報酬 > 0 且 t ≥ 2；對加權指數的超額報酬 > 0；T+5 的超額報酬同號 |
| 排序有效 | 同上的樣本下，總分與之後報酬的每日排序相關平均 > 0 且 t ≥ 2 |
| 方向一致但不顯著 | 超額報酬 > 0 但 t < 2：不下結論，每月重跑累積 |
| 無效 | 至少 60 個交易日後，T+20 對同日母體的超額報酬 ≤ 0 |
| 樣本不足 | 不到 60 個交易日：只記錄，不判定 |

候選名單上線不久（起訖日以成績單報告為準），滿 60 個交易日之前一律是「樣本不足」；早期的依據以特徵證據（2024-09-30 起）為主。

### 結果不如預期時

依序處理，每一步的結果都在 [#1](https://github.com/YiCheng0608/stock-lab/issues/1) 回報：

1. 現行條件裡「沒有證據」或「驗證段反轉」的，提案移除或改為只顯示，由使用者決定。提案不能讓今日名單停產：現行兩條規則就算在長歷史上也沒有優勢，今日名單仍每天產出，要等新規則通過驗證、使用者同意替換才換（使用者 2026-11-15，[#1 6891614350](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6891614350)）。
2. 特徵裡有「有證據」的，照階段二用它們重做評分；現行兩條進場規則不是前提，可以整組換掉。
3. 特徵與名單都沒有證據時，停止策略研究並回報使用者。產品改以篩選與紀律為主：首頁維持「今日名單」、不顯示任何預期報酬或勝率，工作轉到出場規則、部位與風險、每日提醒；要不要回補歷史再驗一次由使用者決定。使用者 2026-11-14 決定不停止、回補歷史並繼續找策略，見[現況與方向](#現況與方向2026-11-14)。

### 階段二的先後

1. **出場規則**：不需要新資料，用現有研究回測比較固定目標一、移動停利與時間出場。
2. **組合層級回測**：衡量第 1 項與之後每一項有沒有用的尺。
3. **評分改版**：依階段一的特徵證據。
4. **歷史回補**：前三項的結論在兩年資料上站不穩時才做；範圍與來源由使用者決定。使用者 2026-11-14 決定做，補到各官方來源最早可得（[#692](https://github.com/YiCheng0608/stock-lab/issues/692)）。

### 現況與方向（2026-11-14）

階段一的特徵證據與階段二前三項都跑完了，報告在各 Issue，方法與判定在[策略證據](spec/evidence.md)：

| 項目 | 結果 |
| --- | --- |
| 階段一：特徵證據（[#619](https://github.com/YiCheng0608/stock-lab/issues/619)、[#671](https://github.com/YiCheng0608/stock-lab/issues/671)） | 現行 8 個條件全部「沒有證據」；特徵裡只有「投信近 5 日買超天數」T+5「有證據」 |
| 階段一：候選成績單 | 樣本不足；候選滿 60 個交易日（約 2027 年 1 月中）才判定 |
| 階段二第 1 項：出場規則（[#673](https://github.com/YiCheng0608/stock-lab/issues/673)） | 7 種替代出場 × 兩條規則全部「沒有差異」，出場不改；兩條進場規則扣成本後每筆平均為負 |
| 階段二第 2 項：組合層級回測（[#682](https://github.com/YiCheng0608/stock-lab/issues/682)） | 照名單買前 N 檔、持有 K 天，9 組對母體全部「沒有差異」，沒有一組贏過加權指數 |
| 階段二第 3 項：評分改版研究（[#689](https://github.com/YiCheng0608/stock-lab/issues/689)） | 用有證據的特徵排序，照事先固定的讀法沒有一個排序站得住；產品的評分不改 |

結論是現行兩條進場規則沒有優勢。使用者 2026-11-14 決定不停止策略研究，方向改為**有紀律地找有優勢的策略**（[#1](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6872448519)），取代「結果不如預期時」第 3 步的「停止策略研究」：

1. **前瞻驗證**（[#691](https://github.com/YiCheng0608/stock-lab/issues/691)）：#689 唯一的線索固定成單一假設 H1，工具與參數凍結。H1 成立與否以回補出來、沒被用來挑 H1 的歷史段（2024-09-27 以前，「歷史樣本外」）那一次的判定為準；2026-11-14 以後的新資料照常每月重驗，只當紀錄（使用者 2026-11-14 決定，[#1](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6880114734) 第 3 項，[#721](https://github.com/YiCheng0608/stock-lab/issues/721)）。
2. **歷史回補**（[#692](https://github.com/YiCheng0608/stock-lab/issues/692)）：見上面第 4 項。
3. **新策略探索**（歷史回補後開單）：不再修補現行兩條規則。每個假設在跑之前寫死，在長歷史上分探索與驗證兩段；每個假設在它需要的資料驗收後各跑一次探索、報告都公開，再跑只跑一次的驗證段。歷史上通過就可以提案進產品，由使用者決定；前瞻改成進產品之後的監測，判到明顯輸給母體就提案下架（[#1](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6880114734) 第 2 項，規則見[新策略探索](spec/evidence.md#新策略探索)）。驗證段贏母體但不顯著的記「前瞻觀察」，只累積紀錄、不進產品。候選方向：持有較久、低換手；籌碼加基本面；大型股傾向；事件（月營收公布、重大訊息）。
4. **產品**（[#693](https://github.com/YiCheng0608/stock-lab/issues/693)、[#729](https://github.com/YiCheng0608/stock-lab/issues/729)）：今日名單照常每天產出，價位陳述規則價位、不寫成下單指示；研究狀態不放頁面，留在 Issue（#729 取代 #693 的「現行規則尚無證據」標示）；策略在歷史上通過驗證、使用者同意後才做進產品，它的點位必須是登記的假設定義的一部分（[#1](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6880927520)）。提案與報告第一個列對加權指數的超額，判定仍只比等權母體。今日名單之外並列第二份「主流族群前 20」（使用者 2026-11-15 決定，見下面「已排入」）。

一個策略算有優勢的標準：扣成本後期望值為正，而且探索與驗證兩段都贏過母體；勝率只是參考。「結果不如預期時」第 1 步（沒有證據的現行條件移除或改為只顯示）等候選滿 60 個交易日重跑成績單後再提。階段三裡需要「有證據的策略」的項目（每檔理由旁標示證據、成績單頁面）等策略通過驗證後才做。

### 部位與風險（階段三）

使用者設定每筆願意承擔的損失金額後，候選才顯示建議張數（金額 ÷（進場價 − 停損價），無條件捨去到整張）；沒有設定就不顯示張數（[PRODUCT_SPEC §5](PRODUCT_SPEC.md#5-一檔一張行動摘要與完整交易計畫)）。同一天多檔候選屬於同一族群時提示曝險重疊，不把它們當成各自獨立的機會。

### 未排入的候選方向

排入前各自先開單評估，由使用者決定：

- **事件研究**：用已有的重大訊息與月營收公布日，量特定事件之後 5／20 日的超額報酬，同時檢驗新聞 AI 方向判讀有沒有用。
- **以模型組合特徵**：取代人訂的權重。兩年資料容易只記住這段歷史，等歷史回補後再評估。

不做：沒有證據支持的新技術指標或進場條件；更多 AI 生成的說明文字。上面的「主流族群前 20」只排序、不附點位，不算進場條件；使用者是在知道它沒有歷史證據的前提下選擇並列。

### 順序與取捨


- 階段一跑完前不開新的「對現行兩條規則加減條件」的研究單（#318、#546、#567 三輪的差距都在雜訊內；#598 未產出結果，2026-11-12 關單）；連續兩輪沒有新的證據就停手回報（[研究規則](spec/evidence.md#研究規則)）。
- 畫面與策略並行。畫面方向為「盤後終端」（使用者 2026-11-11 選定）：圖優先、資訊密、文字少。第 1 步是個股頁 K 線的規則價位線（[#617](https://github.com/YiCheng0608/stock-lab/issues/617)）；第 2 步是今日名單改成左清單（走勢線、價位尺）右圖，並一併改名：主導航「今日可買→今日名單」「觀察中→我的追蹤」「策略說明→策略與成績」，個股頁分頁「圖表與指標→走勢」「法人籌碼→籌碼」「研究條件→進出場」「資料說明→資料來源」；之後是個股頁圖表上移、我的追蹤頁重排、分數與強弱改用圖形、每頁資料日期只標一次。改版與改名同一張單做，同步改 [UI_COPY_SPEC](UI_COPY_SPEC.md)、[DESIGN_SYSTEM](DESIGN_SYSTEM.md) 與 verify 檢查。
- 「今日可買」改名為「今日名單」是因為目前沒有證據支持「可買」；成績單顯示名單穩定贏過同日母體後可以改回。
- 券商分點以免費公開來源不可行（[#548](https://github.com/YiCheng0608/stock-lab/issues/548)：官方逐檔日報表每檔要驗證碼且條款禁止自動化，FinMind 分點資料只限付費會員），維持不做。集保戶股權分散表現階段不收集：開放資料只保留當週、歷史補不回來，要累積數月才能驗證，排在後面（使用者 2026-11-11）。擴充資料來源本身是歡迎的；要不要納入一項資料，看兩件事：對之後的報酬有沒有預測力、現在驗證得了嗎（[策略證據](spec/evidence.md)），不看它多久更新一次。每日資料決定進出場的時機，月營收、季報這類更新慢的資料用來篩選值得看的股票。

## V1 範圍基線（2026-10-17 核定）

使用者於 2026-10-17 核定。V1 定位為 **研究輔助 app**：像一般股票 app 可查個股資訊，並以國內外新聞與技術指標給出建議進出點，每日排程更新熱門族群、候選股票與進出點。

- **範圍**：台灣上市（TWSE）與上櫃（TPEx）全部普通股；ETF 收集並分類，但不進候選清單。
- **使用者需求對應**：N1 個股資訊（K 線、成交量、均線、MACD、RSI、KD、布林、籌碼、新聞）；N2 依新聞與技術指標分析建議進出點；N3 每日排程更新國內外新聞、熱門族群與熱門股候選，並據此更新進出點。
- **顯示原則**：有資料就顯示並標來源與資料日期；缺資料留空並標「無資料」，不補零、不混來源、不以較早或未來日替代；LLM 推論與來源事實分欄並標「推論」。
- **資料與保存**：官方 TWSE／TPEx 整批下載為每日主來源（行情、法人、融資、官方事件），FinMind 補歷史與缺口；先回補 2～3 年日線；指標每日批次計算標量，不預存陣列；raw 回應保留 30～90 天；單一 SQLite 檔（全市場 10 年行情＋籌碼＋索引約 2.5 GB）。
- **新聞**：每日排程抓國內與國際免費公開來源進 DB；保存來源、時間、標題、摘要、關聯個股／族群、方向判讀、原文連結，正文可選；去重與時間規則依[新聞規格](NEWS_SPEC.md)。
- **熱門族群**：官方產業分類＋人工維護題材表（版本化、含生效／失效日）為底（新聞聚合的題材建議已於 #629 移除，題材表只由人工維護）；`hot_group_v1` 五分項沿用，產業與題材各算一榜並可切換。
- **進出點**：規則式為主，保留 `breakout_v1`／`pullback_v1` 原公式與版本，新增指標條件以升版方式加入；技術＋籌碼＋新聞情緒評分只用於排序；LLM 只寫說明文字；進場區／停損／目標／RR 由策略與 ATR 推算。
- **指標**：MA5／10／20／60／120、MACD(12,26,9)、RSI(6,12)、KD(9,3,3)、布林(20,2)、成交量與量均；參數變更以版本記錄。

使用者層級決策記在[治理 Issue #1](https://github.com/YiCheng0608/stock-lab/issues/1)，必要任務納入 [V1 milestone](https://github.com/YiCheng0608/stock-lab/milestone/1)，整體發布由 V1-G7 與 milestone 承接（已完成，見 [V1 已完成](#v1-已完成)）。任務與 gate 的對應見[工作手冊](WORKFLOW.md#版本範圍與完成判定)。

## 保留的產品取捨

- 盤後 long、最早 T+1、數天至數週；精確期間與做空待決，T+5／T+20 是追蹤窗口，不當退出日。
- 只用免費公開來源，選用與限制見[資料來源](DATA_SOURCES.md)。
- 保留研究、模擬追蹤、持倉風險與來源追溯。
- LLM 只做新聞摘要、關聯、方向判讀與進出點說明文字，結果標推論；經本機 Claude Code 無介面模式用使用者訂閱帳號呼叫，不用 API 計費。勝率顯示條件見[產品規格 §8](PRODUCT_SPEC.md#8-ai-的角色與完成條件)。
- 第一版不含自動下單、盤中即時交易、無來源 AI 報價與未驗證勝率。盤中即時**通知**不在此限：今日名單與我的追蹤的股票觸及頁面上的規則進場、停損或目標價時傳 Telegram，只陳述規則價位、不寫成下單指示，來源為富果行情 API（[#756](https://github.com/YiCheng0608/stock-lab/issues/756)），做法依該單的決定（使用者 2026-11-15 提出，[#1 6888509471](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6888509471)）。本機排程屬 V1 範圍；正式 DB、採購、帳戶、部署仍須個別授權。
