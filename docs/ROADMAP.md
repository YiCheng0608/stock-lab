# 產品路線與能力邊界

本文件管理產品方向、已驗能力及未完成核心；版本任務在 GitHub milestone，排序與交接在 Issues／Projects，見[遷移入口](TASK_COORDINATION.md)。流程依 [AGENTS](../AGENTS.md)。

## 目前產品能力

已有官方資料收集／回補、v1 規則、行動摘要、持倉、技術回測及研究介面；指定市場／標的／日期的有限 API、UI、保存及來源追溯已接受。完整 R0–R3、M1／M2／M3 均未完成；有限子能力不換算完整產品完成率。

已接受七股 explicit 2026-10-06 法人每日淨超、gross 買賣、方向區段、相鄰 5 日窗口，以及自行買賣／避險／合計 5 日對帳。對帳的來源與用途邊界見[來源 §46](SOURCE_REGISTRY.md#46-m1-chips-stock-scope-7-dealer-components-5-1006-20261008-1b1自行買賣避險與合計來源及對帳)，操作與未驗範圍見[個股頁 §51](STOCK_RESEARCH_PAGE.md#51-m1-chips-stock-scope-7-dealer-components-5-1006-20261008-1b1自行買賣避險及合計並列對帳)。既有庫存／指定私人保存的有限磁碟驗收不代表新 Plan 或正式 DB 已完成。

## 接下來的順序：近期產品里程碑

使用流程：**今日關注 → 個股研究 → 條件計畫 → 追蹤回看**。建置優先方向：**M1 個股研究 → M2 今日關注串個股 → M3 條件計畫與追蹤**。全局統籌在 GitHub 依實際可用依賴選單；未採用來源不作全域阻塞。

| 里程碑 | 完成後的使用者操作 | 尚需滿足的核心條件 |
| --- | --- | --- |
| M1 個股研究總覽 | 同一研究截止查看價格、5／20 交易日各法人淨超、趨勢、新聞／官方事件與研究條件。 | 範圍外來源與完整交易日、普通股真實日線及趨勢接線仍缺；20／21 根收盤不證兩策略完整，必要輸入見 V1-G2。逐數值可追來源、時間、分類、規則版本，成立／未成立／資料不足有真實原因；不補零或跨策略拼價。 |
| M2 今日關注串個股 | 可追溯理由、同股去重、進入 M1 並返回原條件。 | 已有指定理由與範圍的有限接線；其他來源／分類品質仍缺。每項理由須有已驗來源、時間、版本，零候選與資料不足可分，不為湊名單補候選。 |
| M3 條件計畫與追蹤 | 保存並讀回版本化計畫，操作觸發、到期、未成交、模擬成交與退出。 | 新 Plan／完整 ActionsPage、生命週期、曝險及整合驗收仍缺；逐子能力滿足官方 tick／費稅、合法時段、時間版本及執行 gate，驗磁碟保存和跨程序讀回。未知風險預算不給張數，觸價不當成交。 |

沿用五個導航與既有量化契約。候選範圍包含普通股收盤／研究趨勢、剩餘法人研究及 M2／M3 接線；是否可開工由 GitHub 依最新證據決定，歷史 NEXT 不是自動順序。

## V1 範圍基線（2026-10-09 已核定邊界）

使用者核定首版完成 **盤後研究 → 保存條件計畫 → 模擬追蹤回看** 的完整流程，先支援 TPEx 普通股 **3105、3293、5274、5347、6488、6510、8069**，後續版本再擴市場及標的。七股是使用者操作範圍，不代表策略必要的基準、有效群組成員或資料來源只需這七股。首版須可手動更新及在多個明選研究截止重複操作，不能只交付固定 2026-10-06 的展示。

版本化 AC 及來源／證據對應由全局統籌存於[治理 Issue](https://github.com/YiCheng0608/stock-lab/issues/1)，必要任務納入 [V1 milestone](https://github.com/YiCheng0608/stock-lab/milestone/1)，整體操作／發布 gate 由 [#26](https://github.com/YiCheng0608/stock-lab/issues/26) 承接。派工前盤點、依賴准入及完成判定依[工作手冊](GITHUB_WORKFLOW.md#版本範圍與完成判定)；範圍核定、盤點無缺口、功能驗收與發布完成分別核實。

| 能力 gate | V1 必要邊界與驗收要點 |
| --- | --- |
| V1-G1 可更新來源與標的身分 | 七股普通股身分、實際行情／OHLCV／成交額、法人、融資、基準與策略所需群組資料須按市場、日期及用途准入；可手動更新、多截止查詢及重開讀回，保留來源、snapshot、版本與品質。缺日、來源失敗與有效零分開；既有固定日的有限保存不證可更新流程完成。 |
| V1-G2 canonical 兩策略及研究判定 | 保留 `breakout_v1`／`pullback_v1` 原公式及版本。breakout 的前 20 日 high／volume、當日值、群組相對 TAIEX、法人 5 日／20 日週轉額與 5 日融資均須完整；pullback 至少 60 根日線及 MA20／MA60，並有同樣群組、法人與融資確認。20／21 根收盤及 MA20 只是子能力。membership 與有效期間必須可驗，不能用 current 分類補造歷史。兩策略分別判定成立／未成立／資料不足，不跨策略拼價；首版不切換 Wilder。 |
| V1-G3 完整條件計畫與時間接線 | 滿足觸發／確認、區間、不追價上限、失效／目標／期限、成本／流動性與最早合法時段等完整計畫計算／執行契約；核官方 tick、費稅、交易日曆、停牌、公司行動及價格 basis。R0-C3／C4 要接實際必要來源、snapshot／revision、availability／decision／execution 時間及保存，caller-declared 純核心通過不能替代。來源／時間缺失就拒絕必要判定，不能靠 unknown 交付；legacy 規則參考價與新計畫版本分開。 |
| V1-G4 Plan 持久化與讀回 | 保存版本化 Plan、原輸入、設定、來源及時間證據，API／UI 讀回同一計畫；核最小隔離磁碟、失敗／更新邊界、跨程序及重開讀回。Plan 保存是獨立能力，不等於完整計畫計算；既有 quote 或 inventory 保存也不等於 Plan 完成。 |
| V1-G5 模擬生命週期與回看 | 同一計畫可驗建立、更新／到期、觸發、未成交、模擬成交、失效／退出與結果版本，最早 T+1；T+5／T+20 是追蹤窗口，不是固定退出日。停牌、公司行動、缺價及同日 stop／target 順序不明按原契約拒絕或 incomparable，觸價不當成交；重播保存策略／執行／成本版本，legacy 結果可重現，不宣稱真實成交或策略有效。 |
| V1-G6 同股完整跨頁流程 | 今日關注／個股研究／Plan／Actions／追蹤回看沿用同一標的、研究截止、來源與版本，可信桌面／窄版實際操作驗同股去重、兩策略摘要、替代條件、返回原條件、真零及資料不足／失敗清值。計畫、模擬與實際庫存分開，風險預算未知不給張數；獨立子頁或 API 通過不取代完整跨頁整驗。 |
| V1-G7 發布驗收 | 已整合 master 的全部 V1 必要 AC 及必要執行單通過，完整端到端流程含磁碟／跨程序受獨立 QA 驗證，required CI、文件與版本證據齊全，阻擋缺陷為 0；全局統籌寫發布驗收收據後才關 milestone。Issue closed 數或全部 Project 卡片結案不代表完成，部署另需授權。 |

完整公式與拒收條件以[canonical 規格](V1_SPEC.md)、[產品計畫與摘要契約](PRODUCT_SPEC.md)、[R0 接線邊界](R0_IMPLEMENTATION.md)及[分類／有效期間](INDUSTRY_CLASSIFICATION.md)為準；本表不降低原契約。既有有限能力與未合併 archive 成果先按能力及版本去重，只有適用的已整合驗收證據才能承接 V1 AC，不整包當完成。

AI、完整題材排行、主力／券商分點與九類法人方向研究列後版；首版仍保留兩策略必要的群組／基準、分類及法人確認，不能因完整排行或九類方向延後而移除必要輸入。既有含後版能力的整合契約保留原 AC 與依賴，以獨立 V1 整合範圍對應必要子能力，不刪原失敗或直接縮小跨版本母單；首版整驗證據可供原契約核適用性後沿用，但不足以提前關閉跨版本母單。後版想法不延長 V1；新增市場、策略、能力或降低 AC 另由使用者決策，pending 不默認納入。

## 保留的產品取捨

- 盤後 long、最早 T+1、數天至數週；精確期間與做空待決，T+5／T+20 是追蹤窗口，不當退出日。
- 免費公開來源，以 FinMind 免費方案為主要新來源、官方 OpenAPI／網站為既有 collector 來源與核對依據（選用原則見[來源契約](SOURCE_REGISTRY.md#來源選用原則finmind-為主)）；來源權限、資料日期、發布／可用時間、修訂及 PIT 分開核。未有新取得路徑不重複相同來源審查。
- 保留研究、模擬追蹤、持倉風險與來源追溯；主力／券商分點接入、統計與歷史仍待做，官方人工入口不等於已接資料集。
- 尚無經驗收的 AI 預測或校準勝率。目標、採用門檻、樣本外／walk-forward／前瞻證據須事先定義；時間與樣本未足就等待。
- 第一版不含自動下單、盤中即時交易、無來源 AI 報價與未驗證勝率。正式 DB、採購、帳戶、部署及排程仍須個別授權。
