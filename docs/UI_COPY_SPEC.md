# UI 文案與資訊層級規格

本文是日常頁的中文、資訊層級、單位、unknown 與 reason code 契約。能力狀態見 [CAPABILITIES](CAPABILITIES.md)，策略合併判定見 [PRODUCT_SPEC](PRODUCT_SPEC.md#action-merge)。

## 1. 共通原則

- 日常頁使用可理解、可追溯的繁體中文；enum、欄位名、資料庫 key、raw ID 與 ISO 時間只可在預設收合的研究／系統層。
- 每個「完整」都須說明資料層與用途。官方事實、規則關聯、推論與 unknown 分開；unknown 不是負面訊號。
- Asia/Taipei 日期顯示 `YYYY/MM/DD`，日期時間顯示 `YYYY/MM/DD HH:mm`（24 小時制，不寫上午／下午）。資料日期 badge、表格日期欄、計算與產生時間都適用，API 的 `YYYY-MM-DD` 不原樣顯示；來源原文裡的日期（如公告內容的民國日期）照原文。
- 「現價」只用於可信即時報價；日資料一律寫「最近收盤（日期）」。缺少可驗證行情時不顯示價格結論。
- 台股紅漲綠跌須同時有正負號或文字，不能只靠顏色。
- 數值表格、缺值與合法 0 的顯示依 [§8.4](#84-數值表格單位與空白)。
- 「待核實」「推論」「無資料」三種字樣依 [§1.1](#11-待核實推論與無資料)，不混用。
- **資料日期、來源與單位每頁講一次**（[#661](https://github.com/YiCheng0608/stock-lab/issues/661)，視覺見 [DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)）：導覽列的「資料 YYYY/MM/DD」是每頁唯一的資料日期（手機也在導覽列上，不收進選單）。卡片、區塊標題、表格列與句子裡的日期與它同一天就不寫；不同天（較早的模擬日、研究截止日、季別日期、非最新的指數列）照舊寫在該處。導覽列日期載入中、失敗或沒有值時，各處日期照舊寫。「非最新」「更新中」、停牌、無資料原因與「待核實」這類狀態不受影響，一律照寫。同一張卡或同一頁的來源相同只寫一處；單位已寫在欄名（「收盤（元）」）就不在每格或每張表重複。
- **「推論」每項一次**：每個 LLM 區塊在區塊標題列標一次「AI 推論」，區塊內不再逐項加；規則算出的事實（分數、來源行、價位）不寫推論字樣。推論的單項（新聞情緒分項、`inference=true` 的理由）只標一次：理由文字已寫「（推論）」就不另加 badge。

### 1.1 待核實、推論與無資料

畫面上每一個「待核實」都要有可說明的原因（[#465](https://github.com/YiCheng0608/stock-lab/issues/465)）。三種字樣依值的來歷選一種：

| 字樣 | 用在 | 例 |
| --- | --- | --- |
| 待核實 | 有值，但還沒通過、或沒有通過核對：時間衝突或沒有時區、前一列不是同來源的相鄰交易日、單位不明、本地手動記錄、前端不認得的代碼 | 「來源時間待核實」「漲跌待核實」「單位待核實」「狀態待核實」 |
| 推論 | LLM 產出。附模型與提示版本；能用規則核對的，另寫核對結果與規則版本，通過的寫「規則核實」 | 新聞 AI 候選的「規則核實：原文提及」／「推論」（[§4](#4-新聞卡文案與折疊)） |
| 無資料 | 沒有值：來源沒給寫「未提供」，系統沒存寫「未記錄」，尚未產生寫「尚無…」；原因已知時直接寫原因；API 失敗寫「暫時無法載入」 | 「資料日期未提供」「決策時間：未記錄」「前一交易日無收盤」「資料日期暫時無法載入」 |

- 不用「待核實」代替「沒有值」或「載入失敗」；LLM 產出不寫「待核實」，寫「推論」。
- 規則核對只改顯示；規則核實的 AI 候選不寫進規則關聯（`symbols`），不改分數與篩選。

| canonical／canonical config snapshot | 固定研究規則／規則版本與稽核設定；只在研究詳情 |
| prior_20_highs／bars_20d／bars_60d／institutional_flow_5d | 前 20 個交易日高點／近 20 日行情／近 60 日行情／近 5 日法人籌碼 |
| company／taiwan／domestic／international | 個股公告／台灣官方事件／國內／國際；尚未接入的來源不顯示空卡 |

## 3. 三種資料完整度

| 資料層 | 完整 | 部分／缺失 | 只代表 |
| --- | --- | --- | --- |
| 來源擷取 | 來源擷取完整 | 來源擷取部分完成／失敗 | 來源與 raw 稽核；不代表欄位或歷史窗口完整。 |
| 當日行情 | 當日行情完整 | 當日行情部分缺漏／尚無可驗證行情 | 指定標的、市場與日期的 OHLCV。 |
| 策略判斷 | `<策略>條件資料完整` | `<策略>條件資料不足` | 該策略所需行情、TAIEX、membership、籌碼等輸入。 |

同頁可同時顯示「來源擷取完整 · 當日行情完整 · 回踩條件資料不足」，並列精確缺項。全市場 run 成功或資料列增加不能升格個別標的；全域 partial 也不能自動降級一條已完整策略。

同卡有兩條策略時使用「主研究條件資料完整 · 另一研究條件資料不足：<缺項>」。只有所有呈現條件都完整時才可省略範圍。完整 observation 沒有 entry／target／RR 仍是完整，不使用資料不足 badge。

族群熱度：完整與四分項條件以 [hot_group_v1](spec/hot_group.md) 為準。UI 對合格 partial 顯示「技術與籌碼觀察（事件資料待補）」，不得稱完整熱門或產生完整熱門候選。

## 4. 新聞卡文案與折疊

- **分頁**：`/news` 以「國內」（`category=domestic`）、「國際」（`category=international`）、「官方公告」（`source_kind=official_disclosure`）三個分頁瀏覽，可再以關鍵字與股票代號篩選；個股頁「新聞與公告」顯示該股最近 50 則（交易所＋代號完全相符，官方公告為純代號相符）。三個分頁共用一個搜尋列（關鍵字、股票代號、搜尋與清除按鈕），版面見 [DESIGN_SYSTEM §5](DESIGN_SYSTEM.md#5-元件)「搜尋列」。搜尋列下方兩個各自開關的篩選膠囊「只看有已核實標的」「只看自選相關」（[#523](https://github.com/YiCheng0608/stock-lab/issues/523)），由 API 篩選（`verified_only`／`watchlist_only`，[NEWS_SPEC §6](NEWS_SPEC.md#6-ui-與-api-契約)），分頁與「共 N 則」跟著篩選結果，網址記 `verified=1`／`watchlist=1`。篩選後沒有新聞時：開了「只看自選相關」寫「目前沒有與自選股相關的新聞。自選清單是空的時不會有結果；個股頁勾選「我的自選」可查看目前的自選股。」，只開「只看有已核實標的」寫「目前沒有符合條件、且有已核實標的的新聞。」，其餘照分頁的空資料文案。
- **標題與摘要前綴**（[#523](https://github.com/YiCheng0608/stock-lab/issues/523)）：`/news`、今日頁、個股頁與 `/news/:id` 顯示的標題，以及清單與卡片的摘要預覽，去掉開頭的符號與署名（規則見 [NEWS_SPEC §6](NEWS_SPEC.md#6-ui-與-api-契約)）；欄目標記（《營建股》【盤前】）照留。`/news/:id` 技術資訊的「原始標題」列出來源原文（只有清理後不同時才列），來源事實欄的摘要也是原文。
- **`/news` 新聞清單**（#523，版面見 [DESIGN_SYSTEM §5](DESIGN_SYSTEM.md#5-元件)「新聞清單」）：每則兩行：標題（一行，放不下以省略號收尾，全文在連結的 `title`）→ 來源 · 來源時間 · 影響／AI（AI 方向後接「AI 推論」）與規則核實的相關標的 tag（「代號 名稱」，沒有就不放）；640px 以下影響／AI 接在標題右側，第二行是來源與時間。右側「展開」「收合」切換展開區，依序為「分類 · 來源類型」→ 摘要預覽（120 個全形字元）→ 已核實關聯（同下一條卡片的寫法，沒有就整行不顯示）→ AI 候選行 → 來源連結與「詳情 →」。清單不寫「未有已核實的標的或族群」。
- **卡片正面**（個股頁「新聞與公告」）：固定順序為分類與來源 → 兩行內標題 → 120 個全形字元或三行內摘要 → 來源時間 → 影響／關聯 → 相關標的 → AI 候選（預設收合，見下一條）→ 來源連結。標題除了上一條的前綴清理，只正規化連續空白與換行，列表截在兩行，詳情保留完整標題。`/news` 不展開全文；`/news/:id` 用「展開公告內容／收合公告內容」，只顯示可用的來源 description，不顯示 raw JSON 或內部 ID。相關標的只列已核實關聯；媒體新聞的關聯來自規則比對，標的前先寫「規則核實 · v<版本>」（版本取自 `impact.method`，[NEWS_SPEC §2](NEWS_SPEC.md#規則關聯)；未重算的舊新聞寫舊版本號），官方公告不加；沒有已核實關聯時寫「未有已核實的標的或族群」。`/news/:id` 技術資訊的「關聯方法」寫「規則比對（名稱／簡稱／代號） · 規則版本 v<版本>」。
- **AI 候選行**（[#452](https://github.com/YiCheng0608/stock-lab/issues/452)）：`/news` 清單的展開區與個股頁「新聞與公告」的卡片，在規則核實的相關標的那一行之後另起一行，用預設收合的 `<details>`，收合時寫「AI 候選 · N 檔（規則核實 M、推論 K）」，括號內只列非 0 的部分（文字已標推論，不另接「AI 推論」badge：卡片的「AI 推論」badge 只接在 AI 方向後，一則一個）；展開後每檔一項「代號 名稱 · 規則核實：原文提及 · 模型把握高／中／低」或「代號 名稱 · 推論 · 模型把握…」，依 API 的 `source_check`（`mentioned` 為規則核實，其餘與沒有這個欄位的都是推論，[NEWS_SPEC §5](NEWS_SPEC.md#5-ai-摘要與推論)），最後一行 muted 小字「模型 <model> · 提示版本 <prompt_version> · 核對規則 <candidate_check_version>。規則核實：名稱或代號出現在標題或摘要；推論：原文沒有寫出，由模型推得。候選不計入已核實關聯。」（沒有值寫「未記錄」）。#465 起不寫「待核實」（[§1.1](#11-待核實推論與無資料)）。名稱與連結同 `/news/:id` 的候選標的（見下方「候選標的名稱」）；卡片不列理由，理由在 `/news/:id`。來源是 `ai.symbol_candidates`（只用 `usableAi` 認可的 `done` 結果）；代號與規則核實的標的（`instruments`，或 `symbols` 的 `交易所:代號`／純代號）相同的那檔不列，同一代號重複時只列一次；只比代號、不比交易所，因為上市櫃代號不會重複，模型寫錯交易所的同一檔不在兩行各出現一次；剩下沒有候選時整行不顯示，不寫「無」。今日頁精簡列不顯示這一行。
- **候選標的名稱**（[#512](https://github.com/YiCheng0608/stock-lab/issues/512)）：卡片 AI 候選行與 `/news/:id` 的候選標的，一律寫「代號 名稱」，依 API 的 `listing`（[NEWS_SPEC §5](NEWS_SPEC.md#5-ai-摘要與推論)）：上市櫃（`listed`）寫「2330 台積電」並連到個股頁；興櫃（`emerging`）寫「7808 訊聯智藥（興櫃）」，已下市（`delisted`）寫「2888 新光金（已下市）」，兩者都不連結，因為系統沒有它們的現行行情。不寫「代號未對應到已知標的」：主檔與興櫃名冊都查不到的代號，API 已移到 `hidden_symbol_candidates`，畫面不列，也不算進「AI 候選 · N 檔」；沒有名稱的候選（舊版 API）同樣不列。沒有 `listing` 的候選（舊版 API）有名稱就照舊連結。`/news/:id` 的候選全部被移走時寫「模型提出的候選代號都查無對應標的，不列出。」，模型沒有提出任何候選時寫「模型未提出候選標的。」。
- **今日名單頁不列新聞**（#625）：首頁原本的「重點新聞」卡已移除；和候選有關的新聞在該候選展開後的理由，全部新聞在 `/news`。
- **摘要**：沒有摘要時寫「來源未提供摘要」。只有存在合法可用原文時，才可另顯示附引用與方法的「AI 摘要」；不得由標題或模型記憶補造。
- **影響與 AI 推論**：方向寫「可能正向」「可能負向」「正負互見」「影響尚未判定」，前置色點（正向 `--color-up`、負向 `--color-down`、互見 `--color-flat`）；unknown 與 `unsupported` 不加色點。卡片上的方向若來自 AI，後接「AI 推論」badge；新聞頁、個股頁與今日頁的卡片讀同一份 `ai`，有 AI 判讀時都顯示 AI 方向，不退回規則方向。`/news/:id` 來源事實欄的「影響」列只讀來源的 `impact_direction`（新聞收集一律存 unknown，[NEWS_SPEC §3](NEWS_SPEC.md#3-去重新資訊與事件影響)），unknown 寫「來源未標示影響」、不加色點，不寫「影響尚未判定」，以免讀成與右欄 AI 方向衝突。`/news/:id` 的「AI 摘要與判讀」區與來源事實分開，列 AI 摘要、方向與範圍、理由、候選標的與候選題材（候選標的每檔寫「規則核實：原文提及」或「推論」，再接「模型把握高／中／低」與理由；候選題材的標題旁標「已通過題材核對」（success badge），因為存下來的題材候選都通過了[題材核對](NEWS_SPEC.md#5-ai-摘要與推論)；兩者都不寫「待核實」；名稱與連結見下方「候選標的名稱」；交易所以 API 的 `exchange` 為準，模型寫錯時 API 已依主檔更正（[NEWS_SPEC §5](NEWS_SPEC.md#5-ai-摘要與推論)），名稱與連結用更正後的交易所，不另標示），以及模型、提示版本、產生時間（`generated_at` 換算台北時間 YYYY/MM/DD HH:mm，沒有時區寫「待核實」）與候選標的的核對規則（同卡片的說明句，後接「候選標的與題材都不作為交易理由。」）；沒有結果寫「此則尚未產生 AI 摘要與判讀」。
- **日期**：`published_at`／`event_at`／`event_date` 依序寫「發布於 日期時間」／「事件於 日期時間」／「事件日 日期」；三者皆無寫「來源時間未提供」，有值但 `product_time` 角色為 unknown 或 `time_consistency=conflict` 寫「來源時間待核實」，collected_at 只在詳情稽核層顯示「系統收錄時間」；`time_consistency=conflict` 寫「資料集事件日期與公告內容提及日期不一致，時間待人工核實」。排序依 [NEWS_SPEC §4](NEWS_SPEC.md#4-時間與排序)，依 collected_at 排序的項目不可顯示成發布時間。
- **來源連結**：`source_url_kind=item` 寫「查看原文／原始公告」；`feed` 寫「查看官方公告資料集」並提示「資料集連結未必定位到本則公告」；`none` 寫「來源連結未提供」，不畫無效按鈕。raw payload、hash 與 event ID 只在稽核層。
- **族群關聯**：只顯示來源直接指向且已驗證的族群，或已核實的 Event—Instrument—Theme 關聯；由現有 membership 自動推得、英文名稱／代碼、名稱狀態未核實的關聯只留系統層。關聯可信度文案見 §2。

## 5. 行動中心的分級與預設篩選

頁面是「我的追蹤」（`/watch`，#493 前叫「行動」「行動中心」，舊網址 `/actions` 轉到這裡）：眉標「追蹤與提醒」、標題「我的追蹤」；標題同一行右側一個預設收合的「說明」（#649），展開後兩段：第一段寫給第一次看的人「把有興趣的候選加入追蹤，系統每天收盤後依日線模擬它的進場與出場（不是實際成交）；這裡也會提醒你庫存的風險，和快要成立的股票。」，第二段是隱藏規則「自選標的一律顯示；隱藏不刪資料，切換上方篩選即可看到。」。以下是頁面下半部的行動列表。

列表依 `action_tier_v1` 分六級，級內依下表排序（`backend/app/decision.py` 的 `ACTION_TIERS`，由測試釘住）。分級只決定列表順序與預設篩選，每列的狀態、價位與理由仍是該檔的行動摘要（[PRODUCT_SPEC §6](PRODUCT_SPEC.md#action-merge)）。分級的日資料部分由 daily 預算（`action_tier_snapshots`，[action tier 預算與新聞投影](ops/SCHEDULING.md#action-tier-預算與新聞投影)）；持股、自選與名稱每次即時讀。沒有當日預算或依據已變時即時計算，結果相同；API 以 `action_tier_source`（`/api/dashboard`）、`summary.tier_source`（`/api/actions`）標示來源。

| 級 | 區塊標題 | 條件 | 級內排序 |
| --- | --- | --- | --- |
| 0 | 持倉風險 | 有持倉，或持倉數量待核實 | 行動摘要為減碼／退場 → 需人工判讀 → 資料不足 → 持倉觀察，再依代號 |
| 1 | 今日候選 | 資料日的每日候選（[§10](#10-每日候選)） | 名次 |
| 2 | 其他成立條件 | 資料日有資料完整的成立訊號、近 60 個交易日都有日線，但不在今日候選（被名次截斷的股票、ETF） | 所屬族群當日最佳名次，再依代號；沒有族群名次的排最後 |
| 3 | 接近成立 | 第 4 級的條件，再加上至少一條策略「接近」（下方） | 未達成條件數，再依價格差距（由小到大），再依代號 |
| 4 | 其他觀察 | 資料日有資料完整的觀察訊號、近 60 個交易日都有日線 | 差項最少的策略的未達成條件數（條件明細尚未產生的排最後），再依代號；同短名的條件各算一條，所以與說明欄「差 N 項」的 N（短名數，§6）可能不同 |
| 5 | 資料不足 | 兩條策略都沒有資料完整的結果，或近 60 個已核實交易日有缺日線（含上市未滿 60 個交易日）；行動摘要對這些標的判 `data_insufficient`，標籤寫「資料不足，無法判斷」；原因句（§6.1）只有 `etf_not_general_action_eligible` 時寫「不適用一般研究條件」（[#524](https://github.com/YiCheng0608/stock-lab/issues/524)，只改標籤，分級與計數不變） | 自選在前，再依代號 |

- **接近成立**（第 3 級，`decision.py` 的 `ACTION_NEAR_PRICE_GAP`，屬 `action_tier_v1`）：一條策略的條件價位列（`strategy_levels`，[strategy_levels_v1](spec/strategy_levels.md)）同時符合：
  1. `availability=levels`，且 `reachable_next_session` 不是 false。`trend_unreachable`、ETF 排除類別（`not_applicable`）、資料不足都不算。
  2. 未達成的條件只有價格（突破的收盤突破前 20 日高點、回踩的收盤在支撐區）或量能；族群、法人、融資（回踩另含趨勢）與其他條件都已達成。
  3. 價格差距：突破 ≤ 3%、回踩 ≤ 2%（含等於）。差距是條件明細裡價格條件的下一交易日距離（突破為觸發價 ÷ 最近收盤 − 1；回踩為最近收盤到支撐區最近一端，區內為 0），取絕對值；價格條件在資料日已達成時記 0。

  兩條策略都接近時取未達成條件數較少的一條，相同再取價格差距較小的，再相同依策略宣告順序（突破在前）。沒有條件價位列的觀察（較早的資料日，或條件價位步驟失敗）不判接近，歸第 4 級。
- **不升級**：自選不改變級別；近 7 日官方事件不提升級別。
- **篩選膠囊**：「重點」（第 0～3 級）、「含其他觀察」（再加第 4 級）、「全部」（再加第 5 級），預設「重點」；只有選中的膠囊後接檔數 N（「重點 6」，#649），其他兩個只寫名稱。旁邊一個勾選框「含 ETF」（不寫檔數），預設不勾。持倉與自選在任何篩選下都列出，持倉的 ETF 不受「含 ETF」影響。N 是目前「含 ETF」設定下該篩選的檔數，取自 API 的 `summary`，前端不自己數。
- **隱藏數**：同一列接在「含 ETF」之後「預設隱藏：ETF X 檔、其他觀察 Y 檔、資料不足 Z 檔」（#649 前是篩選列下方一整句；為何隱藏移到頁首「說明」）。數字取自 `summary.hidden`；一檔只算一次，ETF 先算在 ETF。為 0 的項目不寫，三項都是 0 時不出現。不是預設篩選（「重點」且不含 ETF）時開頭改為「目前隱藏：」。
- **搜尋**（代號／名稱）不受篩選限制：符合的標的不論級別、是否 ETF 都列出，各在所屬級別的區塊；搜尋時隱藏數改為「搜尋不受篩選限制，結果依級別列出。」
- **區塊**：每級一個區塊，只列目前篩選下有標的的級別。開頁時載入列表第一頁 20 檔；有標的但第一頁沒輪到的級別，首屏另外載入它的前 5 檔，不留空區塊。標題下一行「顯示 k／N 檔」（k 已載入、N 是該級在目前篩選下的檔數）；還有未載入的列時，區塊下方一個按鈕「顯示更多（還有 M 檔）」，一次載入 20 檔。所有區塊都沒有標的時寫「目前沒有符合篩選的標的。」
- **每列**：代號名稱、市場 · 類型、狀態（行動摘要的標籤，持倉數量待核實另標「庫存數量待核實」）、最近收盤與漲跌（[§8.1](#81-行動摘要壓縮卡)）、「策略總表 →」（連到個股頁進出場分頁）。沒有「資料日」欄（#661）：列的資料日與導覽列的頁面日期不同時，在代號名稱下另起一行「資料 YYYY/MM/DD」，同日不寫。第 0～2 級另有進場區、停損、目標一（成立條件的價位，表頭帶「（元）」；行動列表只列目標一；持倉列的停損是使用者 stop 或策略失效價），第 1 級另有名次與總分，第 2 級狀態下一行寫為何不在今日候選（§6）。第 3 級沒有價位欄，改為「差哪個條件」一欄（§6 接近成立卡），最後一欄寫「價位見策略總表 →」。第 4、5 級另有一欄說明（第 4 級為行動摘要的主要原因，即 §6 的「差 N 項」句，沒有條件價位列時下一行加「條件明細尚未產生」；第 5 級有 `gap_reasons` 時為主要原因 `primary_reason`（§6.1 的第一句），舊回應沒有時為缺資料句 `data_gap`）。沒有合法價位時該格留空，表外註明「空白表示沒有成立的價位」，不用 0 或破折號；這句與「單位：價格為各標的報價幣別的元」合成一行，只寫在頁面上第一張畫出來的價位表上方（某一級沒有列、表不畫時順延到下一張，#661）。當日行情不足時收盤格寫「價格資料尚未完整，暫不顯示最近收盤」。手機卡片（640px 以下，#649）只露出代號名稱與狀態、收盤與漲跌、價位三格（第 3 級為「差：…」各行、第 4、5 級為說明）、資料日（只在與頁面日期不同時，寫「資料 YYYY/MM/DD」）與連結；「市場 · 類型」（第 1 級前接 `#名次`）、第 2 級為何不在今日候選、第 3 級「…已達成」收進卡底的「更多」，「更多」在資料日與連結之間。
- **我的庫存**：沒有庫存時收成一行：「我的庫存」「尚未建立庫存。」「有持倉風險時列在最上方。」與「新增庫存」展開鈕；有庫存時顯示完整區塊（每筆持倉、核對與新增表單）。

**`no_condition` 的主要原因**（`primary_reason`，行動列表第 4 級的說明欄與個股頁研究動作共用）：取資料日判定完整（`rejected`）的策略中未達成的短名最少的一條（相同時依策略宣告順序，突破在前），寫「{策略}差 {N} 項：{短名，以「、」連接}」，例「突破條件差 3 項：價格、量能、法人」。短名見 [§10.1 條件表](#101-個股策略總表)，同短名只寫一次，N 是寫出的短名數，比較哪條策略差得少也用這個數（回踩的兩個趨勢條件都未達成是 1 項「趨勢」）。第 4 級列表的排序依未達成條件數（§5），兩者基準不同。這一行只讀訊號的判定（`signals.rule_evidence_json`），不讀條件價位，所以有沒有 `strategy_levels` 列結果都相同；沒有完整判定的策略時沿用原本的理由。

「差：」句的數字：價格差距為 %、兩位小數、不帶正負號（方向寫在句中）；量比為兩位小數加「倍」。

### 6.1 資料不足的原因句

`data_insufficient` 不只列缺項，還要說為什麼缺（[#511](https://github.com/YiCheng0608/stock-lab/issues/511)）。行動摘要的 `gap_reasons` 是 `{code, label}` 的清單，每個原因一句；`primary_reason` 取第一句（行動列表的說明欄與個股頁共用），個股頁「進出場」分頁的缺資料列寫「目前不能判斷的原因：{各句以「；」連接}。」，精確缺項（`blocking_reasons` 經欄位對照表）收在「查看缺少的欄位」。舊回應沒有 `gap_reasons` 時寫「研究資料不足：{缺項}」。原因只解釋，哪些標的是 `data_insufficient` 與策略規則都不變（60 日基準照舊只數有 bar 的交易日）。各原因的日期在個股 API `coverage` 的 `no_trade_dates_to_20`／`no_trade_dates_to_60`、`suspended_dates_to_60`、`quote_not_listed_dates_to_60`、`invalid_bar_dates_to_60`、`halted_dates_to_60`（停止買賣的區間在 `halt_periods_to_60`），個股頁「資料說明」的缺口明細照列；那裡的原因標籤用個股頁自己的寫法，官方無成交日寫「官方行情表列出但當日無成交（依規則仍算缺一日）」，減資停止買賣寫「減資換發新股停止買賣（依規則仍算缺一日）」，不沿用市場覆蓋頁的「不算缺資料」。

| code | 句子（{} 為數字） | 依據 |
| --- | --- | --- |

個股頁「籌碼」表的單位說明同樣寫出空白的原因：三大法人欄空白是官方三大法人表當天未列此股（只列當天有法人買賣的股票），融資欄空白是當天不是融資標的或官方融資餘額表未列此股，其他空白才是數值無效或來源單位待核實。

## 7. 詞彙原則

詞條內容（term_id、名稱、別名、分類、白話說明、用途、解讀、限制、相關詞、版本）以 `backend/app/glossary.py`（`GET /api/glossary`）為準，`frontend/src/glossary.ts` 是 API 不可用時的本地副本；本節只寫原則。

- **中文對照**：日常頁用中文術語，英文、enum 與欄位名依 §2 對照，只在研究／系統層露出；別名用於搜尋。詞彙出現在 UI 不代表對應資料或模型已上線。
- **白話與限制並列**：每個詞同時寫用途與誤讀界線，例如突破、目標價、T+1 都不等於成交或必達；資料不足時明說無法用該指標下結論。
- **事實／推論分欄**：來源事實、規則判定與推論（AI 摘要、影響推論）分開命名；推論詞須標方法與引用，unknown 不是負面訊號。
- **口徑**：「外資」「三大法人」依[資料來源的法人口徑](DATA_SOURCES.md#法人口徑)；「熱門族群」只用於五分項完整的群組（[hot_group_v1](spec/hot_group.md)）。
- **不用的詞**：日資料不稱「現價」，固定 confidence 或模型自評不稱「勝率」或「校準機率」；不以「主力」「隔日沖」或分點名稱推定投資人身分；不寫「保證」「必漲」等報酬承諾。
- **呈現**：Modal 依白話定義、用途、解讀與限制排列，不以 term_id 或欄位名作標題。詞彙按鈕須支援滑鼠、觸控、Enter／Space，Esc 關閉後焦點回觸發點；定義不得只靠 hover 或顏色。滑鼠移到詞彙按鈕上時以原生提示（`title`）顯示白話定義，點開才是完整 Modal；所以就地說明詞條的白話定義寫成一句口語，不放公式或門檻，例如 RR「可能賺的空間是可能賠的幾倍」、總分「用來排候選順序的分數，不代表勝率」。詞彙按鈕不放在整張可點的連結卡片裡（如族群榜手機卡、今日頁熱門族群卡），那裡只顯示文字，說明在同一詞出現的表格、詳情頁或用語表。
- **就地說明**：候選卡、族群頁與個股「進出場」分頁的下列用詞以詞彙按鈕開啟詞條；`percentile` 日常頁不露出英文。

| 用詞（出現處） | 詞條 `term_id` |
| --- | --- |
| 總分（候選卡）、權重涵蓋（評分細節） | `candidate_score` |
| 進場區（候選卡） | `entry_zone` |

## 8. 壓縮卡、詳情與單位文案

### 8.1 行動摘要壓縮卡

今日名單頁不放行動摘要卡（#493 起「關注標的」移出首頁，行動摘要在我的追蹤）；以下是行動摘要的共通欄位順序。

順序為：代號／名稱 → 最近收盤與可信漲跌幅 → 一個行動結論 → 一個主要原因 → 一組關鍵價位（如合法）→ 資料日期與詳情入口。缺相鄰、同 basis 的可信前收盤時寫「漲跌幅待核實」；行動摘要的 `price_change_status` 是 `no_previous_close` 或 `first_trading_day` 時改寫「前一交易日無收盤」「掛牌首日」（[§8.2](#82-個股詳情的第一屏)，行動列表的漲跌同此）；no condition、資料不足或人工判讀不顯示關鍵價位。行動摘要附 `market_read` 時，只有 `status=known`、`invalid_fields` 為空且最近收盤為正有限數值才顯示價格；否則價格與漲跌顯示「待核實」「漲跌待核實」，標題改為「資料不足，無法判斷」。

### 8.2 個股詳情的第一屏

第一屏是頁首與 K 線卡（#648 圖優先：頁首 → K 線卡 → 摘要卡 → 分頁籤，K 線卡在每個分頁都在，頁面上只畫一張；#656 起 K 線卡只有主圖與成交量，指標面板與圖表資料表在「走勢」分頁）。頁首依序為代號、名稱、市場（上市／上櫃）與類型、最近收盤（報價幣別元）、漲跌與漲跌幅（漲紅跌綠、正數帶 `+`）、資料日期 badge 與來源。頁面的日子（指定研究截止日期時是該日，否則是最新的加權指數交易日）在減資停止買賣區間內時（個股 API `trading_halt`，[#582](https://github.com/YiCheng0608/stock-lab/issues/582)），來源之後接 warning badge「停止買賣中（{原因}，預計 YYYY/MM/DD 恢復）」，原因目前只有「減資換發新股」；說明最近收盤為什麼停在最後交易日。恢復買賣日起不再顯示；該股在頁面的日子有日線時也不顯示（以 bar 為準）。頁尾固定附註：「此為研究工具與資料摘要，不構成投資建議、報酬保證或自動下單指令。」

**摘要卡**（#519，K 線卡下方、分頁籤上方，每個分頁都在；視覺見 [DESIGN_SYSTEM §5 個股摘要卡](DESIGN_SYSTEM.md#5-元件)）：回答「現在能不能買、差哪個條件、價位在哪」，只重排既有的判定與文字，不另算、不放 AI 內容。三欄的標籤依序為「目前判斷」「最接近成立」「規則價位」，第一欄標籤右側是資料日期 badge（`strategy_board.as_of`，沒有時用 `decision_summary.data_cutoff`）；卡的右下角「完整條件 →」切到「進出場」分頁。

- **目前判斷**：依序取第一個成立的判斷，badge 寫判斷、後接原因句：

  | 條件 | badge | 原因句 |
  | --- | --- | --- |
  | 行動摘要 `reduce_exit` | 持倉風險 | 行動摘要的指示句（`display_instruction`，沒有時用標籤） |
  | `strategy_board.candidate` 非 null（資料日的每日候選） | 條件成立 | 「每日候選第 {rank} 名 · 總分 {0–100} · {突破條件／回踩條件}」（同 §10 個股頁候選列）。badge 不寫「可買」（「今日名單」不是推薦，#581），與策略總表的「成立」、下一列非候選的「條件成立」同字，候選與否由原因句分辨 |
  | 行動摘要 `hold_observe` | 持倉觀察 | 行動摘要的指示句（`display_instruction`，沒有時用標籤） |
  | 行動摘要 `manual_review` | 需人工判讀 | 主要原因（`primary_reason`），沒有時用指示句 |
  | 策略總表每一列都是 `not_applicable` | 不適用 | 該列的 `missing_labels`（同策略總表「差哪個條件」） |
  | 行動摘要為資料不足（`data_insufficient` 等） | 資料不足 | §6.1 的原因句，各句以「；」連接；舊回應沒有 `gap_reasons` 時用 `data_gap` 的對照句 |
  | 策略總表有 `conditional` 列（不在每日候選） | 條件成立 | `liquidity.candidate_exclusion` 有值時是策略總表成立列同一句的流動性門檻句；ETF 寫「ETF 不列入候選評分」；其他寫「不在這個資料日的每日候選名單」 |
  | 其他（觀察、等待條件、暫無研究條件） | 觀察 | 主要原因（例「回踩條件差 1 項：支撐區」，§6 的「差 N 項」句），沒有時用指示句 |

  沒有行動摘要也沒有策略總表時 badge 寫「無資料」，原因句「尚無行動摘要。」。
- **最接近成立**：取一條策略：每日候選的那一條策略 → 第一個 `conditional` 列 → 未達成條件最少的 `observation` 列（條件明細未產生的排最後，相同時依宣告順序，突破在前）→ 第一列。寫策略名（「突破條件」「回踩條件」，詞彙按鈕）與狀態 badge，下一行「差：{差哪個條件}」（§10.1；成立寫「差：全部達成」；資料不足與不適用的列直接寫 §10.1 的句子，不加「差：」，例「無法判斷：近 5 個交易日有 1 天官方三大法人表未列此股（…）」）。策略總表沒有任何列時寫「此股尚無策略判定資料。」，不顯示規則價位欄。
- **規則價位**：同一條策略在策略總表的價位（§10.1）：成立價位、觀察價位（含「條件未成立・觀察價位」標籤與其下各句），其他狀態寫「無價位」。

**分頁內的說明文字**：各分頁卡片的單位、口徑與規則解釋收進卡內「說明」`<details>`（例：籌碼表上方的單位說明、財務表的口徑說明、策略總表的固定說明句、研究截止日期的說明句）；資料日期、來源與 badge 不收。

個股詳情以「走勢／籌碼／財務／新聞與公告／進出場／資料來源」分頁，預設為「走勢」。頁首最近收盤取 bars API 日線最後一根有完整 K 線的列；直接前一列也是同來源的交易日才算漲跌，否則顯示「漲跌待核實」；bars API 的 `latest_change`（只有日線，同一天的 `adjacent_change`）是 `no_previous_close` 或 `first_trading_day` 時，不拿更早的列算漲跌，寫「前一交易日無收盤」「掛牌首日」（下段）；沒有可信收盤時顯示「待核實」，不改稱零或負面訊號。研究截止日期不影響頁首收盤與 K 線。

每日候選與族群成員的 `market.change_status`（`app.market_change.adjacent_change`）、個股頁首讀的 bars API `latest_change.change_status`、行動摘要的 `price_change_status`（行動頁與今日頁行動卡）是同一套狀態，同一檔同一天在各頁寫同樣的字（[#475](https://github.com/YiCheng0608/stock-lab/issues/475)）：`known` 才顯示漲跌。前一個已驗證交易日這檔沒有成交收盤時，依 `app.market_change.no_close_status` 分兩種，都不拿更早的收盤補算（交易所的參考價不一定是最後一筆成交價）：主檔的上市日（`listing_date`）晚於前一個已驗證交易日是 `first_trading_day`，寫「掛牌首日」；否則該來源那天有其他標的的日線、只有這檔沒有（無成交或停牌，來源沒給收盤，collector 不存沒有收盤的列；畫面不指明是哪一種）是 `no_previous_close`，寫「前一交易日無收盤」（[#465](https://github.com/YiCheng0608/stock-lab/issues/465)）。整個來源那天都沒有日線（資料未抓）、前一列是另一個來源，仍是 `unverified`，寫「漲跌待核實」。上市日缺值的新上市股照 `no_previous_close` 寫；同一檔從上櫃轉上市時，主檔的新列以轉市日為上市日，轉市第一天也寫「掛牌首日」。

行動詳情與進出場分頁的時間摘要「資料日期：… · 決策時間：… · 規則最早執行日：…」（資料日期與頁面日期同一天時不寫，從「決策時間：」起；研究動作的「資料日：… · 價位語意：…」同理，#661）：角色沒有值寫「未記錄」（`decision_at` 目前一律 `legacy_decision_at_not_persisted`，系統沒有保存決策時間），有值但無法確認（沒有時區、狀態 unknown）才寫「待核實」；下一行固定「時間以台灣時間顯示；系統沒有記錄的時間寫「未記錄」，有值但尚未確認的寫「待核實」。」

**研究截止日期**（頁首的設定列）：開關與表單上寫目前實際使用的資料日。沒有指定日期時寫「研究截止日期：最新資料（YYYY/MM/DD）」，日期是 API 實際採用的截止日（`news_cutoff.as_of`，沒有時用 `decision_summary.data_cutoff`；兩者都沒有就只寫「最新資料」）；指定日期時寫「研究截止日期：YYYY/MM/DD」。表單最後一個收合「說明」（#519），展開後固定一句「只用這一天收盤（含）以前的資料判斷研究條件、研究動作與候選，用來回看當時會怎麼判斷；空白或按「最新資料」時用 YYYY/MM/DD（該股最近一個有資料的交易日）。頁首收盤、K 線與新聞時間線不受影響。」日期與上一句相同；已指定截止日或不知道最新資料日時，「用 YYYY/MM/DD（…）」改寫「用最新資料日」。日期欄預設填目前使用的日期：指定日期時是該日，沒有指定時是上述最新資料日（不留空白），並以最新資料日為可選的最大值；日期沒改就按「套用截止」時維持最新資料，網址不帶 `as_of`，改了日期才帶（[#492](https://github.com/YiCheng0608/stock-lab/issues/492)）。「進出場」分頁依序為策略總表（[§10.1](#101-個股策略總表)）、研究動作、所屬族群（#519）。研究動作區把原本的缺資料列、研究動作、風險與時間、追蹤計畫合成一張卡：標題「研究動作」與策略判斷資料 badge，下一行是動作名稱（`display_action`，資料不足時「資料不足，無法判斷」，只有 ETF 類別不適用時「不適用一般研究條件」（§5））、指示句與主要原因；資料不足時其下是缺資料框，內容是 §6.1 的缺資料列，行動摘要的缺資料句（`data_gap`）接在原因句下一行；同一張卡裡一句只寫一次：指示句已含缺資料句時框內不再寫，主要原因就是其中一條原因句時原因列不再寫；收合的「查看風險提醒、時間與價位」內容不變，但行動摘要的價位（停損與目標一）與策略總表某個成立列相同時（#648），收合標題改「查看風險提醒與時間」，價位格換成一句「價位見上方策略總表。」（同一組價位在分頁內只完整寫一次）；其下是追蹤計畫：每個成立策略一行「{策略}成立」「條件資料日 YYYY/MM/DD」與「加入追蹤」（已追蹤時「已在追蹤」連結），沒有成立策略時一行既有句「目前沒有成立的研究條件，無法建立追蹤計畫」（[§12](#12-追蹤計畫)），最後一句模擬說明不變。族群卡標題「所屬族群」，一行列出族群名（以「、」連接），各族群的有效期間收在「有效期間」裡；讀 API `groups`：`verified=true` 顯示 `display_name`（ETF 與新上市列沿用前端類別譯名），`verified=false` 顯示「族群關聯待核實」，驗證規則見 [INDUSTRY_CLASSIFICATION §5.1](INDUSTRY_CLASSIFICATION.md#51-既有錯配-membership-修復)。

K 線卡（頁首下方，#656 起標題「K 線」、不放眉標）畫日／週 K 線、成交量、MA5／10／20／60／120（可勾選，勾選列在圖下第一行）與規則價位線；「走勢」分頁是技術指標卡（眉標「技術指標 {公式版本}」、標題「技術指標」），放 MACD／RSI／KD／布林面板、指標批次時間、「最近 N 根日線；區間與日K／週K 跟著上方 K 線卡」與「查看圖表資料表（最近 30 根）」，區間與日K／週K 由上方 K 線卡決定、兩張圖同步（今日名單與大盤頁的 K 線卡不拆，維持一張卡）。兩張圖的資料全部取自 `GET /api/stocks/{exchange}/{symbol}/bars`（`limit=250`；公式與欄位見 [技術指標](spec/indicators.md)），前端不自行計算均線或指標；停牌與無效列不畫 K 線，缺日不補。

**區間按鈕**（[#600](https://github.com/YiCheng0608/stock-lab/issues/600)）：日K／週K 之後一列「1M」「3M」「6M」「1Y」「全部」，預設「6M」。按下時顯示範圍是最新一根往前推整數個月（月底對齊，03/31 往前 1M 是 02/28）的那天起、到最新一根，不重抓已載入的資料；資料不夠該區間時從第一根顯示到最新一根，不另出文案。日K／週K 切換、大盤頁換選列時區間維持；拖動、滾輪或雙指縮放後按鈕都不顯示為選取，換週期時沿用當下顯示的日期範圍；新的序列沒有這段日期（例如大盤頁加權「全部」拖到 2023 年再換 S&P 500）時退回預設的 6M。按「全部」（或某區間的起日早於已載入的第一根）且已載入的根數等於請求的 250 根時，圖表另取 `limit=1500`（API 上限）：載入中圖下 `chart-note`「正在載入更早的日線…」（週線寫「週線」），失敗時「更早的日線暫時無法載入，目前顯示最近 N 根」，再按任一區間按鈕會重新取一次；取到後 `chart-meta` 的「最近 N 根日線」與資料表都改讀這份。

指標或均線欄位為 null 時依最新一根判斷：

| 情況 | 顯示 |
| --- | --- |
| 原因全是 `not_computed` 且整段沒有值 | 面板「指標尚未計算」 |

### 8.3 張／零股

- DB／API／來源數量保存精確整數股與 unit；`LOT_SIZE=1000`。
- 成交量與法人買賣超的日常主值為整數張：股數 ÷ 1,000 四捨五入到整數，`.5` 一律遠離零，千分位逗號；以精確股數字串計算，不先轉 `Number`。499／500／1,500／−7,500 股分別為 `0`／`1`／`2`／`-8` 張；int64 上限 `9,223,372,036,854,775,807` 股為 `9,223,372,036,854,776` 張。絕對值不足 500 股的非零值（零股）主值為 `0`、不帶正負號，原股數見原始值；方向值非零時帶 `+`／`-`。多日合計先加總股數再換算，不把每日已四捨五入的張數相加。
- 依據（2026-10-25 查證）：TWSE [三大法人買賣超日報](https://www.twse.com.tw/rwd/zh/fund/T86?date=20261022&selectType=ALLBUT0999&response=json)與[個股日成交資訊](https://www.twse.com.tw/rwd/zh/afterTrading/STOCK_DAY?date=20261022&stockNo=2330&response=json)以股為單位、千分位、不換算張；[Yahoo 股市法人買賣](https://tw.stock.yahoo.com/quote/2330.TW/institutional-trading)標「單位(張)」，整數、千分位，與 T86 股數逐筆比對為四捨五入且 `.5` 遠離零（−500 股 → −1、−7,500 股 → −8、53,500 股 → 54），不足 500 股顯示 `0`，三大法人合計由股數加總後換算。
- 原股數放預設收合的「資料來源與原始值」或同等的來源稽核 details；表格單位依 §8.4 放表外。
- 庫存數量是持有量而非統計值，維持精確：拆末三位、保留至多 3 位小數的零股（1,500 股為 `1.5 張`、999 股為 `0.999 張`），不四捨五入。
- 價格與平均成本為元／股，不乘 1,000；API 未提供 currency 時寫「各標的報價幣別的元」，不猜 `NT$`。TAIEX 等指數用點數。
- 來源單位 unknown／mixed 不換算，表外說明「單位待核實」、數值格留空；來源已為張的融資不重複換算。可信 `quantity.unit="mixed"` 是同一已知股數的張／零股拆分，仍有效。
- Canonical 股字串只接受 ASCII `0` 或無前導零的非零整數；方向欄可有單一負號，不接受 `-0`、正號、分數、科學記號、空白或尾端換行。單日絕對值上限 `9223372036854775807`，買進／賣出與成交量須非負；5／20 日淨超的絕對值上限分別為 `46116860184273879035`／`184467440737095516140`。精確欄為 null、非法或壞字串時顯示待核實；response 完全沒有精確欄時才讀安全整數 number（`units.ts` 的 `exactVolumeText`）。
- **我的庫存**：表單預設 `unit=lot`，張數或股數輸入正整數 ASCII 字串；送出 `unit + quantity` 整數字串，例如 1 張送 `unit=lot, quantity="1"`、1 股送 `unit=odd_lot, quantity="1"`，讀回主值為 `1 張`／`0.001 張`。可保存總股數為 `1..9,223,372,036,854,775,807`，超限不送出，超大字串不經 Number；這個上限只留在程式，畫面不顯示：表單提示寫「每張為 1,000 股，可輸入整數張或零股股數。」，超限錯誤寫「數量超過可保存的上限，請確認張數或股數。」。平均成本與停損為元／股；空字串送 `null`，非空須為非負 ASCII 十進位數。前端拒收或 API 回 422 時保留 draft 並顯示錯誤。

| 庫存讀值 | 日常文案 |
| --- | --- |
| 股數無法核實 | 「庫存數量待核實」；原股數稽核顯示「股數待核實」 |
| 可信股數超出安全整數 | 市值／損益顯示「估值精度待支援」 |
| 成本或停損 missing／invalid | 「未提供」／「待核實」 |
| 本地收盤可試算 | 日常卡顯示「行情待核實」；收盤 missing／invalid 為「未提供行情」／「行情數值待核實」 |

本地收盤與市值／損益試算只在預設收合的「核對庫存原股數、本地行情與試算」內顯示，並標「本地記錄；來源／日期待核實」與「本地試算，行情來源／日期尚未核實」。

### 8.4 數值表格、單位與空白

每個數值欄位都要帶單位，使用者不必去讀表外說明才知道單位（[#463](https://github.com/YiCheng0608/stock-lab/issues/463)）：

- **表格**：單位寫在欄名後的全形括號，例如「收盤（元）」「漲跌幅（%）」「成交金額（億元）」「成交量（張）」「成交股數（股）」「樣本（筆）」「成員（檔）」。數值格只顯示數字，不逐格重複「元」「張」或 `%`，方向值明示 `+`／`-`。價格的「元」指各標的報價幣別的元，指數為「點」（§8.3），這層說明留在表外說明。
- **卡片與標籤／值**（手機卡片、`dl`、指標卡）：百分比在值後面接 `%`（`-9.62%`），倍數接「倍」，其他單位寫在標籤括號內，例如「成交金額（億元）」。
- **0–100 的分數與百分位**（族群分數、五分項、候選總分）沒有單位：分數欄名寫「分數（0–100）」「總分（0–100）」；五分項欄位多，量尺寫在表外說明一次。
- **兩個數字並列**時各自標名稱，不只用斜線隔開：價位寫「目標一／目標二」，值寫「{目標一}／{目標二}」，欄名與標籤用同一個順序。
- 表外說明仍寫空白、「—」與口徑的意思；單位已在欄名的就不再逐欄重寫。

缺值不寫 0、`N/A`、`--`、「無資料」或英文 placeholder，改為空白，並在表格外寫「空白表示來源未提供」；若原因是來源或單位未核實，須另行具體說明。

畫面呈現成交金額時，須依 API 的 `turnover_status` 決定數值格：`available` 且值為來源明確的 `0` 才顯示 `0`；`unavailable` 或 `unknown` 即使底層 `turnover=0` 也留空。`unavailable` 可在表格外說「成交金額未取得」，`unknown` 則說「成交金額待核實」，不把兩者合稱來源真的零；原因碼與數值狀態須一致。底層保存與計算規則見 [DATA_SOURCES](DATA_SOURCES.md)。tooltip、等效資料表與表外說明須同步使用相同口徑。

### 8.5 族群榜與族群詳情

- **榜別**：`board` 寫「產業」「題材」，其他值寫「其他」；族群頁與今日頁的分頁籤只有產業、題材兩個。
- **今日頁**：「熱門族群」區取各榜前 5 名（不放眉標，#510），標題列下一行是資料日期 badge（與導覽列的頁面日期同一天時不畫，§1、#661）與「1／5／20 日為相對加權指數的報酬」，每名兩行：名次、名稱、品質（只在不是「熱門族群」時顯示）、「分數」與分數；「1 日 {±%}　5 日 {±%}　20 日 {±%}」。完整排行在 `/themes`（「完整排行 →」）。
- **族群頁**（`/themes`，#522；版面見 [DESIGN_SYSTEM §5 族群榜](DESIGN_SYSTEM.md#5-元件)）：頁面標題只有眉標「族群排行」與「族群」。分頁籤與搜尋框下一行是「共 {N} 個」（搜尋時「符合 {n}／共 {N} 個」；分頁籤已標榜別，#666）與資料日期 badge，同一行右側收合的「說明」，展開後依序四句：「產業與題材各自成榜，依相對報酬、廣度、量能、法人與催化劑五分項計分；只有五分項完整的族群稱為熱門族群，熱門族群不另標，其他族群在名稱後標出資料完整度。」「分數 0–100，依分數排名；五分項為同榜百分位（0–100）；1／5／20 日為相對加權指數的報酬（%）；成員為有效／總數（檔）；「—」表示該項無資料。」「名稱後的兩個分項是五分項中最高與最低的一項。」「今日名單 N 檔是當日今日名單中屬於這個族群的檔數，沒有時不顯示。」（「分數」「排名」開 `heat_rank`、「同榜百分位」開 `percentile` 詞條）。每個族群兩行：
  - **第一行**：`#{rank}`、族群名（連到族群詳情）、品質 badge（只在不是「熱門族群」時）、最高與最低分項「{分項} {值}・{分項} {值}」；右側「分數 {分數}」。最高、最低依五分項原值，只看有值的分項，同值依分項的顯示順序（相對報酬、廣度、量能、法人、催化劑），在前的為最高、在後的為最低；只有一項有值時只寫那一項，都沒有值時寫「五分項無資料」。
  - **第二行**：「1 日 {±%}　5 日 {±%}　20 日 {±%}」；當日今日名單（`GET /candidates` 最新一期）的 `trading_date` 等於本榜 `trading_date`，且名單中有 `groups[].group_id` 等於這個族群的股票時，後接「今日名單 N 檔」（N 為檔數）；名單沒載入、載入失敗、日期不同或 0 檔都不顯示。
  - **五分項**：列右側按鈕「五分項 ▸」（展開時「五分項 ▾」），展開列下方：相對報酬、廣度、量能、法人、催化劑五格與「成員（檔）」（有效／總數），右側「族群詳情 →」。
- **品質**：`quality` 依 [§3](#3-三種資料完整度) 寫「熱門族群」或「技術與籌碼觀察（事件資料待補）」；其他值寫「資料完整度待核實」。
- **數值**：分數 0–100 取兩位小數；五分項是同榜百分位，以 0–100 整數呈現，族群榜列明細與族群詳情五分項卡畫成分數橫條、數字在橫條右側（列標題後的最高、最低分項只寫數字；#654）；1／5／20 日相對報酬是相對加權指數的百分比，兩位小數、正數帶 `+`，今日頁熱門族群、族群榜與族群詳情的族群報酬是漲跌文字（紅漲綠跌的文字顏色、沒有底色，#675；[DESIGN_SYSTEM §5 漲跌文字](DESIGN_SYSTEM.md#5-元件)），`aria-label` 寫「{N} 日相對加權指數 {±%}」，族群成員表的個股報酬仍是漲紅跌綠文字；成員寫「有效／總數」。單位依 §8.4：族群頁與今日頁精簡列的單位在「說明」或區塊標題下一行，1／5／20 日值後接 `%`，明細的格名寫「成員（檔）」；族群詳情的 1／5／20 日值後接 `%`。分項或報酬為 null 時顯示「—」（[DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)），並寫明「「—」表示該項無資料」，不寫 0。
- **日期**：右上角 badge 寫「資料 YYYY/MM/DD」（分數日 `trading_date`）（與導覽列的頁面日期同一天時不畫，§1、#661）；官方資料日 `data_as_of` 不同時另加「官方資料 YYYY/MM/DD」。
- **相關新聞時間**：族群詳情的相關新聞每列時間與新聞頁相同，只讀 `product_time`，文案見 [§4 日期](#4-新聞卡文案與折疊)。
- **空狀態**：空榜原文顯示 API 的 `empty_message`，前端不自組原因；走勢少於 2 個有分數的交易日寫「走勢資料不足（需至少 2 個交易日的分數）」；相關新聞為零寫「此族群尚無已核實關聯的新聞」。
- **族群詳情的名次與五分項**：名次、品質與五分項讀族群榜（`GET /themes?board=`），不是讀族群詳情本身，所以依族群榜請求分三種狀態，不混用（[#463](https://github.com/YiCheng0608/stock-lab/issues/463)）：
  - **載入中**：排名格與五分項卡顯示骨架（標 `aria-busy`），不寫「不在本日榜」。
  - **載入失敗**：排名格寫「—」與「榜單暫時無法載入」，五分項卡寫「榜單暫時無法載入：{原因}」，不寫「未列入」。
  - **已載入、不在榜上**：排名寫「—」與「未列入本日榜單」，五分項卡說明「此族群不在本日<榜別>榜（有效成員未達 3 檔或資料不足以計分），五分項沒有同榜百分位。」
  - **已載入、在榜上**：排名後接「<榜別>榜共 N 個族群」。分數與有效成員先讀族群榜那一列，沒有時讀族群詳情。排名、分數（0–100）、有效成員／成員（檔）三項在頁首寫成一行（#666 起不是三張卡；390 寬可在項與項之間換行，不截數字）。
- **族群成員表**（族群詳情「族群成員」，讀 `GET /themes/{id}/members`，每頁 30 檔；桌面表格、640px 以下每檔一張卡，[DESIGN_SYSTEM §5](DESIGN_SYSTEM.md#5-元件)；標題上方的眉標「成員資料截至 YYYY/MM/DD」只在與頁面日期不同天時寫，#661）：
  - **欄位**：代號 → 名稱（後接狀態 badge：今日候選寫「候選 #N」（`candidate_rank`），不是候選但有成立條件寫「條件成立」（`conditional`）；兩者都不是但符合行動列表第 3 級的接近規則（§5；持倉在行動列表列為第 0 級，這裡照樣標）寫「接近成立」（`near`）；題材榜 `role=leader` 另加「領先成員」）→ 市場（上市／上櫃）→ 收盤（元）（`latest_bar.close`，兩位小數）→ 漲跌幅（%）（`change_pct`，兩位小數、正數帶 `+`、紅漲綠跌；與今日候選 `market` 同一個相鄰交易日規則）→ 成交金額（億元）（當日成交金額，`turnover` ÷ 1 億，兩位小數、千分位）→ 5 日相對（%）、20 日相對（%）（`excess_return_5d`／`excess_return_20d`，讀當日族群分數的 `member_returns`，相對加權指數的報酬，兩位小數、正數帶 `+`、紅漲綠跌，與族群榜 1／5／20 日同一口徑）→ 證據（只有題材榜）。產業榜不顯示角色，題材榜的角色只以「領先成員」badge 呈現。
  - **排序**：表上方「排序」下拉：成交金額（預設）、漲跌幅、5 日相對、20 日相對，皆由大到小；代號由小到大。由 API 排序（`sort=turnover`／`change_pct`／`return_5d`／`return_20d`／`symbol`），空白值一律排最後，同值依代號；換排序回到第 1 頁。
  - **不同日**：成員最新一根日線早於「成員資料截至」日（`members_as_of`）時，收盤格下一行寫「資料 YYYY/MM/DD」（該根日期，§1），漲跌幅與成交金額留空，不拿舊日資料冒充當日；同日不標日期。
  - **空白**（§8.4）：`change_status` 不是 `known`（缺前一交易日的同來源日線、停牌或沒有當日日線）時漲跌幅留空；`turnover_status` 不是 `available` 時成交金額留空（`available` 且來源為 0 才寫 `0.00`）；不在 `member_returns` 的成員（例如未合格成員）5／20 日相對留空。單位在欄名（§8.4），表上方標題列右側預設收合的「說明」裡（#666 起不外露）先寫「收盤為各標的報價幣別的元；成交金額是當日成交金額；5／20 日相對是相對加權指數的報酬。」，再依本頁出現的情形逐句接：「漲跌幅空白表示前一交易日沒有收盤價，不計算漲跌。」（`no_previous_close`，[§8.2](#82-個股詳情的第一屏)）「漲跌幅空白表示該檔為掛牌首日（新上市或轉市），沒有前一交易日收盤。」（`first_trading_day`）「漲跌幅空白表示漲跌待核實。」（其他不是 `known` 的值）「成交金額空白表示來源未提供。」（`unavailable`）「成交金額空白表示待核實。」（`unknown`）「5／20 日相對空白表示未列入當日族群計分。」「收盤下方的「資料 YYYY/MM/DD」表示該檔沒有成員資料日的日線，漲跌幅與成交金額留空。」「收盤空白表示該檔尚無日線。」；本頁沒有空白就只有第一句。
- **題材成員證據**：`relation` 寫「主要業務」（core_business）、「產品線」（product_line）、「供應鏈」（supply_chain），`relevance` 寫「關聯度高／中／低」，未知值寫「關係待核實」「關聯度待核實」；http(s) 的 `url` 顯示「證據來源」並開新分頁，否則寫「來源連結未提供」；沒有證據寫「證據待核實」。題材詳情另列「題材表版本 <definition_version>」（#666 起在族群成員標題列的「說明」裡，排在單位句之前）。
- **成員手機卡**（640px 以下，#666）：外露代號名稱與 badge、收盤與漲跌幅、一行「5 日相對 {±%} · 20 日相對 {±%}」；「更多」裡是「成交金額（億元）」與題材證據，文字與桌面欄位相同。

### 8.7 個股清單

個股頁 `/stocks` 的標的目錄（[#602](https://github.com/YiCheng0608/stock-lab/issues/602)）。

- **頁首**（#666）：h1「個股」，右側預設收合的「說明」，展開依序兩段：「市場標的目錄：股票、ETF 與新上市標的分開標示；行動與缺資料優先級只來自已驗證官方快照。」「單位：價格為各標的報價幣別的元，指數為點。空白表示未提供資料或數值待核實；最近收盤早於最新交易日時，下方括號標出它的日期。」表格與卡片上方不再另寫單位句。篩選列最後是「共 {N} 筆」（千分位）；頁底分頁「第 {p}／{P} 頁 · 共 {N} 筆」不變。
- **手機卡**（640px 以下）：兩行，「{代號} {名稱}」與最近收盤；目前研究動作（資料不足時下一行缺項）與右側小字「{市場} · {類型}」。

- **欄位**：代號、名稱、交易所、類型、最近收盤（元）、目前研究動作。「目前研究動作」是行動摘要的動作標籤（`action_state`／`action_label_zh`，資料不足寫「暫不行動」）；資料不足時下一行 12px muted 小字寫第一個缺項（`missing_data_priority[0].field` 經 §9 的原因碼對照，例如「缺少 20 日有效行情」），其他動作只寫標籤。不另列「策略判斷資料」：它與研究動作同向（`data_quality=partial` 就是資料不足，2026-11-09 全量 2,357 檔無例外，[#602 交叉表](https://github.com/YiCheng0608/stock-lab/issues/602#issuecomment-6760088832)）；`data_quality` 是 `partial` 而動作不是資料不足時（例如持倉的需人工判讀），照樣只寫動作標籤。手機卡片同一格。
- **排序**：篩選列最後一個「排序」下拉（`filter-select`，無障礙名稱「個股排序」）：「類型（股票在前）」（預設：股票、ETF、新上市依序，同類型內依代號，同代號再依交易所）、「代號」、「名稱」、「最近收盤高到低」、「最近收盤低到高」（沒有收盤的排最後）。換排序、搜尋、類型或自選都回到第 1 頁。不提供依研究動作排序（即時算全量約 81 秒，[決定](https://github.com/YiCheng0608/stock-lab/issues/602#issuecomment-6760099353)）。
- **搜尋**：比對代號或名稱的字面（`%`、`_` 不當萬用字元），最多 100 字；導覽列搜尋框（§15）同一上限。

## 9. 中文原因碼對照

reason code 的日常文案由 `backend/app/presentation.py`（`REASON_LABELS`、`display_reason`）與 `frontend/src/presentation.ts` 提供，下表只列原則與代表列。未知 code 一律顯示「研究條件需要人工核對」，原值只留稽核層；不同策略的 code 保留各自範圍。

| 原始值 | 日常文案／處置 |
| --- | --- |
| `passed`／`rejected`／`data_incomplete`／`observation`／`conditional` | 「此研究條件已符合」「尚未成立」「資料不足」「條件尚未成立，持續觀察」「符合條件後可研究進場」；observation 不是缺資料，conditional 須附 T+1。tracking 狀態（`active`、`target_1_hit` 等）只在追蹤／歷史顯示，不替代今日結論。 |
| `*_missing_or_non_finite`／`*_missing_or_invalid`（如 `prior_20_highs_missing_or_invalid`） | 「<資料項>資料不足」（[#524](https://github.com/YiCheng0608/stock-lab/issues/524)；為什麼不足由 §6.1 的原因句說明）；不補 0，不把 unknown 當中性。 |
| `close_not_above_prior_20_day_high`／`volume_ratio_below_1_20` | 規則未通過，不是看空。 |
| `effective_group_score_missing_or_under_minimum_members` | 群組成員或相對大盤資料不足；不能顯示為 0 分。 |
| `etf_category_excluded_from_actionable_signals:<category>` | 債券／槓桿／反向 ETF 可收集與分榜，暫不產生一般 v1 動作。 |
| `invalid_levels` 與各價位關係碼（如 `invalid_price_must_be_below_entry`） | 「研究價位無法驗證」；隱藏不合法價位、目標與 RR。 |
| `target_1_risk_reward_below_minimum` | 第一目標 RR 未達門檻，不形成 conditional；不是績效結論。個股策略總表把只有 RR 類錯誤的列寫成「觀察」與 RR 句（[§10.1](#101-個股策略總表)，#580）。 |
| `unsupported_current_status`／`illegal_signal_status_transition` | 追蹤狀態無法驗證；日常顯示「需人工判讀」。 |

| `hot_group_rank` | 有當日合格群組 | 所屬{產業／題材}「{名稱}」熱度第 {排名} |

- **位置**：今日名單頁（`/`）大盤概況與持倉風險提示列之後、「熱門族群」之前（第一焦點）。標題列一行（#510 起不放眉標「條件已成立 · 依評分排序」；#493 前為「每日候選 · 依評分排序」「明日候選」）：標題「今日名單」、資料日期 badge、「{N} 檔」、小字接連兩句「{YYYY/MM/DD} 收盤後條件成立，最早下一個交易日（T+1）才可研究進場。」（日期為 `trading_date`；最新一天的 `earliest_execution_date` 一定為 null，不寫 T+1 的日期）與聲明句（句尾加「。」），最後是連到 `/strategy` 的「順勢籌碼型 · 策略說明 →」（#577：名稱在前，標出這份名單用哪一套策略；名稱是前端一個常數 `STRATEGY_NAME`，連結文字 `STRATEGY_LINK_LABEL` 由它組成，各狀態〔有候選、零候選、尚無清單〕都顯示）。個股頁的候選資訊在策略總表的候選列（[§10.1](#101-個股策略總表)），只在該股是策略總表資料日的候選時出現。
- **隔夜美股**（[#681](https://github.com/YiCheng0608/stock-lab/issues/681)，標題列之下、清單之上一行；有候選、零候選、尚無清單都顯示，載入中與載入失敗不顯示；讀 `overnight_us`，[美股指數 API 契約](DATA_SOURCES.md#美股指數-api-契約)）：一行「隔夜美股 {開頭語} 資料 {YYYY/MM/DD} S&P 500 {±漲跌幅%} · NASDAQ {…} · 道瓊 {…} · 費半 {…}」。
  - 開頭語：四檔都沒有前一晚（沒有一檔 `freshness` 是 `latest`／`us_market_closed`，含四檔都沒有收盤）寫「美股尚未更新」；有新的而全是 `us_market_closed` 寫「美股休市」；其他不寫。
  - 資料日：有收盤的幾檔同一天時寫一次「資料 YYYY/MM/DD」（美股的美東日期，與導覽列的台股日期不同，所以一定寫）；日期不同時不寫這段，改在每檔後面接「（YYYY/MM/DD）」。

  - 費半對應（`overnight_us_links`，對應表見 [DATA_SOURCES](DATA_SOURCES.md#美股指數-api-契約)）：候選屬半導體相關族群時，列的第一行在名稱之後、「{上市／上櫃} · {族群短寫}」之前寫「費半 {±漲跌幅%}」（同上格式與顏色；不是前一晚的值時再接「非最新」；放在族群前，是因為第一行放不下時從行尾以省略號截掉，截的是族群而不是費半）；費半沒有收盤或沒有對應時不寫。只是背景資訊，不影響分數、排序與名單。
- **今日名單每檔**（#510：所有寬度同一份清單，每檔一列，[DESIGN_SYSTEM §5 候選列表](DESIGN_SYSTEM.md#5-元件)）：
  - **列**：第一行「#{rank} {代號} {名稱} {上市／上櫃} · {族群短寫}」（半導體相關族群在名稱之後、市場之前插入「費半 {±漲跌幅%}」，見上方「隔夜美股」，#681），族群短寫依下方「族群」的三種：計入族群分「{名稱}（{產業／題材} #{rank}）」、資料不完整「{名稱}（{產業／題材}，事件資料待補）」（「事件資料待補」為詞彙按鈕）、其他「{名稱}（{產業／題材}，未排名）」，沒有群組「無所屬族群」，完整寫法（下方「族群」）放在 `title`。第二行是 [§10.2](#102-進場方式) 的類型與主句，句中「停損」「目標」開 `support`／`target` 詞條；主句改寫缺價位的原因時，句下加「進場區（元）」「停損（元）」「目標一／二（元）」三格（沒有目標二時寫「目標一（元）」）。進場句之下的走勢線與價位尺（[DESIGN_SYSTEM §5 候選列表](DESIGN_SYSTEM.md#5-元件)）不帶頁面文字，只有 `aria-label`：走勢線（[#653](https://github.com/YiCheng0608/stock-lab/issues/653)，讀 `recent_closes`）寫「近 {N} 個交易日收盤走勢：{第一個有收盤的日期}–{最後一個有收盤的日期} {±漲跌幅}%」（N 是 `dates` 的筆數，日期 YYYY/MM/DD，漲跌幅為最後收盤對第一個收盤、兩位小數，正數帶 `+`，持平寫「0.00%」）；價位尺寫「收盤在停損與進場之間」「收盤在進場與目標之間」「收盤已低於停損」「收盤已高於目標」。右側三組標籤與值：「收盤（元）」（`market.close` 兩位小數；下一行漲跌幅，正數帶 `+`、紅漲綠跌；`change_status` 為 `no_previous_close` 寫「前一交易日無收盤」、`first_trading_day` 寫「掛牌首日」（[§8.2](#82-個股詳情的第一屏)），其他不是 `known` 的寫「漲跌待核實」，沒有當日日線時收盤寫「待核實」）、「RR」（值後接「倍」；下一行小字寫 RR 的計算基準（[#580](https://github.com/YiCheng0608/stock-lab/issues/580)，讀 `levels.risk_reward_basis`）：`entry_zone_midpoint`「以進場區中點計算」、`entry_price`「以進場價計算」、`signal_close`「以資料日收盤計算」（`pullback_v4` 以前的回踩），沒有這欄或值未知時不寫）、「總分（0–100）」；「RR」「總分」以詞彙按鈕開詞條（§7）。主要理由與均量不在列上，在展開內容。
  - **AI 入口**：`llm_note` 存在（`done` 或 `pending`）時按鈕寫「AI 推論 ▸」，null 或欄位不存在時寫「AI 說明 ▸」。
  - **名次按鈕**（K 線卡，[DESIGN_SYSTEM §5 候選列表](DESIGN_SYSTEM.md#5-元件)）：按鈕文字一律是「#{rank}」。1280px 以上選右側的圖，`aria-label`「第 {rank} 名，顯示走勢圖」（`aria-pressed`）；1279px 以下開合該列下方的 K 線卡（[#665](https://github.com/YiCheng0608/stock-lab/issues/665)），`aria-label` 收起時「第 {rank} 名，展開 K 線圖」、展開時「第 {rank} 名，收起 K 線圖」（`aria-expanded`）。展開的卡是一個 region，`aria-label`「{代號} {名稱} 走勢圖」（同 1280 右側卡）；卡內文案同個股頁 K 線卡。不帶 K 線卡的名單，名次不是按鈕，`aria-label`「第 {rank} 名」。
  - **展開內容**（該列下方，#510 的順序）：① 「AI 進出點說明」區（文案同下方 AI 進出點說明；第一段「為何入選」是摘要）；② 規則價位「進場區（元）」「停損（元）」「目標一／二（元）」「RR」（詞彙按鈕同上；RR 的值寫「{RR} 倍（以{基準} {價} 元計算）」，基準依 `risk_reward_basis` 寫「進場區中點」「進場價」「資料日收盤」，價是 `levels.entry`；基準未知或沒有價時只寫「{RR} 倍」），「加入追蹤」（§12）與「評分細節 → 個股頁」連結；③ 三個預設收合：「完整條件（YYYY/MM/DD 判定）」（[§10.2](#102-進場方式)）、「分項分數與理由」（部分分項說明、四分項（各一條 0–100 分數橫條，數字在右，無資料寫「—」不畫填色；#654）與全部理由，理由照 API 順序，`inference=true` 的理由只標一次推論：文字已寫「（推論）」就不另加 badge，沒寫才同列加「推論」badge，#661）、「資料日期與來源」（「20 日均量 {N} 張（資料日期 {`liquidity.data_as_of`}，候選門檻 {門檻} 張）」，資料日期與頁面日期同一天時寫成「（候選門檻 {門檻} 張）」，N 為 `liquidity.average_volume_lots_20d` 無條件捨去的整數張、千分位（999.6 張寫「999 張」，不會寫成門檻值），`liquidity` 為 null（v6 以前的 run）時不顯示；「資料日期 YYYY/MM/DD」只在與頁面日期不同天時寫（#661）；「來源：{同評分細節的來源}」，來源是事實，新聞方向寫「新聞方向 LLM 判讀 {提示版本}」不接「（推論）」）。評分細節表只在個股頁。
  - **其餘收合**：預設列前 10 檔，其餘以「顯示其餘 {N} 檔」展開（展開後寫「收合其餘 {N} 檔」）。
- **個股頁候選列**（策略總表最上方，[§10.1](#101-個股策略總表)）：「每日候選」badge、「第 {排名} 名 · 總分 {0–100} · {突破條件／回踩條件}」，同列接聲明句「評分只用於排序，不代表勝率或預期報酬」；進場方式（[§10.2](#102-進場方式)）；收合的「理由與 AI 進出點說明」（#519，展開為全部理由與 AI 進出點說明區）；收合的「評分細節、資料日期與來源」，展開列子項原值、百分位（表頭「百分位」，表外說明「分數與百分位為 0–100」）與權重（每個分項的標題列是「{分項} 分數橫條 權重 N%」，#654 起取代「{分項}（{分數}，權重 N%）」；子項百分位仍是數字）、同檔另一策略、權重涵蓋、資料日期、規則最早執行日與來源。價位欄不在候選列重複；#648 起進場句也不重複：候選的停損與目標一和策略總表某個成立列相同時，進場方式改寫成類型標接「進場、停損與目標價見下方策略總表「{突破條件／回踩條件}」列。」，其下「完整條件」照舊；不相同時照舊寫 §10.2 的句子。
- **子項名**：量比「量比（當日量／前 20 日均量）」、距離「距離（突破距 20 日高點、回踩距 20 日均線）」、RR「RR（只顯示，不計分）」、法人「三大法人 5／20 日淨買超（÷20 日均量）」、融資「融資 5 日變動」、新聞「近 3 日新聞淨方向（偏多＋1、偏空−1）」、族群「所屬族群榜內位置」。倍數兩位小數加「倍」，距離與融資為 %、一位小數。
- **分項名**：technical「技術」、chips「籌碼」、group「族群」、news_sentiment「新聞情緒」；新聞情緒另標「推論」。
- **族群**（`groups[0]`，`candidateGroupText`；#453）：依該群組存下的 `qualified` 與 `data_quality` 分三種，不把有排名的群組寫成未排名：
  - 計入族群分（`qualified`）：「{名稱}（{產業／題材}，第 {rank} 名／{board_size}）」，沒有 `board_size` 時只寫「第 {rank} 名」。
  - 資料不完整（`data_quality=partial`）：「{名稱}（{產業／題材}，事件資料待補，未計入族群分）」，「事件資料待補」以詞彙按鈕開 `event_data_pending`，與族群榜的 partial badge 同一詞。這個群組在族群榜上仍有名次，但候選只用五分項完整的群組（[candidate_score 族群](spec/candidate_score.md)），所以不寫名次。
  - 其他（沒有分數列、`insufficient_members`、`insufficient_data`）：「{名稱}（{產業／題材}，當日未排名）」。
  - 沒有所屬產業或題材時寫「無所屬產業或題材」。
- **分數**：總分與分項為 0–1，日常以 0–100 整數呈現；分項為 null 顯示「—」並附 API 的 `null_explanation`，不寫 0。`partial_components=true` 時在總分旁註明「部分分項無資料，以有資料的分項計分」。
- **聲明**：清單頂端固定一句「評分只用於排序，不代表勝率或預期報酬」。
- **AI 進出點說明**（`llm_note`，[候選 AI 進出點說明](spec/candidate_score.md#候選-ai-進出點說明)）：個股頁候選列在理由之後、「評分細節」之前，今日名單在展開內容的最上方（#510），放 AI 推論樣式的區塊（左側強調色豎線，[DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)），標題「AI 進出點說明」，右側「AI 推論」（accent badge）。`status=done` 且三段都有字時依序列「為何入選」「進場區、停損與目標」「需留意的風險」與 API 文字；沒有說明（`llm_note` 為 null 或欄位不存在）寫「此檔尚未產生 AI 說明」，`pending` 寫「AI 說明這次未能產生」（不承諾自動重試，補跑見 [日誌與 run 記錄](ops/SCHEDULING.md#日誌與-run-記錄)）。區塊內固定一句「由 AI 依上方規則數值、理由與關聯新聞撰寫的推論，不是買賣建議；價位以規則數值為準。」；有 `llm_note` 時底部「模型 {model，沒有寫未記錄} · 提示版本 {prompt_version} · 產生於 YYYY/MM/DD HH:mm」（`generated_at` 換算台北時間，沒有時區時省略時間）；`pending` 不寫模型，時間改寫「嘗試於」。今日頁與個股頁相同。
- **零候選**：顯示 API 的 `zero_reason_text`；`no_actionable_signals`「當日沒有成立（條件成立）的策略訊號」、`all_excluded`「成立的訊號都因 ETF、價位不合法、成交量低於門檻或評分資料不足被排除」。`status=not_computed` 寫「此交易日尚未產生候選清單」。空狀態標題分別為「當日零候選」與「尚無候選清單」，零候選保留資料日期 badge、not_computed 不顯示日期。

### 10.1 個股策略總表

`GET /api/stocks/{exchange}/{symbol}` 的 `strategy_board`（#274），個股頁「進出場」分頁最上方，取代原本的候選面板與靜態條件清單。視覺見 [DESIGN_SYSTEM §5 策略總表與 §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)。

- **標題列**：標題「策略總表」（#519 起不放眉標），右側「資料 {YYYY/MM/DD}」（`as_of`，該股最近一個策略判定日（與導覽列的頁面日期同一天時不畫，§1、#661））與「價位規則 v1」（`levels_version`）。標題下的「說明」收合內固定一句「每個研究條件各自判定；「觀察價位」是條件尚未成立時，下一交易日收盤與成交量要達到的參考值，不是建議進出點。」下一行「20 日均量 {N} 張 · 資料日期 {YYYY/MM/DD}（候選門檻 {門檻} 張）」（`liquidity`；均量為 null 寫「20 日均量資料不足」，`minimum_lots` 為 null 時省略括號）。沒有任何判定時寫「此股尚無策略判定資料。」不顯示勝率或成立機率。
- **欄位**（桌面表格；640px 以下每策略一張卡，內容相同）：策略（「突破條件」「回踩條件」，詞彙按鈕）→ 狀態 → 差哪個條件 → 價位；每列下方「{策略}明細」展開（策略名已以「條件」結尾：「突破條件明細」「回踩條件明細」，不寫成「突破條件條件明細」，#581）。
- **狀態**：`conditional`「成立」（下一行「最早執行日 {YYYY/MM/DD}」，沒有日期時省略；`liquidity.candidate_exclusion` 有值時再下一行寫 §6 第 2 級同一句的「20 日均量 {N} 張，低於 {門檻} 張門檻，不列候選」或缺資料句，不加「條件成立，」前綴）、`observation`「觀察」、`data_incomplete`「資料不足」、`not_applicable`「不適用」；未知值寫「狀態待核實」。成立是指資料日判定成立，之後追蹤狀態（觸發、達標、失效）不改這一欄。
- **RR 未達門檻**（[#580](https://github.com/YiCheng0608/stock-lab/issues/580)）：條件全部達成、但價位驗證不過（analyze 記 `invalid_levels`）的列，若缺項為空、價位錯誤只有 RR 類（`target_1_risk_reward_below_minimum`、`target_1_must_exceed_entry`、`invalid_price_must_be_below_entry`），API 回 `status=observation` 與 `risk_reward_shortfall`（`risk_reward`、`minimum`、`risk_reward_basis`、`entry`、`errors`；`risk_reward` 為 null 表示中點不在停損與目標一之間），狀態寫「觀察」、價位欄照觀察列讀條件價位，「差哪個條件」寫下方的 RR 句。其他 `invalid_levels`（價位缺漏或非正數）照舊是「資料不足」與「研究價位無法驗證」。
- **條件表**：每個條件碼的文案只在這張表定義。程式各一份：「差哪個條件」「條件明細」「接近成立的差：句」在前端 `frontend/src/stock/strategyBoard.ts`（`CONDITIONS`），「短名」在策略 registry（`backend/app/strategies`，`Strategy.short_label`），API 把短名放進行動列表的 `nearness` 與 `primary_reason`，前端不另存短名。兩份的條件碼都要等於 registry 各策略的條件（測試核對）。未知碼一律寫「研究條件需要人工核對」。

  | 條件碼 | 短名 | 差哪個條件 | 條件明細 | 接近成立的差：句 |
  | --- | --- | --- | --- | --- |
  | `eligibility` | 適用標的 | 標的不適用 | 適用標的 | — |
  | `required_inputs` | 必要資料 | 資料不足 | 必要資料齊備 | — |
  | `breakout_price` | 價格 | 收盤未突破前 20 日高點 | 收盤突破前 20 日高點 | 差：收盤站上前 20 日高點（還差 {價格差距}%） |
  | `breakout_volume` | 量能 | 量比未達 {threshold} 倍 | 量比 {門檻} 倍 | 差：量能 {門檻} 倍（今日 {量比} 倍） |
  | `pullback_history` | 日線 | 日線未滿 {threshold} 日 | 日線滿 {threshold} 日 | — |
  | `pullback_trend` | 趨勢 | 20 日均線未站上 60 日均線 | 20 日均線在 60 日均線之上 | — |
  | `pullback_above_ma60` | 趨勢 | 收盤低於 60 日均線 | 收盤不低於 60 日均線 | — |
  | `pullback_support_zone` | 支撐區 | 收盤不在支撐區 | 收盤在 20 日均線支撐區 | 差：收盤回到 20 日均線支撐區（高於上緣 {價格差距}%）；低於下緣時寫「低於下緣」；資料日收盤不在當日支撐區、但已在下一交易日的區間內（`position=inside`，差距 0）時括號寫「最近收盤已在下一交易日的區間內」 |
  | `pullback_volume` | 量能 | 量比不在 {threshold}～{threshold_high} 倍 | 量比 {門檻} 倍 | 差：量能 {門檻} 倍（今日 {量比} 倍） |
  | `group_relative_strength` | 族群 | 族群未強於大盤 | 族群 20 日超額報酬 {門檻}% | — |
  | `institutional_flow` | 法人 | 法人籌碼未達要求 | 法人 5 日淨額 ÷ 20 日均量 {門檻}% | — |
  | `margin_financing` | 融資 | 融資增加超過上限 | 融資 5 日變動 {門檻}% | — |

  「接近成立的差：句」只用於能接近的條件（價格、量能，§5）；其他條件未達成時不會判接近。{門檻} 的寫法見下方條件明細；{價格差距} 讀 `nearness` 的 `gap`（下一交易日距離，§5），v1 例：「差：收盤站上前 20 日高點（還差 2.10%）」「差：量能 ≥ 1.20 倍（今日 0.80 倍）」「差：量能 0.60～1.20 倍（今日 1.32 倍）」。
- **差哪個條件**：成立寫「全部達成」；條件全部達成、只有 RR 未達門檻的列（`risk_reward_shortfall`，下方）寫「條件全部達成，但以進場區中點計算的 RR {x} 倍未達 1.5 倍」（基準依 `risk_reward_basis`：「以進場價計算的」「以資料日收盤計算的」；未知時省略「以…計算的」），中點不在停損與目標一之間（`risk_reward` 為 null）時寫「條件全部達成，但進場區中點不在停損與目標一之間，RR 未達 1.5 倍」；研究條件摘要卡這一行不加「差：」；觀察列出 `unmet` 的「差哪個條件」短句（條件表），以「、」連接；資料不足寫「無法判斷：{句子，以「；」連接}」：每個缺項（`missing`）依主題取同一檔行動摘要 `gap_reasons` 的句子（§6.1；法人取 `institutional_not_listed`／`institutional_not_collected`，融資取 `margin_not_listed`／`margin_not_collected`／`margin_zero_base`，行情與均線取 `listed_under_threshold`、`suspended_or_no_trade`、`capital_reduction_halt`、`official_no_trade`、`bar_invalid`、`quote_not_listed`、`missing_bar_dates`、`coverage_baseline_unknown`，族群報酬取 `group_return_unavailable`；上市未滿 20 個交易日時族群報酬與法人、融資比率也取 `listed_under_threshold`），同一句只寫一次；找不到同主題的句子時用該缺項的 `missing_labels`（#524）；不適用直接寫 `missing_labels`（例：「債券、槓桿或反向 ETF 不適用一般突破／回踩研究條件」）。
- **成立價位**（`levels.kind=actionable`，讀訊號）：突破「觸發（元）」、回踩「進場區（元） {低}～{高}」，接「停損（元）」「目標一／目標二（元）」（值「{目標一}／{目標二}」；沒有目標二時標籤與值都只寫目標一）「RR」（值後接「倍」，badge 之後寫「（以{基準} {價} 元計算）」，同 [§10](#10-每日候選) 展開內容；價是突破的觸發、回踩的 `reference_entry`）；價位兩位小數，標籤與今日候選相同（詞彙按鈕）。
- **觀察價位**（`levels.kind=observation`，讀條件價位）：一律在「條件未成立・觀察價位」標籤之下；策略總表內整塊收合，標籤就是收合列的文字（#519），摘要卡內不收合。`availability=levels`：突破「收盤（元） ≥ {觸發}」「成交量 ≥ {最小量} 張」；回踩「收盤（元） {低}～{高}」「成交量 {最小}～{最大} 張」；兩者都接「參考停損（元）」「參考目標一／目標二（元） {目標一}／{目標二}」（沒有目標二時寫「參考目標一（元）」），再一句「對象：下一交易日 {YYYY/MM/DD} 收盤；價位為參考，成立當天依實際資料重算。」`reachable_next_session=false` 加一句「超出下一交易日漲跌停範圍，下一交易日無法達到。」`trend_unreachable`：「下一交易日趨勢條件無法成立：收盤需高於 {趨勢下界} 才能讓 20 日均線站上 60 日均線，但支撐區上緣只有 {支撐區上緣}，不產生觀察價位。」其他 availability：「不產生觀察價位：{原因}」。觀察訊號沒有條件價位列（較早的日期、或條件價位步驟失敗）時寫「觀察價位未產生：這個資料日的條件價位尚未計算或計算失敗。」，不補任何價位。
- **量的單位**：觀察價位與條件明細的成交量依 [§8.3](#83-張零股) 換成整數張，但這裡是條件的門檻：下限（最小量）無條件進位、上限（最大量）無條件捨去，顯示的門檻不會比實際條件寬鬆（例：15,110,400 股寫「≥ 15,111 張」）；API 保留原始股數。
- **條件明細**：每條一行，前置狀態 badge「已達成」（success）／「未達成」（warning）／「無資料」（muted）／「不適用」（muted），接條件名（條件表「條件明細」欄）。{門檻} 由 API 該條的 `operator`（`gt` >、`gte` ≥、`lt` <、`lte` ≤）與 `threshold` 組成，`between` 寫「{threshold}～{threshold_high}」，數字兩位小數（比率乘 100 為 %），前端不寫死規則數字；條件沒有門檻時改寫「達規則門檻」「在規則區間」等，不補數字（例：v1 為「量比 ≥ 1.20 倍」「量比 0.60～1.20 倍」「族群 20 日超額報酬 > 0.00%」「法人 5 日淨額 ÷ 20 日均量 ≥ -0.30%」「融資 5 日變動 ≤ 5.00%」）與資料日的實際值（價格兩位小數、量比兩位小數加「倍」、比率為帶正負號的 %、兩位小數）；未達成且可反推的條件另起一行「下一交易日收盤 ≥ {價}（距最近收盤 {±%}）」「下一交易日成交量 {最小}～{最大} 張」等。`eligibility`／`required_inputs` 未通過時列原因（§9）。
- **不適用的條件**（[#392](https://github.com/YiCheng0608/stock-lab/issues/392)）：非融資標的的融資條件（`satisfied` 為 null、`reasons` 含 `margin_financing_not_applicable`）badge 寫「不適用」，數值欄寫原因「非融資標的，融資條件不適用」，不寫「—」也不列下一交易日；它不算未達成，也不是缺資料，所以不出現在「差：」與「缺：」。行動頁不另列這一條：這類標的的卡片照其他條件分級，不再顯示「近 5 日融資變化資料不足」。缺資料的融資條件照舊是「無資料」。
- **候選列**：見 [§10](#10-每日候選) 個股頁候選列（總分旁有聲明句）；AI 說明只出現在候選列，策略列不放 AI 內容。

### 10.2 進場方式

每檔候選的第一行用白話寫「這是哪一型、明天怎麼進、跌破哪裡停損」（[#491](https://github.com/YiCheng0608/stock-lab/issues/491)，統籌決定 6647568372、review 6648572346）。句子只讀訊號的價位，失效條件只有停損；條件價位（[strategy_levels](spec/strategy_levels.md)）的觸發價與區間是「下一交易日會不會再出一個新訊號」的門檻，不是這個訊號的失效條件，句子不用它們的任何數字。文案與判斷在 `frontend/src/candidates/entryPlan.ts`，元件 `EntryPlanCard` 只讀候選本身（`levels`、`entry_plan`、`trading_date`），之後的頁面直接重用。

- **位置**：今日名單每列的第二行（#510；句子不收合，完整條件放在展開內容的收合列）（主句有價位時，列上不另放價位格，統籌決定 6647903049）；個股頁候選列（§10 個股頁候選列）在標題列之後、理由之前。
- **類型**：行首是詞彙按鈕「突破型」（`breakout_entry`）或「回踩型」（`pullback_entry`），依訊號的 `entry_type`；其他值寫「進場方式」，句子寫「進場方式待核實：這個策略沒有對應的白話說明。」
- **主句**（讀訊號的成立價位，與今日名單列缺價位時的「進場區／停損／目標一」格、個股頁策略總表成立列是同一組數字，也是追蹤計畫與回測模擬的口徑）：
  - 突破型：「{資料日 YYYY/MM/DD} 收盤已突破 {進場價} 元。明天起在 {進場價} 元附近可進場；跌破 {停損} 元停損，目標 {目標一} 元」。
  - 回踩型：「{資料日} 已拉回到支撐區。明天起在 {進場區低}～{高} 元之間可進場；跌破 {停損} 元停損，目標 {目標一} 元」。
  - 價位兩位小數；進場、停損、目標依 [DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言) 進出點用色；句中「停損」「目標」兩個詞以詞彙按鈕開 `support`／`target`（#493，今日名單表格沒有價位表頭可以帶詞條），文字不變。
- **缺價位**：訊號的進場價（回踩為進場區兩端）、停損、目標一、資料日任一缺漏或不合理（非正數、NaN、突破的停損不低於進場或目標不高於進場、回踩的進場區下緣高於上緣或停損不低於目標）時，主句改寫「成立價位不完整，暫不顯示進場價位；請看個股頁的策略總表。」（個股頁本身只寫「成立價位不完整，暫不顯示進場價位。」；warning 色），不出現空白、0、NaN 或「—」。
- **完整條件**：有條件價位列（`entry_plan`）時，句子下方（今日名單為 AI 明細與「AI 說明」的最上方）收合的「完整條件（{資料日} 判定）」逐條列資料日的判定：狀態 badge（已達成／未達成／無資料／不適用，同 §10.1 條件明細）、條件名（§10.1 條件表「條件明細」欄）與資料日的實際值；不列下一交易日的門檻。非融資標的的融資條件寫原因「非融資標的，融資條件不適用」；`eligibility`、`required_inputs` 不列。沒有條件價位列時不顯示這一塊。

## 11. 今日頁頁首、大盤摘要與大盤頁

版面與順序見 [PRODUCT_SPEC §2](PRODUCT_SPEC.md#2-主導航與資訊順序) 與 [DESIGN_SYSTEM §4](DESIGN_SYSTEM.md#4-版面與導航)。大盤概況 #549 起從今日名單頁移到大盤頁 `/market`，今日名單頁只留一行摘要。

- **頁首資料列**（今日名單）：一行「{來源} · {快照模式}」，「資料截至 YYYY/MM/DD · 」只在與導覽列的頁面日期不同天時寫在最前（#661）（`dashboard.as_of`、`market.source_label`；模式寫「官方單日快照」「官方單日快照（資料仍待補）」「尚無官方快照」），右側品質 badge 與「資料說明」展開。「資料說明」依序列：掃描範圍與標的、日行情、行動摘要筆數；上櫃漲跌幅為 `derived` 時「櫃買指數漲跌幅依前一日收市指數計算」（摘要列有櫃買漲跌幅）；固定一句「紅色為上漲、綠色為下跌（台股慣例）」。成交金額範圍不在這裡，在大盤頁。
- **大盤摘要列**（今日名單，頁首資料列下一行）：讀 `dashboard.market_overview`。一行「大盤」→「加權 {收盤} {±漲跌幅%}」→「櫃買 {收盤} {±漲跌幅%}」→ 資料日期 badge「資料 YYYY/MM/DD」（`market_overview.trading_date`；與頁面日期同一天時不畫，#661；沒有日期時「資料日期未提供」）→「看大盤 →」連到 `/market`。收盤與漲跌幅兩位小數、千分位，漲跌幅正數帶 `+`、紅漲綠跌；漲跌幅為 null 寫「—」。某交易所 `status=unavailable` 時該項寫「加權 未取得」或「櫃買 未取得」，另一項照常。不放成交金額與漲跌家數。
- **大盤頁頁首**：h1「大盤」，右側預設收合的「說明」（#666），內容是一句「上市、上櫃的收盤概況，以及加權、櫃買、台指期近月三檔指數的總表；點一列看它的日 K。」
- **大盤概況**（大盤頁第一個區塊，標題「大盤概況」）：讀 `dashboard.market_overview`（交易日與 `dashboard.as_of` 相同），標題列右側資料日期 badge「資料 YYYY/MM/DD」（與導覽列的頁面日期同一天時不畫，§1、#661）與「資料說明」。四格：
  | 格 | 標籤與單位 | 內容 |
  | --- | --- | --- |
  | 加權指數 | 「加權指數」，單位「點」 | 上市 `index.close` 兩位小數；下一行漲跌點數與漲跌幅「{±點數}（{±%}）」，兩位小數、正數帶 `+`、紅漲綠跌 |

## 12. 追蹤計畫

使用者把成立的研究條件存成[追蹤計畫](spec/tracking.md#使用者追蹤計畫)；成交與結果都是依日線規則的**模擬**，不是實際成交，也不是 LLM 推論（不標「推論」）。文案常數在 `frontend/src/tracking/tracking.ts`，verify 的 actions A14～A17、today T13 依同一份字串比對。

- **加入追蹤**：今日頁每檔候選的展開內容（規則價位之下，#510）放 secondary 按鈕「加入追蹤」（送出中「加入中…」）；該訊號已有未取消的計畫時改成連結「已在追蹤」，連到 `/watch#plan-<id>`。個股頁的入口只有「進出場」分頁的「追蹤計畫 · 模擬」卡，標題「把研究條件加入追蹤」：每個成立（`conditional`）的策略一列「{突破條件／回踩條件}成立」、`條件資料日 YYYY/MM/DD`（與頁面日期不同天時才寫，#661） 與同樣的按鈕；沒有成立的策略時只寫一行「目前沒有成立的研究條件，無法建立追蹤計畫」。卡底說明「加入後每日依日線規則模擬成交與出場，結果在我的追蹤「追蹤計畫」與「追蹤回看」；不是實際成交。」
- **拒絕原因**（API `detail`）：`stale_signal`「這個研究條件的資料日已過，請用最新資料日的條件建立」、`signal_not_conditional`「這個研究條件目前不成立，無法建立追蹤計畫」、`invalid_levels`「研究條件的價位不完整或不合理，無法建立追蹤計畫」、`candidate_signal_mismatch`「候選與研究條件不一致，請重新整理頁面」、`candidate_not_found`「找不到這筆候選，請重新整理頁面」、`signal_not_found`「找不到這個研究條件，請重新整理頁面」，其他「加入失敗，請稍後再試」。
- **我的追蹤區塊順序**：「我的庫存」（實際持倉）→「追蹤計畫」（眉標「模擬追蹤 · 進行中」，待觸發與已觸發）→ 行動列表（[§5](#5-行動中心的分級與預設篩選)）→「追蹤回看」（眉標「模擬追蹤 · 已結束」，含已取消；#637 起排在行動列表之後，今天要處理的不被回看紀錄壓在下面）；各區不混排，區塊標題右側寫「{n} 筆」。「追蹤回看」預設收合（#649）：整個標題列（眉標、標題與「{n} 筆」）就是展開鈕，右側接「展開 ▸」／「收合 ▾」；從 `#plan-<id>` 連到已結束的計畫時自動展開並捲到該卡。「追蹤計畫」標題下固定一句「計畫價位來自建立當日的研究條件；成交與結果是依日線規則的模擬（買賣各 {滑價} bps 滑價、來回 {成本} bps 成本假設），不是實際成交，也不統計勝率。實際持股請看「我的庫存」。」（數字取 API `meta`）。空狀態「尚未建立追蹤計畫。可從今日候選或個股研究條件加入。」與「尚無已結束的計畫。」。每區每頁 20 筆，超過時下方「第 {頁}／{總頁} 頁 · 共 {總數} 筆」與上一頁／下一頁。
- **計畫卡**：眉標「{上市／上櫃} · {策略}」，標題代號與名稱（連個股頁），右上狀態 badge 與 `資料 YYYY/MM/DD`（追蹤到的最後交易日，還沒有就用計畫資料日；與頁面日期同一天時不畫，較早的照畫，#661）。狀態：`pending` 待觸發、`triggered` 已觸發、`target_hit` 達標、`invalidated` 失效、`incomparable` 無法比較、`expired` 到期、`closed` 期滿結算、`not_entered` 未進場、`cancelled` 已取消。`data_quality=transition_conflict` 時在價位上方加「行情有更正，狀態待核對」，狀態維持 API 的原狀態。價位列「進場區（元）」「停損（元）」「目標一（元）」「RR」（值後接「倍」；停損是策略的條件失效價，與今日名單卡、候選表同名，#581；計畫只追蹤目標一）。之後依序：`計畫資料日 YYYY/MM/DD · 建立 YYYY/MM/DD`（建立日為 `created_at` 的台北日期）、`第 {n}／{視窗} 個交易日`、`模擬成交 YYYY/MM/DD {價格}` 或「尚未模擬成交」、有出場時 `模擬出場 YYYY/MM/DD {價格}`。640px 以下（#649）卡上只留眉標、標題、狀態與資料日期 badge、進場區／停損／目標一三格、`第 {n}／{視窗} 個交易日` 與模擬報酬（已結束的卡）；RR、計畫資料日與建立日、模擬成交與出場、「取消追蹤」與逐日明細收進卡底的「更多」。
- **模擬報酬**：只在已結束的卡。可比較時 `模擬報酬 {±x.xx%}`（`result_return × 100`，兩位小數，正數帶 `+`）；其餘寫 `模擬報酬：無法比較（{原因}）`：未進場「成交當日開盤已在目標以上，不模擬進場」（`gap_above_target`）或「成交當日開盤已在停損以下，不模擬進場」（`gap_below_invalid`）、到期或未成交「視窗內未模擬成交」、已取消「已取消」、同日觸及「同一交易日停損與目標一都觸及，先後順序不明」、`insufficient_sessions`「40 個交易日內該股不足 20 根日線」、停牌「期間有停牌或不可比較的日線」，其他「原因待核實」。不出現勝率、達標率或任何彙總比率。
- **取消**：進行中的卡有 ghost 按鈕「取消追蹤」，按下後改為「確定取消」「保留」與「取消後不再更新，計畫與明細會保留。」；拒絕時「計畫已結束，無法取消」「計畫狀態剛更新，請重新整理後再試」「找不到這個計畫，請重新整理頁面」，其他「取消失敗，請稍後再試」。
- **逐日明細**：每張卡底部收合「版本、來源與逐日明細」：一行 `來源 {今日候選／個股研究條件} · 策略版本 {id} · 公式 {formula_version} · 評分 {score_version，個股來源不寫} · 追蹤規則 {tracking_version}`；展開時才讀明細，表格欄「日期、第幾日、狀態、開、高、低、收、觸發」，表上註「價格為當日原始日線（報價幣別元），觸發依計畫價位換算到當日價格基準判定；成交為模擬。」。第幾日寫「第 {n} 日」；狀態 `not_triggered` 未觸發、`active` 已模擬成交、`target_1_hit` 達標、`invalidated` 失效、`ambiguous` 順序不明、`suspended` 停牌、`not_entered` 未進場；觸發列「進場」「目標」「失效」，沒有寫「—」。還沒有交易日寫「尚無追蹤的交易日。」。

## 13. 策略說明

`/strategy`（主導航最後一項，#493）是靜態頁，寫給第一次看「今日名單」的人；頁面在 `frontend/src/strategy/StrategyPage.tsx`，策略名稱（`STRATEGY_NAME`）在 `strategyName.ts` 只定義一次，門檻與權重的數字在 `trendChips.ts`，公式以 [breakout／pullback](spec/breakout_pullback.md)、[candidate_score](spec/candidate_score.md) 與[追蹤](spec/tracking.md)為準，規格或後端設定（`backend/app/strategies/base.py` 的 `COMMON_CONFIRMATIONS`、`breakout_v1.py`、`pullback_v1.py`、`backend/app/domain.py` 的 `CANDIDATE_SCORE_V6`）改了，這頁要同批改。

頁面以策略為單位（#577）：頁首之後，每個策略是一個 `<section data-strategy>`，標題是策略名稱的詞彙按鈕；其後的「怎麼照著做」「我的追蹤在做什麼」「不做的事」是所有策略共通的。現在只有「順勢籌碼型」一個區塊，不放切換，也不放空的「其他策略」或「即將推出」；日後新增策略就是並列另一個區塊。

- **頁首**：眉標「目前策略：順勢籌碼型」、標題「策略說明」，說明句「「今日名單」不是推薦，而是固定規則篩出來、條件已經成立的研究名單；照著做之前，先看懂它怎麼選、什麼時候算失效。」
- **策略區塊「順勢籌碼型」**：標題是詞彙按鈕（`trend_chips`，[§7](#7-詞彙原則)），下面依序：
  - **第一段**：「目前「今日名單」用的是順勢籌碼型：只做多頭趨勢的股票，除了價量條件成立，還要所屬族群比大盤強、三大法人沒有明顯賣超、融資沒有過熱；大盤好壞目前不影響判斷。它由兩條規則——突破型（`breakout_v3`）與回踩型（`pullback_v4`）——和一個評分——候選總分（`candidate_score_v7`）組成。」候選總分是詞彙按鈕。
  - **今日名單怎麼來**（h3）：三張卡「1. 收盤後掃描全市場」「2. 條件全部成立才入選」「3. 依評分排序」（評分只決定先後，不代表勝率或預期報酬；最多 20 檔；ETF 不列入；資料不足不列入、不以 0 補；第 2 步寫明 20 日平均成交量至少 1,000 張，成交量太少或均量資料不足的股票不列入，[candidate_score_v7](spec/candidate_score.md#candidate_score_v7)；第 3 步指向下方的權重表）。
  - **兩條成立規則：突破型與回踩型**（h3）：每型一張卡，標題是詞彙按鈕（`breakout`／`pullback`），內容「成立條件」「適合」「主要風險」：突破型「收盤站上前 20 個交易日的最高價，而且當天成交量至少是前 20 日均量的 1.2 倍」／「追強勢」／「假突破」；回踩型「中期趨勢向上（20 日均線在 60 日均線之上，收盤在 60 日均線以上），股價拉回到 20 日均線附近（約 −3%～+2%），而且量縮（前 20 日均量的 0.6～1.2 倍）」／「等拉回」／「趨勢轉弱」。
  - **三個確認條件：兩條規則都要通過**（h3）：一句「突破型與回踩型都要同時通過下面三個條件；任何一項資料不足就不列入，不會拿 0 補。」接一張表（欄「確認條件」「門檻」「白話」）：族群「所屬族群近 20 日報酬高於加權指數」／「族群比大盤強，個股才有順風。」；法人「三大法人 5 日淨買賣超 ≥ 20 日均量的 −0.3%（5 日合計賣超不超過一天均量的 0.3%）」／「法人沒有明顯賣超；買超或小額賣超都算通過。」；融資「融資餘額 5 日增幅 ≤ 5%（非融資標的不適用這一條）」／「融資增加太快，代表追價過熱。」
  - **依評分排序：四個分項與權重**（h3）：一句「入選的股票依下面四個分項的加權總分（0–100）由高到低排；總分只決定先後。」接一張表（欄「分項」「權重」「看什麼」）：技術 35%（量比與價位距離各占一半：突破型看距前 20 日高點、回踩型看距 20 日均線；在同一天、同一型的入選股之間比較）、籌碼 30%（三大法人 5 日淨買超占 40%、20 日淨買超占 30%，都除以 20 日均量；融資 5 日變動占 30%，減少較好；和當日全市場的股票比較）、族群 20%（所屬產業、題材族群在各自榜上的名次，兩種都有時取較高的）、新聞情緒（推論）15%（近 3 日關聯新聞的淨方向，由 AI 判讀）。表下小字：沒有資料的分項不以 0 計，改用有資料的分項重新加權；技術分項必須有資料，有資料的分項權重合計要達 65%，否則不列入；並連到「候選總分」「百分位」詞條與個股頁「進出場」分頁。數字與 [candidate_score_v7](spec/candidate_score.md#candidate_score_v7) 的權重（技術 0.35、籌碼 0.30、族群 0.20、新聞情緒 0.15）、子項權重與最低涵蓋 0.65 一致。
- **怎麼照著做**：T+1 才進場、進場區（突破型一個價位、回踩型一段區間；開盤就跳過目標或跌破停損時不進場）、停損（跌破就出場）、目標（目標一主要出場、目標二延伸參考）、RR（目標一減進場價，除以進場價減停損；回踩型的進場價取進場區中點；至少 1.5 倍，[#580](https://github.com/YiCheng0608/stock-lab/issues/580)），各以詞彙按鈕開詞條。
- **我的追蹤在做什麼**：「加入追蹤」後從下一個交易日起每天收盤後依日線模擬進場與出場（最多 20 個交易日），結果在我的追蹤的「追蹤計畫」「追蹤回看」；已扣固定手續費與滑價假設，不是實際成交，也不寫進庫存。另一句寫我的追蹤也提醒庫存風險與差一點成立的股票。
- **不做的事**：不自動下單、不提供盤中即時價格；不顯示勝率或成立機率；AI 只寫說明文字並標「AI 推論」，價位以規則數值為準。最後一行連到「策略版本」與「用語表」。

## 14. 資料覆蓋度頁

`/research/coverage`（官方資料回補與覆蓋度）的「最近一次回補」卡讀最新一筆回補 run 的 metadata；「目前市場資料覆蓋度」讀 `/api/coverage`。

- **已驗證交易日**：寫「{已驗證}／{目標} 日」，有確定休市日時接「（已扣除 {N} 個確定休市日）」，例如「62／62 日（已扣除 5 個確定休市日）」（[#479](https://github.com/YiCheng0608/stock-lab/issues/479)）。
  - 目標取 run 的 `target_sessions`，N 是 `confirmed_non_trading_dates` 的筆數。規則見[回補目標與確定休市日](DATA_SOURCES.md#回補目標與確定休市日)。
  - 規則改版前的 run 沒有 `target_sessions`，目標寫 `coverage_targets.ohlcv_taiex_sessions`（上限 65），不加後綴。
- **覆蓋目標**與「回補目標：」那一行：`target_met` 為真寫「已達成」，否則寫「尚未達成」；`/api/coverage` 的 `target_met` 是 null 時寫「尚無回補稽核基準」。頁面在 `frontend/src/App.tsx` 的 `BackfillCoveragePage`；「已驗證交易日」的字串由 `frontend/src/coverage/CoverageSummary.tsx` 的 `backfillSessionsLabel` 組出。

## 15. 導覽列搜尋

導覽列右側的搜尋框（[#599](https://github.com/YiCheng0608/stock-lab/issues/599)；樣式見 [DESIGN_SYSTEM §5](DESIGN_SYSTEM.md#5-元件)「導覽列搜尋建議」）：

- 輸入框 placeholder「代號或名稱」，無障礙名稱「搜尋個股代號或名稱」。
- 輸入後約 250 ms 列出最多 8 檔符合的股票，每檔一列「代號 名稱 上市／上櫃」（市場依交易所，未知寫「市場待核實」）；清單的無障礙名稱「符合的股票」。來源是 `GET /api/instruments?q=&securities_only=true&page_size=8`：只列正常交易的證券與 ETF（不含指數、期貨、下市），代號完全相符排第一，其次代號開頭、名稱相符、名稱開頭，其餘依交易所與代號。查詢中不顯示清單。
- 點選一檔或用上下鍵選取後按 Enter，進該股個股頁 `/stocks/:exchange/:symbol`；Esc 關閉清單、保留輸入；沒有選取時按 Enter 照舊到個股清單 `/stocks?q=`。逐鍵只查這支建議 API，`/api/stocks` 只在送出時查。
- 沒有符合時一行「沒有符合「{輸入}」的股票，按 Enter 到個股清單搜尋。」；請求失敗時一行「建議暫時無法載入，按 Enter 到個股清單搜尋。」，Enter 照常可用。
- 有清單時螢幕閱讀器念「{N} 檔符合，按上下鍵選取。」；沒有符合與失敗念上面那一行。注音等輸入法組字中不查詢，組完才查。
- 手機（860px 以下）搜尋框在漢堡選單內，清單與輸入框同寬，選單可捲動到最後一檔。
