# UI 文案與資訊層級規格

更新：2026-09-11。本文是現行呈現契約，不代表所有案例已驗收。原文件整理輪只修改文件；其後 C-001 已加入信心語意的最小相容呈現，新增 AI、題材與短線資金呈現仍待實作。能力狀態見 [ROADMAP](ROADMAP.md)，行動聚合見 [PRODUCT_SPEC](PRODUCT_SPEC.md#action-merge)。

## 1. 共通原則

- 日常研究畫面只顯示使用者可理解、可追溯的繁體中文。內部 enum、欄位名、資料庫 key、原始 JSON、raw payload id 和 event id 不得出現在卡片正面。
- 每個「完整」都必須說明完整的是哪一種資料與用途；禁止只有「完整／資料不足」兩種模糊 badge。
- 來源、事件、數字與關聯必須能分辨「官方直接提供」、「經核實規則關聯」和「尚未核實」。未知不是負面訊號，也不能用紅／綠暗示。
- 所有時間以 Asia/Taipei 顯示：日期為 YYYY/MM/DD，含時間為 YYYY/MM/DD HH:mm。不得把 ISO 字串直接露出。
- 「現價」只適用於即時報價。現行日資料頁一律使用「最近收盤（YYYY/MM/DD）」；當當日行情未完整時不顯示任何價格結論。

## 3. 三種資料完整度

同一個個股頁可以同時出現「來源擷取完整」與「策略判斷資料待補」，兩者不矛盾。卡片和個股頁必須用下表的完整句子，並可展開缺少欄位。

| 資料層 | 完整 | 部分／缺失 | 使用者含義 |
| --- | --- | --- | --- |
| 來源擷取 | 來源擷取完整 | 來源擷取部分完成／來源擷取失敗 | 官方來源與 raw 稽核是否已完成；不代表每個欄位可用。 |
| 當日行情 | 當日行情完整 | 當日行情部分缺漏／尚無可驗證當日行情 | 該標的、交易所和日期的 OHLCV 是否可驗證；不代表歷史、籌碼或族群完整。 |
| 策略判斷 | 策略判斷資料完整 | 策略判斷資料待補／目前無法產生研究判斷 | 20／60 日行情、TAIEX、族群、法人與融資等**某一研究條件**的輸入是否足夠。 |

標準呈現順序：

    來源擷取完整 · 當日行情完整 · 策略判斷資料待補
    缺少：近 20 日行情、近 5 日法人籌碼

不得把來源擷取狀態直接命名為「資料品質完整」，也不得因 P0 已有 65 個 TAIEX session 或全市場資料列數增加，就顯示某一標的「策略判斷資料完整」。

同一標的同時有兩個研究條件時，策略完整度 badge 必須標出適用範圍。例如：

    主研究條件資料完整 · 另一研究條件資料待補：近 5 日法人籌碼

不可只寫模糊的「策略判斷資料完整」或把整張卡稱為資料待補。只有所有正在呈現的研究條件都完整時，才可不加範圍使用前者；只有沒有完整研究條件、完整 observation 或等待條件時，後者才能成為卡片主標籤。

來源擷取 badge 必須說明資料域。P0 的正確呈現範例是：

    行情與籌碼來源擷取完整 · 當日行情完整 · 策略判斷資料完整
    事件脈絡：官方事件資料尚無法按交易日核實，未納入族群技術與籌碼觀察

上例只有在該標的正在呈現的 v1 研究條件之必要行情、TAIEX、membership、chips 與價位輸入完整時可用；若同卡列出另一條待補條件，必須改用前述有範圍的文字。P0 的 global partial 不得自動把它降格；反之，個別近 20／60 日、chips 或公司行動缺口也不得因全市場 P0 target_met 而升格。

## 4. 新聞卡文案與折疊

### 4.1 卡片正面

固定順序為：

    個股公告 · MOPS 官方公告資料
    [來源原始標題，最多兩行]
    [摘要預覽，最多 120 個全形字元或三行]
    發布於 2026/09/07 09:00／事件日 2026/09/07／來源時間未提供（三擇一）
    影響尚未判定 · 標的關聯已驗證
    相關標的：2330
    查看官方公告資料集

- title 保留來源原意，僅正規化連續空白與換行；長於兩行時以省略號截斷，點擊「查看詳情」後顯示完整標題。
- `/news` 只顯示摘要預覽，不在列表展開原始公告。`/news/:id` 預設收合全文，按鈕為「展開公告內容」與「收合公告內容」；展開後只顯示來源提供的 description，不顯示 details_json、raw payload、event id 或內部 provenance id。
- 現行來源內容缺失時顯示「官方來源未提供摘要」，不可憑 title／事件類型補造。下一版若有可合法使用的原文，可顯示獨立、有引用且標明方法的「AI 摘要」；原文不足仍不生成，依 NEWS_SPEC 的驗證／覆核規則。
- 來源／時間／影響資訊採小字，不可用 company、high 或 ISO 時間原字串。

### 4.2 日期與可信度

| 資料可用性 | 顯示文案 |
| --- | --- |
| published_at 有值 | 發布於 YYYY/MM/DD HH:mm |
| 只有 event_at | 事件於 YYYY/MM/DD HH:mm |
| 只有 event_date | 事件日 YYYY/MM/DD |
| published_at、event_at 與 event_date 都無 | 來源時間未提供 |
| collected_at 有值 | 僅在新聞詳情的「資料來源與稽核」顯示「系統收錄時間 YYYY/MM/DD HH:mm」 |
| time_consistency=conflict | 資料集事件日期與公告內容提及日期不一致，時間待人工核實 |
| 直接 Event—Instrument 關聯 | 標的關聯已驗證 |
| 已核實規則關聯 | 關聯由規則核實 |
| 沒有可稽核關聯 | 關聯尚未判定 |

confidence 是來源／關聯的可追溯程度，不是事件真實性評分、更不是價格方向把握；不使用「高／中／低信心」裸字。

列表依已核實來源時間排序。現行契約仍有未知時間的 collected_at fallback；下一版需將這類項目分到時間待核實區，避免新收錄被誤認新事件。來源衝突不進預設最新串流；已核實的歷史日期不因今天收錄而改變。完整排序與 cursor 規則見 [新聞時間與排序契約](NEWS_SPEC.md)。

### 4.3 來源連結

- source_url_kind=item：按鈕「查看原始公告」。
- source_url_kind=feed：按鈕「查看官方公告資料集」，旁邊固定說明「此連結開啟官方清單，未必直接定位本則公告。」。
- source_url_kind=none：顯示「來源連結未提供」，不顯示無效按鈕。
- raw payload、hash 與 event id 只在「資料來源與稽核」展開層或系統頁顯示。

### 4.4 族群關聯

事件卡只能顯示以下兩種族群關聯：

1. 來源文字明確指向該族群，且人工／規則審核為 verified。
2. 經核實的 Event—Instrument—Theme 規則關聯，且 Theme 中文名稱與 name_status 皆為 verified。

僅由現有 group membership 自動推得的關聯為 unverified，日常新聞卡、首頁與個股頁一律不顯示。這包括 Industry · Shipping、Industry · 32、Industry · 38 等原始或未核實標籤。可在系統頁保留關聯方法與原始 ID，供維運核對。

## 5. 行動中心的預設資訊層級

預設畫面依下列四層，不以大量資料待補卡填滿第一屏：

| 順序 | 區塊 | 顯示對象與文案 |
| --- | --- | --- |
| 1 | 持倉風險 | 只顯示持倉的減碼／退場條件、持倉資料待補與使用者停損；標題為「持倉風險與觀察」。 |
| 2 | 可研究條件 | 顯示條件進場、以及有策略 contract 合法等待價位的等待突破／等待回踩和持有觀察，且策略判斷資料完整。標題為「可研究條件」。 |
| 3 | 自選／事件關注 | 顯示使用者自選或有已核實事件關聯、但尚無進場條件的標的；完整 observation 沒有合法等待價位時可在此／個股詳情顯示「暫無研究條件，持續觀察」，不屬於資料待補。 |
| 4 | 資料待補 | 預設收合為「X 檔暫無法評估」，最多顯示三種常見缺項與「查看待補資料」按鈕。 |

排序規則：持倉的已驗證風險條件優先；其次是資料完整的可研究條件；再來是自選／事件關注；非持倉且 data_insufficient 的項目不能出現在預設卡片列表。

資料待補的精簡卡：

    目前無法產生研究動作
    策略判斷資料待補：近 20 日行情、近 5 日法人籌碼
    資料截至 2026/09/08
    優先補齊：近 20 日行情

- 當當日行情不完整時：顯示「價格資料尚未完整，暫不顯示最近收盤」。
- 當行情完整但策略輸入不足時：可以顯示「最近收盤（YYYY/MM/DD）」；不可稱「現價」。
- 沒有有效 entry、invalid、target 時：顯示「研究價位暫無法計算」；不顯示破折號、0、目標價或 RR。
- 沒有有效 RR 時：顯示「風險報酬比暫無法計算」。
- 絕不把資料待補卡語言寫成看多、看空、買入、賣出或停損指令。

完整 observation 因條件尚未成立而沒有價位時，不使用本區的「資料待補」文案；改寫為「目前沒有符合的研究條件，持續觀察」，並保留可展開的條件未通過理由。只有策略 contract 明確給出合法等待價位時，才顯示等待突破／回踩。

## 6. 行動狀態與卡片文字

| action_state | 標籤 | 次文案 |
| --- | --- | --- |
| conditional_entry | 符合條件後可研究進場 | 僅在觸發價與資料條件成立後，最早 T+1 再檢查。 |
| wait_breakout | 等待突破條件 | 僅在策略明確提供合法突破觀察門檻時顯示；突破前不產生進場結論。 |
| wait_pullback | 等待回踩條件 | 僅在策略明確提供合法回踩觀察區間時顯示；回到區間後仍要重新檢查量能與籌碼。 |
| hold_observe | 持倉觀察 | 持續留意使用者停損、策略失效與資料更新。 |
| reduce_exit | 持倉風險：減碼／退場條件 | 符合既定風險條件時重新研究處置；不是自動下單。 |
| data_insufficient | 策略判斷資料待補 | 目前無法產生研究動作。 |
| no_condition | 暫無研究條件 | 資料足夠、條件尚未成立，且沒有策略 contract 允許的等待價位；顯示「持續觀察」與未通過理由。 |
| manual_review | 需人工判讀 | 資料截止、策略條件或價位有衝突。 |

主頁和行動卡不用顯示「主條件：突破 v1／替代：回踩 v1」的技術列。可改成「研究條件：突破」與「替代條件：回踩」，並提供「查看規則依據」連到研究詳細。

### 6.1 兩個研究條件的合併呈現

下表是日常 UI 的呈現契約；判定可留在 API／稽核層，但畫面不得露出內部狀態字串。詳盡的策略規則見 [產品行動合併契約](PRODUCT_SPEC.md#action-merge)。

| 畫面可用的證據組合 | 主標籤與內容 | 次要呈現 | 禁止文案／行為 |
| --- | --- | --- | --- |
| 一組完整研究條件＋另一組完整 observation | 「符合條件後可研究進場」；只顯示主條件自己的觸發、失效、目標、RR 與「最早 T+1」。 | 有合法等待價位才寫「替代條件：等待突破／等待回踩」；否則寫「替代策略：本次條件未成立」並保留原因。 | 不得寫成「策略判斷資料待補」或要求替代 observation 補出目標價／等待價位。 |
| 一組完整研究條件＋另一組資料待補 | 同上；可加 badge「主研究條件資料完整」。 | 可展開「另一研究條件資料待補：<精確缺項>」。 | 不得隱藏主條件價位、用 0 補值，或讓整張卡改成資料待補。 |
| 兩組完整研究條件 | 「符合條件後可研究進場」；主條件依固定排序顯示。 | 「替代條件」完整列出另一組自己的價位與 T+1，並顯示「兩組價位請分開閱讀」。 | 不得把兩組價位、失效點、目標或 RR 混成一組；資料／調整／執行證據互相衝突時改用「需人工判讀」。 |
| 至少一組完整 observation 有合法等待價位 | 「等待突破條件」或「等待回踩條件」；只可顯示策略明確給出的觀察門檻／區間。 | 另一組若也有合法等待價位則為替代等待條件；若待補則顯示精確缺項。等待價位不等同 entry，不須偽造失效、目標或 RR。 | 不得以高點、MA 或最近收盤臆造等待價位，或把替代待補變成整張卡的 blocker。 |
| 一組完整 observation 沒有合法等待價位＋另一組資料待補 | 「暫無研究條件」與「持續觀察」；摘要不顯示資料待補 badge。 | 保留完整 observation 的未通過理由；另一策略可展開「資料待補：<精確缺項>」。 | 不得把替代待補污染整張卡，或為 observation 補 0、破折號、entry、目標或 RR。 |
| 兩組完整 observation，皆無合法等待價位 | 「暫無研究條件」與「持續觀察」。 | 可展開兩組各自的未通過理由；沒有價位就不顯示價位區塊。 | 不得將「條件未成立」寫成「策略判斷資料待補」。 |
| 已驗證持倉風險＋任一研究條件 | 「持倉風險：減碼／退場條件」優先，分別標示使用者停損與策略失效價。 | 把其他條件置於「其他研究條件」，固定提示「持倉風險優先處理；此處不是新增／加碼指令」。 | 不得以進場條件壓過已驗證風險或自動下單。風險資料待補時只能顯示「持倉風險資料待補」。 |

「策略判斷資料待補」只有在相關策略有真正缺少 canonical 輸入、且沒有可用完整 conditional 或 complete observation 的摘要結果時才可作為卡片主標籤。完整 observation 但沒有等待價位時，主標籤是「暫無研究條件」且 summary blocker 為空；另一策略待補只能是 per-strategy disclosure。完整熱門族群、候選名單與事件脈絡是背景：一個已完整的個股研究條件即使不在完整熱門名單，也應進入「可研究條件」；卡片只可如實補充「族群脈絡」與「事件脈絡資料待補」，不得改稱熱門推薦。

## 8. 程式驗收條件

1. 瀏覽日常五個 route 時，不會看到 DecisionSummary、data_insufficient、canonical、prior_20_highs、company、high 或 ISO 時間。
2. 同一個個股／行動卡可同時正確呈現三種完整度，不再出現「資料品質完整」卻又只寫「資料不足」的語意衝突。
3. 新聞預設不展開完整原始公告；來源連結明示 item／feed 差異；未知影響和未核實族群都不帶方向標籤。
4. Industry · Shipping／32／38 等未核實關聯不會出現在新聞、首頁或個股事件標籤。
5. 行動中心首屏沒有大量非持倉的資料待補卡；資料待補區預設收合並不顯示不可計算價位。
6. 個股籌碼與完整度的新詞彙都可用鍵盤開啟 modal，內容與本文一致。
7. 2330 的兩條完整 observation、沒有合法等待價位時，顯示「暫無研究條件，持續觀察」，不顯示資料待補 badge、entry、target、RR 或虛構價位；兩條未通過理由仍可展開。
8. 新聞列表沒有「蒐集於」、ISO 時間或完整原始公告；標題連到詳情，收錄時間與 provenance 只在詳情收合層。
9. 首頁同一 exchange／symbol／as_of 只有一張壓縮卡；它只含一個結論、一個主要原因和一組最重要價位。
10. 250、1,000、1,250 股分別顯示「250 股（零股）」「1 張」「1 張 250 股」；成本仍標為每股，股票與 ETF 規則一致。

## 9. v1 族群空狀態與發布規則

- 五分項完整才稱 v1 完整熱門；四分項觀察遵守 V1_SPEC 的 coverage 條件，標示「技術與籌碼觀察（事件資料待補）」，不能直接轉成完整熱門候選。
- 不能把歷史 P0 的零完整熱門當成所有未來資料日的固定文案。每次依實際資料判斷；歷史數據見 DATA_SOURCES。
- 個股完整主條件不因另一策略缺漏或事件脈絡待補而整張降級；unknown 不暗示方向。
- 下一版新增題材／事件機會榜需標示方法版本，不能改名後繞過 v1 資料限制。
- 尚未接入來源顯示未接入，不補新聞、事件數或推論。

## 10. 壓縮卡、詳情與單位文案

### 10.1 今日／個股清單壓縮卡

固定順序：

    2330 台積電
    最近收盤（2026/09/08）NT$X · 漲跌 X%／漲跌幅待核實
    符合條件後可研究進場
    收盤已站上前 20 個交易日高點
    關鍵價位：觸發 NT$X／失效 NT$Y
    資料截至 2026/09/08 · 查看個股

無條件、待補或人工判讀時不顯示最後一行關鍵價位，改用「研究價位暫無法計算」或不放價位區。日線資料不可寫「現價」；漲跌幅缺少相鄰、同調整基礎的可信前一收盤時，固定寫「漲跌幅待核實」，不用 `0.00%`。

### 10.2 個股詳情的第一屏

固定標題順序：

    今日研究結論
    現在怎麼做
    關鍵價位
    為何如此
    資料時間與完整度

其後才是可收合的「技術條件」「個股籌碼」「公告與事件」「替代研究條件」「資料來源與稽核」。固定附註：「此為研究工具與資料摘要，不構成投資建議、報酬保證或自動下單指令。」完整八種 action state 的主文案以 [本文行動狀態](#6-行動狀態與卡片文字) 為準。

### 10.3 張／零股

預設切換文案為「單位：張」與「單位：股」。顯示規則：

    250 shares  →  250 股（零股）
    1,000 shares  →  1 張
    1,250 shares  →  1 張 250 股
    成本  →  平均成本 NT$X／股

張是呈現單位；股票與 ETF 的 canonical quantity 都是精確整數股。TAIEX 等指數顯示點數，不使用張／零股元件。

C-001 已讓行動卡技術資訊讀取 API 的 `confidence_semantics.display_label_zh`，缺少 semantics 時也使用非機率 fallback；一般卡片不顯示 75%。程式 task 回報新增信心 assertions 與 `pnpm build` 通過；統籌另以相同編譯方式比較原備份和目前 `presentation.test.ts`，兩者都在既存「回踩研究條件」／「回踩條件」文案 assertion exit 1，且新增三個信心 assertions 在此前均已通過。因此信心呈現的 targeted 證據可接受，但不能宣稱前端整套測試通過。

增加「不交易」「計畫到期」「未觸發」「未成交」「模擬追蹤」等狀態時須清楚區分，不能都算成失敗交易。風險預算未知時寫「尚未設定風險預算，暫不提供部位數量」，不自填張數。
