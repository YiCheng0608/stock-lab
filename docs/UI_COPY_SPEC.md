# UI 文案與資訊層級規格

本文是日常頁的中文、資訊層級、單位、unknown 與 reason code 契約。能力狀態見 [ROADMAP](ROADMAP.md)，策略合併判定見 [PRODUCT_SPEC](PRODUCT_SPEC.md#action-merge)。

## 1. 共通原則

- 日常頁使用可理解、可追溯的繁體中文；enum、欄位名、資料庫 key、raw ID 與 ISO 時間只可在預設收合的研究／系統層。
- 每個「完整」都須說明資料層與用途。官方事實、規則關聯、推論與 unknown 分開；unknown 不是負面訊號。
- Asia/Taipei 日期顯示 `YYYY/MM/DD`，日期時間顯示 `YYYY/MM/DD HH:mm`。
- 「現價」只用於可信即時報價；日資料一律寫「最近收盤（日期）」。缺少可驗證行情時不顯示價格結論。
- 台股紅漲綠跌須同時有正負號或文字，不能只靠顏色。
- 數值表格、缺值與合法 0 的顯示依 [§8.4](#84-數值表格單位與空白)。

## 2. 禁止露出的內部詞與繁中對照

| 內部詞 | 日常頁 |
| --- | --- |
| DecisionSummary | 行動摘要 |
| data_insufficient／data_incomplete | 策略判斷資料待補 |
| canonical／canonical config snapshot | 固定研究規則／規則版本與稽核設定；只在研究詳情 |
| prior_20_highs／bars_20d／bars_60d／institutional_flow_5d | 前 20 個交易日高點／近 20 日行情／近 60 日行情／近 5 日法人籌碼 |
| company／taiwan／domestic／international | 個股公告／台灣官方事件／國內／國際；尚未接入的來源不顯示空卡 |
| foreign_investor | 外資（口徑見[資料來源](DATA_SOURCES.md#法人口徑)） |
| high／medium／low・unknown confidence | 「標的關聯已驗證」／「關聯由規則核實」（可展開方法與規則）／「關聯尚未判定」；不得解讀成勝率，low／unknown 不驅動進場、出場或其他交易動作 |
| impact_direction unknown | 影響尚未判定 |

## 3. 三種資料完整度

| 資料層 | 完整 | 部分／缺失 | 只代表 |
| --- | --- | --- | --- |
| 來源擷取 | 來源擷取完整 | 來源擷取部分完成／失敗 | 來源與 raw 稽核；不代表欄位或歷史窗口完整。 |
| 當日行情 | 當日行情完整 | 當日行情部分缺漏／尚無可驗證行情 | 指定標的、市場與日期的 OHLCV。 |
| 策略判斷 | `<策略>條件資料完整` | `<策略>條件資料待補` | 該策略所需行情、TAIEX、membership、籌碼等輸入。 |

同頁可同時顯示「來源擷取完整 · 當日行情完整 · 回踩條件資料待補」，並列精確缺項。全市場 run 成功或資料列增加不能升格個別標的；全域 partial 也不能自動降級一條已完整策略。

同卡有兩條策略時使用「主研究條件資料完整 · 另一研究條件資料待補：<缺項>」。只有所有呈現條件都完整時才可省略範圍。完整 observation 沒有 entry／target／RR 仍是完整，不使用資料待補 badge。

族群熱度：完整與四分項條件以 [V1_SPEC](V1_SPEC.md#hot_group_v1) 為準。UI 對合格 partial 顯示「技術與籌碼觀察（事件資料待補）」，不得稱完整熱門或產生完整熱門候選。

## 4. 新聞卡文案與折疊

- **分頁**：`/news` 以「國內」（`category=domestic`）、「國際」（`category=international`）、「官方公告」（`source_kind=official_disclosure`）三個分頁瀏覽，可再以關鍵字與股票代號篩選；個股頁「新聞與公告」顯示該股最近 50 則（交易所＋代號完全相符，官方公告為純代號相符）。
- **卡片正面**：固定順序為分類與來源 → 兩行內原始標題 → 120 個全形字元或三行內摘要 → 來源時間 → 影響／關聯 → 相關標的 → 來源連結。標題只正規化連續空白與換行，列表截在兩行，詳情保留完整標題。`/news` 不展開全文；`/news/:id` 用「展開公告內容／收合公告內容」，只顯示可用的來源 description，不顯示 raw JSON 或內部 ID。
- **摘要**：沒有摘要時寫「來源未提供摘要」。只有存在合法可用原文時，才可另顯示附引用與方法的「AI 摘要」；不得由標題或模型記憶補造。
- **影響與 AI 推論**：方向寫「可能正向」「可能負向」「正負互見」「影響尚未判定」，前置色點（正向 `--color-up`、負向 `--color-down`、互見 `--color-flat`）；unknown 與 `unsupported` 不加色點。卡片上的方向若來自 AI，後接「AI 推論」badge。`/news/:id` 的「AI 摘要與判讀」區與來源事實分開，列 AI 摘要、方向與範圍、理由、候選標的與候選題材（標「待核實」並寫「模型把握高／中／低」；代號查無標的寫「代號未對應到已知標的」且不連結），以及模型、提示版本與產生時間；沒有結果寫「此則尚未產生 AI 摘要與判讀」。
- **日期**：`published_at`／`event_at`／`event_date` 依序寫「發布於 日期時間」／「事件於 日期時間」／「事件日 日期」；三者皆無寫「來源時間未提供」，有值但 `product_time` 角色為 unknown 或 `time_consistency=conflict` 寫「來源時間待核實」，collected_at 只在詳情稽核層顯示「系統收錄時間」；`time_consistency=conflict` 寫「資料集事件日期與公告內容提及日期不一致，時間待人工核實」。排序依 [NEWS_SPEC §4](NEWS_SPEC.md#4-時間與排序)，依 collected_at 排序的項目不可顯示成發布時間。
- **來源連結**：`source_url_kind=item` 寫「查看原文／原始公告」；`feed` 寫「查看官方公告資料集」並提示「資料集連結未必定位到本則公告」；`none` 寫「來源連結未提供」，不畫無效按鈕。raw payload、hash 與 event ID 只在稽核層。
- **族群關聯**：只顯示來源直接指向且已驗證的族群，或已核實的 Event—Instrument—Theme 關聯；由現有 membership 自動推得、英文名稱／代碼、名稱狀態未核實的關聯只留系統層。關聯可信度文案見 §2。

## 5. 行動中心的預設資訊層級

1. **持倉風險與觀察**：已驗證減碼／退場條件、使用者 stop 或持倉風險資料待補。
2. **可研究條件**：完整 conditional、有合法 contract 價位的等待條件，以及持倉觀察。
3. **自選／事件關注**：自選、已核實事件，或完整 observation 的「暫無研究條件，持續觀察」。
4. **資料待補**：預設收合為「X 檔暫無法評估」，列最多三種常見缺項。

非持倉 data insufficient 不進預設卡片列表。行情完整但策略不足時可顯示「最近收盤」；當日行情不足時寫「價格資料尚未完整，暫不顯示最近收盤」。無合法 levels 或 RR 時隱藏相應區塊，必要時寫「研究價位／風險報酬比暫無法計算」，不用 0 或破折號。

## 6. 行動狀態與卡片文字

| `action_state` | 標籤 | 次文案／限制 |
| --- | --- | --- |
| conditional_entry | 符合條件後可研究進場 | 觸發與資料條件成立後，最早 T+1 再檢查；不是成交。 |
| wait_breakout | 等待突破條件 | contract 有合法門檻時才顯示；突破後仍需重查量能、族群與籌碼。 |
| wait_pullback | 等待回踩條件 | contract 有合法區間時才顯示；回到區間後仍需重查趨勢、量能與籌碼。 |
| hold_observe | 持倉觀察 | 只用於持倉，留意使用者 stop、策略失效與資料更新。 |
| reduce_exit | 持倉風險：減碼／退場條件 | 已碰到既定風險條件，重新研究處置；不是自動下單。 |
| data_insufficient | 策略判斷資料待補 | 目前無法產生研究動作；列精確缺項，不顯示方向。 |
| no_condition | 暫無研究條件 | 資料完整但條件未成立且沒有合法等待價位；顯示未通過理由。 |
| manual_review | 需人工判讀 | cutoff、basis、標的、價位或執行證據無法調和；不合成動作與價位。 |

日常頁說「突破／回踩研究條件」，完整版本名只在研究詳情。兩個研究條件的合併判定見 [PRODUCT_SPEC §6](PRODUCT_SPEC.md#action-merge)：UI 維持同標的一張卡與各策略自己的價位，持倉風險優先，其他條件置於「其他研究條件」。

## 7. 詞彙原則

詞條內容（term_id、名稱、別名、分類、白話說明、用途、解讀、限制、相關詞、版本）以 `backend/app/glossary.py`（`GET /api/glossary`）為準，`frontend/src/glossary.ts` 是 API 不可用時的本地副本；本節只寫原則。

- **中文對照**：日常頁用中文術語，英文、enum 與欄位名依 §2 對照，只在研究／系統層露出；別名用於搜尋。詞彙出現在 UI 不代表對應資料或模型已上線。
- **白話與限制並列**：每個詞同時寫用途與誤讀界線，例如突破、目標價、T+1 都不等於成交或必達；資料不足時明說無法用該指標下結論。
- **事實／推論分欄**：來源事實、規則判定與推論（AI 摘要、影響推論）分開命名；推論詞須標方法與引用，unknown 不是負面訊號。
- **口徑**：「外資」「三大法人」依[資料來源的法人口徑](DATA_SOURCES.md#法人口徑)；「熱門族群」只用於五分項完整的群組（[V1_SPEC](V1_SPEC.md#hot_group_v1)）。
- **不用的詞**：日資料不稱「現價」，固定 confidence 或模型自評不稱「勝率」或「校準機率」；不以「主力」「隔日沖」或分點名稱推定投資人身分；不寫「保證」「必漲」等報酬承諾。
- **呈現**：Modal 依白話定義、用途、解讀與限制排列，不以 term_id 或欄位名作標題。詞彙按鈕須支援滑鼠、觸控、Enter／Space，Esc 關閉後焦點回觸發點；定義不得只靠 hover 或顏色。

## 8. 壓縮卡、詳情與單位文案

### 8.1 今日／個股清單壓縮卡

順序為：代號／名稱 → 最近收盤與可信漲跌幅 → 一個行動結論 → 一個主要原因 → 一組關鍵價位（如合法）→ 資料日期與詳情入口。缺相鄰、同 basis 的可信前收盤時寫「漲跌幅待核實」；no condition、資料待補或人工判讀不顯示關鍵價位。行動摘要附 `market_read` 時，只有 `status=known`、`invalid_fields` 為空且最近收盤為正有限數值才顯示價格；否則價格與漲跌顯示「待核實」「漲跌待核實」，標題改為「策略判斷資料待補」。

### 8.2 個股詳情的第一屏

第一屏是頁首加「圖表與指標」。頁首依序為代號、名稱、市場（上市／上櫃）與類型、最近收盤（報價幣別元）、漲跌與漲跌幅（漲紅跌綠、正數帶 `+`）、資料日期 badge 與來源。頁尾固定附註：「此為研究工具與資料摘要，不構成投資建議、報酬保證或自動下單指令。」

個股詳情以「圖表與指標／法人籌碼／新聞與公告／研究條件／資料說明」分頁，預設為「圖表與指標」。頁首最近收盤取 bars API 日線最後一根有完整 K 線的列；直接前一列也是同來源的交易日才算漲跌，否則顯示「漲跌待核實」；沒有可信收盤時顯示「待核實」，不改稱零或負面訊號。研究截止日期不影響頁首收盤與 K 線。「研究條件」的族群列讀 API `groups`：`verified=true` 顯示 `display_name`（ETF 與新上市列沿用前端類別譯名），`verified=false` 顯示「族群關聯待核實」，驗證規則見 [INDUSTRY_CLASSIFICATION §5.1](INDUSTRY_CLASSIFICATION.md#51-既有錯配-membership-修復)。

「圖表與指標」的日／週 K 線、成交量、MA5／10／20／60／120（可勾選）與 MACD／RSI／KD／布林面板全部取自 `GET /api/stocks/{exchange}/{symbol}/bars`（`limit=250`；公式與欄位見 [V1_SPEC 技術指標](V1_SPEC.md#技術指標)），前端不自行計算均線或指標；停牌與無效列不畫 K 線，缺日不補。指標或均線欄位為 null 時依最新一根判斷：

| 情況 | 顯示 |
| --- | --- |
| 原因全是 `not_computed` 且整段沒有值 | 面板「指標尚未計算」 |
| 整段沒有值 | 面板「無資料」加原因 |
| 最新一根沒有值、前面有值 | 照畫，圖下註明該根無資料與原因 |
| 均線最新一根沒有值 | 圖下列出「MA120 無資料：日線不足 120 根，現有 80 根」 |

原因文案：`insufficient_bars` 為「日線不足 N 根，現有 M 根」（週線寫「週線」；N 取缺值欄位 `indicators.required_bars` 的最大值，M 為該根 `bar_count`，缺 `bar_count` 時只寫「日線不足 N 根」）；`suspended` 為「停牌，當日不計算」；`invalid_bar` 為「當日行情無效，不計算」；`no_price_change` 為「期間內收盤沒有漲跌，無法計算」；未知原因為「原因待核實」。籌碼沒有資料列時顯示「尚無可核實的籌碼資料。」。資料說明分頁列出 bars API `indicators` 的指標版本、價格基準、日線指標計算時間與 K 線資料日期。

### 8.3 張／零股

- DB／API／來源數量保存精確整數股與 unit；`LOT_SIZE=1000`。
- 日常主值為張：已知股數以精確字串拆末三位，保留至多 3 位小數的零股，不先轉 `Number`、不以除法捨入或補值。1／999／1,500 股分別為 `0.001`／`0.999`／`1.5` 張；int64 上限為 `9,223,372,036,854,775.807` 張；合法零顯示 `0`，方向保留。
- 原股數只放預設收合的來源／庫存稽核 details；表格單位依 §8.4 放表外。
- 價格與平均成本為元／股，不乘 1,000；API 未提供 currency 時寫「各標的報價幣別的元」，不猜 `NT$`。TAIEX 等指數用點數。
- 來源單位 unknown／mixed 不換算，表外說明「單位待核實」、數值格留空；來源已為張的融資不重複換算。可信 `quantity.unit="mixed"` 是同一已知股數的張／零股拆分，仍有效。
- Canonical 股字串只接受 ASCII `0` 或無前導零的非零整數；方向欄可有單一負號，不接受 `-0`、正號、分數、科學記號、空白或尾端換行。單日絕對值上限 `9223372036854775807`，買進／賣出與成交量須非負；5／20 日淨超的絕對值上限分別為 `46116860184273879035`／`184467440737095516140`。精確欄為 null、非法或壞字串時顯示待核實；response 完全沒有精確欄時才讀安全整數 number（`units.ts` 的 `exactVolumeText`）。
- **我的庫存**：表單預設 `unit=lot`，張數或股數輸入正整數 ASCII 字串；送出 `unit + quantity` 整數字串，例如 1 張送 `unit=lot, quantity="1"`、1 股送 `unit=odd_lot, quantity="1"`，讀回主值為 `1 張`／`0.001 張`。可保存總股數為 `1..9,223,372,036,854,775,807`，超限不送出，超大字串不經 Number。平均成本與停損為元／股；空字串送 `null`，非空須為非負 ASCII 十進位數。前端拒收或 API 回 422 時保留 draft 並顯示錯誤。

| 庫存讀值 | 日常文案 |
| --- | --- |
| 股數無法核實 | 「庫存數量待核實」；原股數稽核顯示「股數待核實」 |
| 可信股數超出安全整數 | 市值／損益顯示「估值精度待支援」 |
| 成本或停損 missing／invalid | 「未提供」／「待核實」 |
| 本地收盤可試算 | 日常卡顯示「行情待核實」；收盤 missing／invalid 為「未提供行情」／「行情數值待核實」 |

本地收盤與市值／損益試算只在預設收合的「核對庫存原股數、本地行情與試算」內顯示，並標「本地記錄；來源／日期待核實」與「本地試算，行情來源／日期尚未核實」。

### 8.4 數值表格、單位與空白

同一張表的單位只在表題、副標、caption 或緊鄰說明出現一次，例如「單位：張」；欄名與數值格不逐格重複「張」「股」「元」或百分號。價格與指數單位依 §8.3。數值格只顯示數字，方向值明示 `+`／`-`。缺值不寫 0、`N/A`、`--`、「無資料」或英文 placeholder，改為空白，並在表格外寫「空白表示來源未提供」；若原因是來源或單位未核實，須另行具體說明。

畫面呈現成交金額時，須依 API 的 `turnover_status` 決定數值格：`available` 且值為來源明確的 `0` 才顯示 `0`；`unavailable` 或 `unknown` 即使底層 `turnover=0` 也留空。`unavailable` 可在表格外說「成交金額未取得」，`unknown` 則說「成交金額待核實」，不把兩者合稱來源真的零；原因碼與數值狀態須一致。底層保存與計算規則見 [DATA_SOURCES](DATA_SOURCES.md)。tooltip、等效資料表與表外說明須同步使用相同口徑。

### 8.5 族群榜與族群詳情

- **榜別**：`board` 寫「產業」「題材」，其他值寫「其他」；族群頁與今日頁的分頁籤只有產業、題材兩個。
- **品質**：`quality` 依 [§3](#3-三種資料完整度) 寫「熱門族群」或「技術與籌碼觀察（事件資料待補）」；其他值寫「資料完整度待核實」。
- **數值**：分數 0–100 取兩位小數；五分項是同榜百分位，以 0–100 整數呈現；1／5／20 日相對報酬是相對加權指數的百分比，兩位小數、正數帶 `+`、漲紅跌綠；成員寫「有效／總數」。分項或報酬為 null 時顯示「—」（[DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)），並在表外寫「「—」表示該項無資料」，不寫 0。
- **日期**：右上角 badge 寫「資料 YYYY/MM/DD」（分數日 `trading_date`）；官方資料日 `data_as_of` 不同時另加「官方資料 YYYY/MM/DD」。
- **相關新聞時間**：族群詳情的相關新聞每列時間與新聞頁相同，只讀 `product_time`，文案見 [§4 日期](#4-新聞卡文案與折疊)。
- **空狀態**：空榜原文顯示 API 的 `empty_message`，前端不自組原因；走勢少於 2 個有分數的交易日寫「走勢資料不足（需至少 2 個交易日的分數）」；相關新聞為零寫「此族群尚無已核實關聯的新聞」；族群不在當日榜上時排名寫「—」並說明「此族群不在本日<榜別>榜（有效成員未達 3 檔或資料不足以計分），五分項沒有同榜百分位。」
- **題材成員證據**：`relation` 寫「主要業務」（core_business）、「產品線」（product_line）、「供應鏈」（supply_chain），`relevance` 寫「關聯度高／中／低」，未知值寫「關係待核實」「關聯度待核實」；http(s) 的 `url` 顯示「證據來源」並開新分頁，否則寫「來源連結未提供」；沒有證據寫「證據待核實」。題材詳情另列「題材表版本 <definition_version>」。

### 8.6 新聞題材建議

[新聞題材建議](V1_SPEC.md#新聞題材建議)是 LLM 推論，與族群榜分開呈現。

- **位置**：族群頁（`/themes`）排行之下另一區，眉標「新聞聚合 · 待核實」、標題「新聞題材建議」，右側「{N} 個建議 · 最近更新 YYYY/MM/DD HH:mm」（`meta.updated_at` 換算台北時間；沒有帶時區的時間不顯示）。區塊說明固定一句「由 AI 從近期新聞判讀出的題材名稱彙整，尚未經人工核實；不列入族群排行、不計分，也不作為交易理由。」
- **每個建議**：放在 AI 推論樣式的區塊（左側強調色豎線，[DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)），名稱旁並列「待核實」（warning badge）與「AI 推論」（accent badge）；下一行「{則數} 則新聞 · 首次 YYYY/MM/DD · 最近 YYYY/MM/DD · 模型未提供把握」，首末同日寫「新聞日 YYYY/MM/DD」；把握有值時寫「模型把握高／中／低」。不顯示排名、分數或 `theme_key` 等內部值。
- **關聯新聞**：預設收合「關聯新聞（{則數} 則）」，展開列最近 5 則：標題連到 `/news/:id`，下一行「{來源} · 新聞日 YYYY/MM/DD · 判讀題材「{模型寫法}」」，有理由再一行「理由：{理由}」。超過 5 則時給「顯示其餘 {N} 則」，載入中寫「載入其餘新聞中…」，失敗寫「其餘新聞暫時無法載入：{原因}」並保留按鈕。
- **版本**：每個建議底部「模型 {模型，多個以頓號分隔；沒有寫未記錄} · 提示版本 {prompt_version} · 彙整規則 {aggregation_version}」。
- **其他**：`meta.matched_total` > 0 時寫「另有 {N} 個建議與既有產業或題材同名，不另列出。」；列表被 `limit` 截斷時寫「依關聯新聞則數顯示前 {顯示數} 個，共 {total} 個。」
- **空狀態**：標題「目前沒有新聞題材建議」，原因「新聞 AI 判讀尚未提出與既有族群不同名的題材」。

## 9. 中文原因碼對照

reason code 的日常文案由 `backend/app/presentation.py`（`REASON_LABELS`、`display_reason`）與 `frontend/src/presentation.ts` 提供，下表只列原則與代表列。未知 code 一律顯示「研究條件需要人工核對」，原值只留稽核層；不同策略的 code 保留各自範圍。

| 原始值 | 日常文案／處置 |
| --- | --- |
| `passed`／`rejected`／`data_incomplete`／`observation`／`conditional` | 「此研究條件已符合」「尚未成立」「資料待補」「條件尚未成立，持續觀察」「符合條件後可研究進場」；observation 不是缺資料，conditional 須附 T+1。tracking 狀態（`active`、`target_1_hit` 等）只在追蹤／歷史顯示，不替代今日結論。 |
| `*_missing_or_non_finite`／`*_missing_or_invalid`（如 `prior_20_highs_missing_or_invalid`） | 「<資料項>資料待補」；不補 0，不把 unknown 當中性。 |
| `close_not_above_prior_20_day_high`／`volume_ratio_below_1_20` | 規則未通過，不是看空。 |
| `effective_group_score_missing_or_under_minimum_members` | 群組成員或相對大盤資料不足；不能顯示為 0 分。 |
| `etf_category_excluded_from_actionable_signals:<category>` | 債券／槓桿／反向 ETF 可收集與分榜，暫不產生一般 v1 動作。 |
| `invalid_levels` 與各價位關係碼（如 `invalid_price_must_be_below_entry`） | 「研究價位無法驗證」；隱藏不合法價位、目標與 RR。 |
| `target_1_risk_reward_below_minimum` | 第一目標 RR 未達門檻，不形成 conditional；不是績效結論。 |
| `unsupported_current_status`／`illegal_signal_status_transition` | 追蹤狀態無法驗證；日常顯示「需人工判讀」。 |

## 10. 每日候選

[`candidate_score_v1`](V1_SPEC.md#candidate_score_v1) 的理由由後端依規則產生（`worker.candidates.REASON_TEMPLATES`），API 的 `reasons[].text` 已是日常文案，前端直接顯示、不自組；`inference=true` 的理由與「推論」標籤同列。

| 理由碼 | 條件 | 文案 |
| --- | --- | --- |
| `breakout_20d_high` | breakout 策略 | 突破 20 日高點，量比 {量比，一位小數} |
| `pullback_ma20_support` | pullback 策略 | 回測 20 日均線，距均線 {距離，%，一位小數}，量比 {量比} |
| `foreign_trust_net_buy_5d` | 外資、投信 5 日皆淨買超 | 外資＋投信 5 日淨買超 |
| `institutional_net_buy_5d` | 三大法人 5 日合計淨買超（上條不成立時） | 三大法人 5 日淨買超，約 20 日均量的 {倍數，兩位小數} 倍 |
| `institutional_net_buy_20d` | 三大法人 20 日合計淨買超 | 三大法人 20 日淨買超 |
| `margin_decrease_5d` | 融資 5 日減少 | 融資 5 日減少 {%，一位小數} |
| `news_positive_3d` | 新聞分項原值 > 0（推論） | 近 3 日 {則數} 則偏多新聞（推論） |
| `hot_group_rank` | 有當日合格群組 | 所屬{產業／題材}「{名稱}」熱度第 {排名} |

- **位置**：今日頁「熱門族群」之後、「關注標的」之前，眉標「每日候選 · 依評分排序」、標題「明日候選」，右側資料日期 badge 與「{N} 檔」；「關注標的」區（行動摘要）的眉標為「使用者行動」，兩區不去重。個股頁在「研究條件」分頁頂端，`candidate` 非 null 才顯示，眉標「每日候選 · 第 {排名} 名」，評分細節預設展開。
- **每檔**：排名、代號名稱、上市／上櫃 · 策略（「突破條件」「回踩條件」）、總分；進場區（回踩為「低～高」）、停損、目標（有目標 2 時以「／」接續）、RR；四分項；理由；「族群：{名稱}（{產業／題材}，第 {排名} 名／{同榜數}）」，未排名寫「當日未排名」，沒有群組寫「無所屬產業或題材」。展開「評分細節、資料日期與來源」列子項原值、percentile 與權重、同檔另一策略、權重涵蓋、資料日期、規則最早執行日與來源。
- **子項名**：量比「量比（當日量／前 20 日均量）」、距離「距離（突破距 20 日高點、回踩距 20 日均線）」、RR「RR（只顯示，不計分）」、法人「三大法人 5／20 日淨買超（÷20 日均量）」、融資「融資 5 日變動」、新聞「近 3 日新聞淨方向（偏多＋1、偏空−1）」、族群「所屬族群榜內位置」。倍數兩位小數加「倍」，距離與融資為 %、一位小數。
- **分項名**：technical「技術」、chips「籌碼」、group「族群」、news_sentiment「新聞情緒」；新聞情緒另標「推論」。
- **分數**：總分與分項為 0–1，日常以 0–100 整數呈現；分項為 null 顯示「—」並附 API 的 `null_explanation`，不寫 0。`partial_components=true` 時在總分旁註明「部分分項無資料，以有資料的分項計分」。
- **聲明**：清單頂端固定一句「評分只用於排序，不代表勝率或預期報酬」。
- **AI 進出點說明**（`llm_note`，[V1_SPEC](V1_SPEC.md#候選-ai-進出點說明)）：每張候選卡在族群列之後、「評分細節」之前放 AI 推論樣式的區塊（左側強調色豎線，[DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)），標題「AI 進出點說明」，右側「AI 推論」（accent badge）。`status=done` 且三段都有字時依序列「為何入選」「進場區、停損與目標」「需留意的風險」與 API 文字；沒有說明（`llm_note` 為 null 或欄位不存在）寫「此檔尚未產生 AI 說明」，`pending` 寫「AI 說明這次未能產生」（不承諾自動重試，補跑見 [OPERATIONS §6.3](OPERATIONS.md#63-日誌與-run-記錄)）。區塊內固定一句「由 AI 依上方規則數值、理由與關聯新聞撰寫的推論，不是買賣建議；價位以規則數值為準。」；有 `llm_note` 時底部「模型 {model，沒有寫未記錄} · 提示版本 {prompt_version} · 產生於 YYYY/MM/DD HH:mm」（`generated_at` 換算台北時間，沒有時區時省略時間）；`pending` 不寫模型，時間改寫「嘗試於」。今日頁與個股頁相同。
- **零候選**：顯示 API 的 `zero_reason_text`；`no_actionable_signals`「當日沒有成立（條件成立）的策略訊號」、`all_excluded`「成立的訊號都因 ETF、價位不合法或評分資料不足被排除」。`status=not_computed` 寫「此交易日尚未產生候選清單」。空狀態標題分別為「當日零候選」與「尚無候選清單」，零候選保留資料日期 badge、not_computed 不顯示日期。
