# UI 文案與資訊層級規格

本文是日常頁的中文、資訊層級、單位、unknown 與 reason code 契約。能力狀態見 [CAPABILITIES](CAPABILITIES.md)，策略合併判定見 [PRODUCT_SPEC](PRODUCT_SPEC.md#action-merge)。

## 1. 共通原則

- 日常頁使用可理解、可追溯的繁體中文；enum、欄位名、資料庫 key、raw ID 與 ISO 時間只可在預設收合的研究／系統層。
- 每個「完整」都須說明資料層與用途。官方事實、規則關聯、推論與 unknown 分開；unknown 不是負面訊號。
- Asia/Taipei 日期顯示 `YYYY/MM/DD`，日期時間顯示 `YYYY/MM/DD HH:mm`（24 小時制，不寫上午／下午）。資料日期 badge、表格日期欄、計算與產生時間都適用，API 的 `YYYY-MM-DD` 不原樣顯示；來源原文裡的日期（如公告內容的民國日期）照原文。
- 「現價」只用於可信即時報價；日資料一律寫「最近收盤（日期）」。缺少可驗證行情時不顯示價格結論。
- 台股紅漲綠跌須同時有正負號或文字，不能只靠顏色。
- 數值表格、缺值與合法 0 的顯示依 [§8.4](#84-數值表格單位與空白)。
- 「待核實」「推論」「無資料」三種字樣依 [§1.1](#11-待核實推論與無資料)，不混用。

### 1.1 待核實、推論與無資料

畫面上每一個「待核實」都要有可說明的原因（[#465](https://github.com/YiCheng0608/stock-lab/issues/465)）。三種字樣依值的來歷選一種：

| 字樣 | 用在 | 例 |
| --- | --- | --- |
| 待核實 | 有值，但還沒通過、或沒有通過核對：時間衝突或沒有時區、前一列不是同來源的相鄰交易日、單位不明、本地手動記錄、前端不認得的代碼 | 「來源時間待核實」「漲跌待核實」「單位待核實」「狀態待核實」 |
| 推論 | LLM 產出。附模型與提示版本；能用規則核對的，另寫核對結果與規則版本，通過的寫「規則核實」 | 新聞 AI 候選的「規則核實：原文提及」／「推論」（[§4](#4-新聞卡文案與折疊)）、新聞題材建議（[§8.6](#86-新聞題材建議)） |
| 無資料 | 沒有值：來源沒給寫「未提供」，系統沒存寫「未記錄」，尚未產生寫「尚無…」；原因已知時直接寫原因；API 失敗寫「暫時無法載入」 | 「資料日期未提供」「決策時間：未記錄」「前一交易日無收盤」「資料日期暫時無法載入」 |

- 不用「待核實」代替「沒有值」或「載入失敗」；LLM 產出不寫「待核實」，寫「推論」。
- 規則核對只改顯示；規則核實的 AI 候選不寫進規則關聯（`symbols`），不改分數與篩選。

## 3. 三種資料完整度

| 資料層 | 完整 | 部分／缺失 | 只代表 |
| --- | --- | --- | --- |
| 來源擷取 | 來源擷取完整 | 來源擷取部分完成／失敗 | 來源與 raw 稽核；不代表欄位或歷史窗口完整。 |
| 當日行情 | 當日行情完整 | 當日行情部分缺漏／尚無可驗證行情 | 指定標的、市場與日期的 OHLCV。 |
| 策略判斷 | `<策略>條件資料完整` | `<策略>條件資料待補` | 該策略所需行情、TAIEX、membership、籌碼等輸入。 |

同頁可同時顯示「來源擷取完整 · 當日行情完整 · 回踩條件資料待補」，並列精確缺項。全市場 run 成功或資料列增加不能升格個別標的；全域 partial 也不能自動降級一條已完整策略。

同卡有兩條策略時使用「主研究條件資料完整 · 另一研究條件資料待補：<缺項>」。只有所有呈現條件都完整時才可省略範圍。完整 observation 沒有 entry／target／RR 仍是完整，不使用資料待補 badge。

族群熱度：完整與四分項條件以 [hot_group_v1](spec/hot_group.md) 為準。UI 對合格 partial 顯示「技術與籌碼觀察（事件資料待補）」，不得稱完整熱門或產生完整熱門候選。

## 4. 新聞卡文案與折疊

- **分頁**：`/news` 以「國內」（`category=domestic`）、「國際」（`category=international`）、「官方公告」（`source_kind=official_disclosure`）三個分頁瀏覽，可再以關鍵字與股票代號篩選；個股頁「新聞與公告」顯示該股最近 50 則（交易所＋代號完全相符，官方公告為純代號相符）。三個分頁共用一個搜尋列（關鍵字、股票代號、搜尋與清除按鈕），版面見 [DESIGN_SYSTEM §5](DESIGN_SYSTEM.md#5-元件)「搜尋列」。
- **卡片正面**：固定順序為分類與來源 → 兩行內原始標題 → 120 個全形字元或三行內摘要 → 來源時間 → 影響／關聯 → 相關標的 → AI 候選（預設收合，見下一條）→ 來源連結。標題只正規化連續空白與換行，列表截在兩行，詳情保留完整標題。`/news` 不展開全文；`/news/:id` 用「展開公告內容／收合公告內容」，只顯示可用的來源 description，不顯示 raw JSON 或內部 ID。相關標的只列已核實關聯；媒體新聞的關聯來自規則比對，標的前先寫「規則核實 · v<版本>」（版本取自 `impact.method`，[NEWS_SPEC §2](NEWS_SPEC.md#規則關聯)；未重算的舊新聞寫舊版本號），官方公告不加；沒有已核實關聯時寫「未有已核實的標的或族群」。`/news/:id` 技術資訊的「關聯方法」寫「規則比對（名稱／簡稱／代號） · 規則版本 v<版本>」。
- **AI 候選行**（[#452](https://github.com/YiCheng0608/stock-lab/issues/452)）：`/news` 與個股頁「新聞與公告」的卡片，在規則核實的相關標的那一行之後另起一行，用預設收合的 `<details>`，收合時寫「AI 候選 · N 檔（規則核實 M、推論 K）」，括號內只列非 0 的部分（文字已標推論，不另接「AI 推論」badge：卡片的「AI 推論」badge 只接在 AI 方向後，一則一個）；展開後每檔一項「代號 名稱 · 規則核實：原文提及 · 模型把握高／中／低」或「代號 名稱 · 推論 · 模型把握…」，依 API 的 `source_check`（`mentioned` 為規則核實，其餘與沒有這個欄位的都是推論，[NEWS_SPEC §5](NEWS_SPEC.md#5-ai-摘要與推論)），最後一行 muted 小字「模型 <model> · 提示版本 <prompt_version> · 核對規則 <candidate_check_version>。規則核實：名稱或代號出現在標題或摘要；推論：原文沒有寫出，由模型推得。候選不計入已核實關聯。」（沒有值寫「未記錄」）。#465 起不寫「待核實」（[§1.1](#11-待核實推論與無資料)）。名稱與連結同 `/news/:id` 的候選標的（代號查無標的寫「代號未對應到已知標的」且不連結）；卡片不列理由，理由在 `/news/:id`。來源是 `ai.symbol_candidates`（只用 `usableAi` 認可的 `done` 結果）；代號與規則核實的標的（`instruments`，或 `symbols` 的 `交易所:代號`／純代號）相同的那檔不列，同一代號重複時只列一次；只比代號、不比交易所，因為上市櫃代號不會重複，模型寫錯交易所的同一檔不在兩行各出現一次；剩下沒有候選時整行不顯示，不寫「無」。今日頁精簡列不顯示這一行。
- **今日頁重點新聞精簡列**：今日頁只列 `dashboard.news` 前 3 則，區塊標題「重點新聞」（眉標「市場基礎層 · 重大事件」），右側「查看全部新聞」。每則依序為分類與來源 → 兩行內原始標題 → 來源時間 → 影響／AI → 相關標的；不顯示摘要、AI 候選行與來源連結（在 `/news/:id`）。沒有新聞時寫「市場新聞區尚無可顯示內容。」。
- **摘要**：沒有摘要時寫「來源未提供摘要」。只有存在合法可用原文時，才可另顯示附引用與方法的「AI 摘要」；不得由標題或模型記憶補造。
- **影響與 AI 推論**：方向寫「可能正向」「可能負向」「正負互見」「影響尚未判定」，前置色點（正向 `--color-up`、負向 `--color-down`、互見 `--color-flat`）；unknown 與 `unsupported` 不加色點。卡片上的方向若來自 AI，後接「AI 推論」badge；新聞頁、個股頁與今日頁的卡片讀同一份 `ai`，有 AI 判讀時都顯示 AI 方向，不退回規則方向。`/news/:id` 來源事實欄的「影響」列只讀來源的 `impact_direction`（新聞收集一律存 unknown，[NEWS_SPEC §3](NEWS_SPEC.md#3-去重新資訊與事件影響)），unknown 寫「來源未標示影響」、不加色點，不寫「影響尚未判定」，以免讀成與右欄 AI 方向衝突。`/news/:id` 的「AI 摘要與判讀」區與來源事實分開，列 AI 摘要、方向與範圍、理由、候選標的與候選題材（候選標的每檔寫「規則核實：原文提及」或「推論」，再接「模型把握高／中／低」與理由；候選題材的標題旁標「已通過題材核對」（success badge），因為存下來的題材候選都通過了[題材核對](NEWS_SPEC.md#5-ai-摘要與推論)；兩者都不寫「待核實」；代號查無標的寫「代號未對應到已知標的」且不連結；交易所以 API 的 `exchange` 為準，模型寫錯時 API 已依主檔更正（[NEWS_SPEC §5](NEWS_SPEC.md#5-ai-摘要與推論)），名稱與連結用更正後的交易所，不另標示），以及模型、提示版本、產生時間（`generated_at` 換算台北時間 YYYY/MM/DD HH:mm，沒有時區寫「待核實」）與候選標的的核對規則（同卡片的說明句，後接「候選標的與題材都不作為交易理由。」）；沒有結果寫「此則尚未產生 AI 摘要與判讀」。
- **日期**：`published_at`／`event_at`／`event_date` 依序寫「發布於 日期時間」／「事件於 日期時間」／「事件日 日期」；三者皆無寫「來源時間未提供」，有值但 `product_time` 角色為 unknown 或 `time_consistency=conflict` 寫「來源時間待核實」，collected_at 只在詳情稽核層顯示「系統收錄時間」；`time_consistency=conflict` 寫「資料集事件日期與公告內容提及日期不一致，時間待人工核實」。排序依 [NEWS_SPEC §4](NEWS_SPEC.md#4-時間與排序)，依 collected_at 排序的項目不可顯示成發布時間。
- **來源連結**：`source_url_kind=item` 寫「查看原文／原始公告」；`feed` 寫「查看官方公告資料集」並提示「資料集連結未必定位到本則公告」；`none` 寫「來源連結未提供」，不畫無效按鈕。raw payload、hash 與 event ID 只在稽核層。
- **族群關聯**：只顯示來源直接指向且已驗證的族群，或已核實的 Event—Instrument—Theme 關聯；由現有 membership 自動推得、英文名稱／代碼、名稱狀態未核實的關聯只留系統層。關聯可信度文案見 §2。

## 5. 行動中心的分級與預設篩選

列表依 `action_tier_v1` 分六級，級內依下表排序（`backend/app/decision.py` 的 `ACTION_TIERS`，由測試釘住）。分級只決定列表順序與預設篩選，每列的狀態、價位與理由仍是該檔的行動摘要（[PRODUCT_SPEC §6](PRODUCT_SPEC.md#action-merge)）。

| 級 | 區塊標題 | 條件 | 級內排序 |
| --- | --- | --- | --- |
| 0 | 持倉風險 | 有持倉，或持倉數量待核實 | 行動摘要為減碼／退場 → 需人工判讀 → 資料待補 → 持倉觀察，再依代號 |
| 1 | 今日候選 | 資料日的每日候選（[§10](#10-每日候選)） | 名次 |
| 2 | 其他成立條件 | 資料日有資料完整的成立訊號、近 60 個交易日都有日線，但不在今日候選（被名次截斷的股票、ETF） | 所屬族群當日最佳名次，再依代號；沒有族群名次的排最後 |
| 3 | 接近成立 | 第 4 級的條件，再加上至少一條策略「接近」（下方） | 未達成條件數，再依價格差距（由小到大），再依代號 |
| 4 | 其他觀察 | 資料日有資料完整的觀察訊號、近 60 個交易日都有日線 | 差項最少的策略的未達成條件數（條件明細尚未產生的排最後），再依代號；同短名的條件各算一條，所以與說明欄「差 N 項」的 N（短名數，§6）可能不同 |
| 5 | 資料待補 | 兩條策略都沒有資料完整的結果，或近 60 個已核實交易日有缺日線（含上市未滿 60 個交易日）；行動摘要對這些標的判「策略判斷資料待補」 | 自選在前，再依代號 |

- **接近成立**（第 3 級，`decision.py` 的 `ACTION_NEAR_PRICE_GAP`，屬 `action_tier_v1`）：一條策略的條件價位列（`strategy_levels`，[strategy_levels_v1](spec/strategy_levels.md)）同時符合：
  1. `availability=levels`，且 `reachable_next_session` 不是 false。`trend_unreachable`、ETF 排除類別（`not_applicable`）、資料不足都不算。
  2. 未達成的條件只有價格（突破的收盤突破前 20 日高點、回踩的收盤在支撐區）或量能；族群、法人、融資（回踩另含趨勢）與其他條件都已達成。
  3. 價格差距：突破 ≤ 3%、回踩 ≤ 2%（含等於）。差距是條件明細裡價格條件的下一交易日距離（突破為觸發價 ÷ 最近收盤 − 1；回踩為最近收盤到支撐區最近一端，區內為 0），取絕對值；價格條件在資料日已達成時記 0。

  兩條策略都接近時取未達成條件數較少的一條，相同再取價格差距較小的，再相同依策略宣告順序（突破在前）。沒有條件價位列的觀察（較早的資料日，或條件價位步驟失敗）不判接近，歸第 4 級。
- **不升級**：自選不改變級別；近 7 日官方事件不提升級別。
- **篩選膠囊**：「重點 N」（第 0～3 級）、「含其他觀察 N」（再加第 4 級）、「全部 N」（再加第 5 級），預設「重點」；旁邊一個勾選框「含 ETF（N）」，預設不勾。持倉與自選在任何篩選下都列出，持倉的 ETF 不受「含 ETF」影響。膠囊的 N 是目前「含 ETF」設定下該篩選的檔數；「含 ETF」的 N 是在目前篩選下勾選它會多列（或已多列）的 ETF 檔數。數字都取自 API 的 `summary`，前端不自己數。
- **隱藏句**：篩選列下方一行「預設隱藏：ETF X 檔、其他觀察 Y 檔、策略判斷資料待補 Z 檔；自選標的一律顯示。隱藏不刪資料，切換上方篩選即可看到。」數字取自 `summary.hidden`；一檔只算一次，ETF 先算在 ETF。為 0 的項目不寫，三項都是 0 時整行不出現。不是預設篩選（「重點」且不含 ETF）時開頭改為「目前隱藏：」。
- **搜尋**（代號／名稱）不受篩選限制：符合的標的不論級別、是否 ETF 都列出，各在所屬級別的區塊；搜尋時隱藏句改為「搜尋不受篩選限制，結果依級別列出。」
- **區塊**：每級一個區塊，只列目前篩選下有標的的級別。開頁時載入列表第一頁 20 檔；有標的但第一頁沒輪到的級別，首屏另外載入它的前 5 檔，不留空區塊。標題下一行「顯示 k／N 檔」（k 已載入、N 是該級在目前篩選下的檔數）；還有未載入的列時，區塊下方一個按鈕「顯示更多（還有 M 檔）」，一次載入 20 檔。所有區塊都沒有標的時寫「目前沒有符合篩選的標的。」
- **每列**：代號名稱、市場 · 類型、狀態（行動摘要的標籤，持倉數量待核實另標「庫存數量待核實」）、最近收盤與漲跌（[§8.1](#81-今日個股清單壓縮卡)）、資料日、「策略總表 →」（連到個股頁研究條件分頁）。第 0～2 級另有進場區、停損、目標一（成立條件的價位，表頭帶「（元）」；行動列表只列目標一；持倉列的停損是使用者 stop 或策略失效價），第 1 級另有名次與總分，第 2 級狀態下一行寫為何不在今日候選（§6）。第 3 級沒有價位欄，改為「差哪個條件」一欄（§6 接近成立卡），最後一欄寫「價位見策略總表 →」。第 4、5 級另有一欄說明（第 4 級為行動摘要的主要原因，即 §6 的「差 N 項」句，沒有條件價位列時下一行加「條件明細尚未產生」；第 5 級為缺項）。沒有合法價位時該格留空，表外註明「空白表示沒有成立的價位」，不用 0 或破折號。當日行情不足時收盤格寫「價格資料尚未完整，暫不顯示最近收盤」。
- **我的庫存**：沒有庫存時收成一行：「我的庫存」「尚未建立庫存。」「有持倉風險時列在最上方。」與「新增庫存」展開鈕；有庫存時顯示完整區塊（每筆持倉、核對與新增表單）。

## 7. 詞彙原則

詞條內容（term_id、名稱、別名、分類、白話說明、用途、解讀、限制、相關詞、版本）以 `backend/app/glossary.py`（`GET /api/glossary`）為準，`frontend/src/glossary.ts` 是 API 不可用時的本地副本；本節只寫原則。

- **中文對照**：日常頁用中文術語，英文、enum 與欄位名依 §2 對照，只在研究／系統層露出；別名用於搜尋。詞彙出現在 UI 不代表對應資料或模型已上線。
- **白話與限制並列**：每個詞同時寫用途與誤讀界線，例如突破、目標價、T+1 都不等於成交或必達；資料不足時明說無法用該指標下結論。
- **事實／推論分欄**：來源事實、規則判定與推論（AI 摘要、影響推論）分開命名；推論詞須標方法與引用，unknown 不是負面訊號。
- **口徑**：「外資」「三大法人」依[資料來源的法人口徑](DATA_SOURCES.md#法人口徑)；「熱門族群」只用於五分項完整的群組（[hot_group_v1](spec/hot_group.md)）。
- **不用的詞**：日資料不稱「現價」，固定 confidence 或模型自評不稱「勝率」或「校準機率」；不以「主力」「隔日沖」或分點名稱推定投資人身分；不寫「保證」「必漲」等報酬承諾。
- **呈現**：Modal 依白話定義、用途、解讀與限制排列，不以 term_id 或欄位名作標題。詞彙按鈕須支援滑鼠、觸控、Enter／Space，Esc 關閉後焦點回觸發點；定義不得只靠 hover 或顏色。滑鼠移到詞彙按鈕上時以原生提示（`title`）顯示白話定義，點開才是完整 Modal；所以就地說明詞條的白話定義寫成一句口語，不放公式或門檻，例如 RR「可能賺的空間是可能賠的幾倍」、總分「用來排候選順序的分數，不代表勝率」。詞彙按鈕不放在整張可點的連結卡片裡（如族群榜手機卡、今日頁熱門族群卡），那裡只顯示文字，說明在同一詞出現的表格、詳情頁或用語表。
- **就地說明**：候選卡、族群頁與個股「研究條件」分頁的下列用詞以詞彙按鈕開啟詞條；`percentile` 日常頁不露出英文。

| 用詞（出現處） | 詞條 `term_id` |
| --- | --- |
| 總分（候選卡）、權重涵蓋（評分細節） | `candidate_score` |
| 進場區（候選卡） | `entry_zone` |

## 8. 壓縮卡、詳情與單位文案

### 8.1 今日／個股清單壓縮卡

順序為：代號／名稱 → 最近收盤與可信漲跌幅 → 一個行動結論 → 一個主要原因 → 一組關鍵價位（如合法）→ 資料日期與詳情入口。缺相鄰、同 basis 的可信前收盤時寫「漲跌幅待核實」；no condition、資料待補或人工判讀不顯示關鍵價位。行動摘要附 `market_read` 時，只有 `status=known`、`invalid_fields` 為空且最近收盤為正有限數值才顯示價格；否則價格與漲跌顯示「待核實」「漲跌待核實」，標題改為「策略判斷資料待補」。

### 8.2 個股詳情的第一屏

第一屏是頁首加「圖表與指標」。頁首依序為代號、名稱、市場（上市／上櫃）與類型、最近收盤（報價幣別元）、漲跌與漲跌幅（漲紅跌綠、正數帶 `+`）、資料日期 badge 與來源。頁尾固定附註：「此為研究工具與資料摘要，不構成投資建議、報酬保證或自動下單指令。」

個股詳情以「圖表與指標／法人籌碼／新聞與公告／研究條件／資料說明」分頁，預設為「圖表與指標」。頁首最近收盤取 bars API 日線最後一根有完整 K 線的列；直接前一列也是同來源的交易日才算漲跌，否則顯示「漲跌待核實」；沒有可信收盤時顯示「待核實」，不改稱零或負面訊號。研究截止日期不影響頁首收盤與 K 線。

每日候選與族群成員的 `market.change_status`（`app.market_change.adjacent_change`）：`known` 才顯示漲跌；`no_previous_close` 是前一個已驗證交易日該來源有日線、只有這檔沒有（無成交、停牌或當天才上市，來源沒給收盤，collector 不存沒有收盤的列；畫面不指明是哪一種），寫「前一交易日無收盤」，不拿更早的收盤補算（交易所的參考價不一定是最後一筆成交價）；整個來源那天都沒有日線（資料未抓）、前一列是另一個來源，仍是 `unverified`，寫「漲跌待核實」（[#465](https://github.com/YiCheng0608/stock-lab/issues/465)）。

行動詳情與研究條件分頁的時間摘要「資料日期：… · 決策時間：… · 規則最早執行日：…」：角色沒有值寫「未記錄」（`decision_at` 目前一律 `legacy_decision_at_not_persisted`，系統沒有保存決策時間），有值但無法確認（沒有時區、狀態 unknown）才寫「待核實」；下一行固定「時間以台灣時間顯示；系統沒有記錄的時間寫「未記錄」，有值但尚未確認的寫「待核實」。」

**研究截止日期**（頁首的設定列）：開關與表單上寫目前實際使用的資料日。沒有指定日期時寫「研究截止日期：最新資料（YYYY/MM/DD）」，日期是 API 實際採用的截止日（`news_cutoff.as_of`，沒有時用 `decision_summary.data_cutoff`；兩者都沒有就只寫「最新資料」）；指定日期時寫「研究截止日期：YYYY/MM/DD」。表單下固定一句「只用這一天收盤（含）以前的資料判斷研究條件、研究動作與候選，用來回看當時會怎麼判斷；空白或按「最新資料」時用 YYYY/MM/DD（該股最近一個有資料的交易日）。頁首收盤、K 線與新聞時間線不受影響。」日期與上一句相同；已指定截止日或不知道最新資料日時，「用 YYYY/MM/DD（…）」改寫「用最新資料日」。「研究條件」分頁依序為策略總表（[§10.1](#101-個股策略總表)）、研究動作、所屬族群；族群卡標題「所屬族群」，讀 API `groups`：`verified=true` 顯示 `display_name`（ETF 與新上市列沿用前端類別譯名），`verified=false` 顯示「族群關聯待核實」，驗證規則見 [INDUSTRY_CLASSIFICATION §5.1](INDUSTRY_CLASSIFICATION.md#51-既有錯配-membership-修復)。

「圖表與指標」的日／週 K 線、成交量、MA5／10／20／60／120（可勾選）與 MACD／RSI／KD／布林面板全部取自 `GET /api/stocks/{exchange}/{symbol}/bars`（`limit=250`；公式與欄位見 [技術指標](spec/indicators.md)），前端不自行計算均線或指標；停牌與無效列不畫 K 線，缺日不補。指標或均線欄位為 null 時依最新一根判斷：

| 情況 | 顯示 |
| --- | --- |
| 原因全是 `not_computed` 且整段沒有值 | 面板「指標尚未計算」 |
| 整段沒有值 | 面板「無資料」加原因 |
| 最新一根沒有值、前面有值 | 照畫，圖下註明該根無資料與原因 |
| 均線最新一根沒有值 | 圖下列出「MA120 無資料：日線不足 120 根，現有 80 根」 |

原因文案：`insufficient_bars` 為「日線不足 N 根，現有 M 根」（週線寫「週線」；N 取缺值欄位 `indicators.required_bars` 的最大值，M 為該根 `bar_count`，缺 `bar_count` 時只寫「日線不足 N 根」）；`suspended` 為「停牌，當日不計算」；`invalid_bar` 為「當日行情無效，不計算」；`no_price_change` 為「期間內收盤沒有漲跌，無法計算」；未知原因為「原因待核實」。籌碼沒有資料列時顯示「尚無可核實的籌碼資料。」。資料說明分頁列出 bars API `indicators` 的指標版本、價格基準、日線指標計算時間與 K 線資料日期。

### 8.3 張／零股

- DB／API／來源數量保存精確整數股與 unit；`LOT_SIZE=1000`。
- 成交量與法人買賣超的日常主值為整數張：股數 ÷ 1,000 四捨五入到整數，`.5` 一律遠離零，千分位逗號；以精確股數字串計算，不先轉 `Number`。499／500／1,500／−7,500 股分別為 `0`／`1`／`2`／`-8` 張；int64 上限 `9,223,372,036,854,775,807` 股為 `9,223,372,036,854,776` 張。絕對值不足 500 股的非零值（零股）主值為 `0`、不帶正負號，原股數見原始值；方向值非零時帶 `+`／`-`。多日合計先加總股數再換算，不把每日已四捨五入的張數相加。
- 依據（2026-10-25 查證）：TWSE [三大法人買賣超日報](https://www.twse.com.tw/rwd/zh/fund/T86?date=20261022&selectType=ALLBUT0999&response=json)與[個股日成交資訊](https://www.twse.com.tw/rwd/zh/afterTrading/STOCK_DAY?date=20261022&stockNo=2330&response=json)以股為單位、千分位、不換算張；[Yahoo 股市法人買賣](https://tw.stock.yahoo.com/quote/2330.TW/institutional-trading)標「單位(張)」，整數、千分位，與 T86 股數逐筆比對為四捨五入且 `.5` 遠離零（−500 股 → −1、−7,500 股 → −8、53,500 股 → 54），不足 500 股顯示 `0`，三大法人合計由股數加總後換算。
- 原股數放預設收合的「資料來源與原始值」或同等的來源稽核 details；表格單位依 §8.4 放表外。
- 庫存數量是持有量而非統計值，維持精確：拆末三位、保留至多 3 位小數的零股（1,500 股為 `1.5 張`、999 股為 `0.999 張`），不四捨五入。
- 價格與平均成本為元／股，不乘 1,000；API 未提供 currency 時寫「各標的報價幣別的元」，不猜 `NT$`。TAIEX 等指數用點數。
- 來源單位 unknown／mixed 不換算，表外說明「單位待核實」、數值格留空；來源已為張的融資不重複換算。可信 `quantity.unit="mixed"` 是同一已知股數的張／零股拆分，仍有效。
- Canonical 股字串只接受 ASCII `0` 或無前導零的非零整數；方向欄可有單一負號，不接受 `-0`、正號、分數、科學記號、空白或尾端換行。單日絕對值上限 `9223372036854775807`，買進／賣出與成交量須非負；5／20 日淨超的絕對值上限分別為 `46116860184273879035`／`184467440737095516140`。精確欄為 null、非法或壞字串時顯示待核實；response 完全沒有精確欄時才讀安全整數 number（`units.ts` 的 `exactVolumeText`）。
- **我的庫存**：表單預設 `unit=lot`，張數或股數輸入正整數 ASCII 字串；送出 `unit + quantity` 整數字串，例如 1 張送 `unit=lot, quantity="1"`、1 股送 `unit=odd_lot, quantity="1"`，讀回主值為 `1 張`／`0.001 張`。可保存總股數為 `1..9,223,372,036,854,775,807`，超限不送出，超大字串不經 Number；這個上限只留在程式，畫面不顯示：表單提示寫「每張為 1,000 股，可輸入整數張或零股股數。」，超限錯誤寫「數量超過可保存的上限，請確認張數或股數。」。平均成本與停損為元／股；空字串送 `null`，非空須為非負 ASCII 十進位數。前端拒收或 API 回 422 時保留 draft 並顯示錯誤。

| 庫存讀值 | 日常文案 |
| --- | --- |
| 股數無法核實 | 「庫存數量待核實」；原股數稽核顯示「股數待核實」 |
| 可信股數超出安全整數 | 市值／損益顯示「估值精度待支援」 |
| 成本或停損 missing／invalid | 「未提供」／「待核實」 |
| 本地收盤可試算 | 日常卡顯示「行情待核實」；收盤 missing／invalid 為「未提供行情」／「行情數值待核實」 |

本地收盤與市值／損益試算只在預設收合的「核對庫存原股數、本地行情與試算」內顯示，並標「本地記錄；來源／日期待核實」與「本地試算，行情來源／日期尚未核實」。

### 8.4 數值表格、單位與空白

每個數值欄位都要帶單位，使用者不必去讀表外說明才知道單位（[#463](https://github.com/YiCheng0608/stock-lab/issues/463)）：

- **表格**：單位寫在欄名後的全形括號，例如「收盤（元）」「漲跌幅（%）」「成交金額（億元）」「成交量（張）」「成交股數（股）」「樣本（筆）」「成員（檔）」。數值格只顯示數字，不逐格重複「元」「張」或 `%`，方向值明示 `+`／`-`。價格的「元」指各標的報價幣別的元，指數為「點」（§8.3），這層說明留在表外說明。
- **卡片與標籤／值**（手機卡片、`dl`、指標卡）：百分比在值後面接 `%`（`-9.62%`），倍數接「倍」，其他單位寫在標籤括號內，例如「成交金額（億元）」。
- **0–100 的分數與百分位**（族群分數、五分項、候選總分）沒有單位：分數欄名寫「分數（0–100）」「總分（0–100）」；五分項欄位多，量尺寫在表外說明一次。
- **兩個數字並列**時各自標名稱，不只用斜線隔開：價位寫「目標一／目標二」，值寫「{目標一}／{目標二}」，欄名與標籤用同一個順序。
- 表外說明仍寫空白、「—」與口徑的意思；單位已在欄名的就不再逐欄重寫。

缺值不寫 0、`N/A`、`--`、「無資料」或英文 placeholder，改為空白，並在表格外寫「空白表示來源未提供」；若原因是來源或單位未核實，須另行具體說明。

畫面呈現成交金額時，須依 API 的 `turnover_status` 決定數值格：`available` 且值為來源明確的 `0` 才顯示 `0`；`unavailable` 或 `unknown` 即使底層 `turnover=0` 也留空。`unavailable` 可在表格外說「成交金額未取得」，`unknown` 則說「成交金額待核實」，不把兩者合稱來源真的零；原因碼與數值狀態須一致。底層保存與計算規則見 [DATA_SOURCES](DATA_SOURCES.md)。tooltip、等效資料表與表外說明須同步使用相同口徑。

### 8.5 族群榜與族群詳情

- **榜別**：`board` 寫「產業」「題材」，其他值寫「其他」；族群頁與今日頁的分頁籤只有產業、題材兩個。
- **今日頁**：「熱門族群」區取各榜前 5 名（眉標「族群發現 · 各榜前 5 名」），每名一列精簡列：名次、名稱、品質、分數、1／5／20 日相對報酬與「資料 YYYY/MM/DD · 相對加權指數」；完整排行在 `/themes`。
- **品質**：`quality` 依 [§3](#3-三種資料完整度) 寫「熱門族群」或「技術與籌碼觀察（事件資料待補）」；其他值寫「資料完整度待核實」。
- **數值**：分數 0–100 取兩位小數；五分項是同榜百分位，以 0–100 整數呈現；1／5／20 日相對報酬是相對加權指數的百分比，兩位小數、正數帶 `+`、漲紅跌綠；成員寫「有效／總數」。單位依 §8.4：族群榜表頭寫「分數（0–100）」「1 日（%）」「5 日（%）」「20 日（%）」「成員（檔）」，手機卡片、今日頁精簡列與族群詳情的 1／5／20 日值後接 `%`。分項或報酬為 null 時顯示「—」（[DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)），並在表外寫「「—」表示該項無資料」，不寫 0。
- **日期**：右上角 badge 寫「資料 YYYY/MM/DD」（分數日 `trading_date`）；官方資料日 `data_as_of` 不同時另加「官方資料 YYYY/MM/DD」。
- **相關新聞時間**：族群詳情的相關新聞每列時間與新聞頁相同，只讀 `product_time`，文案見 [§4 日期](#4-新聞卡文案與折疊)。
- **空狀態**：空榜原文顯示 API 的 `empty_message`，前端不自組原因；走勢少於 2 個有分數的交易日寫「走勢資料不足（需至少 2 個交易日的分數）」；相關新聞為零寫「此族群尚無已核實關聯的新聞」。
- **族群詳情的名次與五分項**：名次、品質與五分項讀族群榜（`GET /themes?board=`），不是讀族群詳情本身，所以依族群榜請求分三種狀態，不混用（[#463](https://github.com/YiCheng0608/stock-lab/issues/463)）：
  - **載入中**：排名格與五分項卡顯示骨架（標 `aria-busy`），不寫「不在本日榜」。
  - **載入失敗**：排名格寫「—」與「榜單暫時無法載入」，五分項卡寫「榜單暫時無法載入：{原因}」，不寫「未列入」。
  - **已載入、不在榜上**：排名寫「—」與「未列入本日榜單」，五分項卡說明「此族群不在本日<榜別>榜（有效成員未達 3 檔或資料不足以計分），五分項沒有同榜百分位。」
  - **已載入、在榜上**：排名下一行「<榜別>榜共 N 個族群」。分數與有效成員先讀族群榜那一列，沒有時讀族群詳情。
- **族群成員表**（族群詳情「族群成員」，讀 `GET /themes/{id}/members`，每頁 30 檔；桌面表格、640px 以下每檔一張卡，[DESIGN_SYSTEM §5](DESIGN_SYSTEM.md#5-元件)）：
  - **欄位**：代號 → 名稱（後接狀態 badge：今日候選寫「候選 #N」（`candidate_rank`），不是候選但有成立條件寫「條件成立」（`conditional`）；兩者都不是但符合行動列表第 3 級的接近規則（§5；持倉在行動列表列為第 0 級，這裡照樣標）寫「接近成立」（`near`）；題材榜 `role=leader` 另加「領先成員」）→ 市場（上市／上櫃）→ 收盤（元）（`latest_bar.close`，兩位小數）→ 漲跌幅（%）（`change_pct`，兩位小數、正數帶 `+`、紅漲綠跌；與今日候選 `market` 同一個相鄰交易日規則）→ 成交金額（億元）（當日成交金額，`turnover` ÷ 1 億，兩位小數、千分位）→ 5 日相對（%）、20 日相對（%）（`excess_return_5d`／`excess_return_20d`，讀當日族群分數的 `member_returns`，相對加權指數的報酬，兩位小數、正數帶 `+`、紅漲綠跌，與族群榜 1／5／20 日同一口徑）→ 證據（只有題材榜）。產業榜不顯示角色，題材榜的角色只以「領先成員」badge 呈現。
  - **排序**：表上方「排序」下拉：成交金額（預設）、漲跌幅、5 日相對、20 日相對，皆由大到小；代號由小到大。由 API 排序（`sort=turnover`／`change_pct`／`return_5d`／`return_20d`／`symbol`），空白值一律排最後，同值依代號；換排序回到第 1 頁。
  - **不同日**：成員最新一根日線早於「成員資料截至」日（`members_as_of`）時，收盤格下一行寫「資料 YYYY/MM/DD」（該根日期，§1），漲跌幅與成交金額留空，不拿舊日資料冒充當日；同日不標日期。
  - **空白**（§8.4）：`change_status` 不是 `known`（缺前一交易日的同來源日線、停牌或沒有當日日線）時漲跌幅留空；`turnover_status` 不是 `available` 時成交金額留空（`available` 且來源為 0 才寫 `0.00`）；不在 `member_returns` 的成員（例如未合格成員）5／20 日相對留空。單位在欄名（§8.4），表外先寫「收盤為各標的報價幣別的元；成交金額是當日成交金額；5／20 日相對是相對加權指數的報酬。」，再依本頁出現的情形逐句接：「漲跌幅空白表示前一交易日沒有收盤價，不計算漲跌。」（`no_previous_close`，[§8.2](#82-個股詳情的第一屏)）「漲跌幅空白表示漲跌待核實。」（其他不是 `known` 的值）「成交金額空白表示來源未提供。」（`unavailable`）「成交金額空白表示待核實。」（`unknown`）「5／20 日相對空白表示未列入當日族群計分。」「收盤下方的「資料 YYYY/MM/DD」表示該檔沒有成員資料日的日線，漲跌幅與成交金額留空。」「收盤空白表示該檔尚無日線。」；本頁沒有空白就只有第一句。
- **題材成員證據**：`relation` 寫「主要業務」（core_business）、「產品線」（product_line）、「供應鏈」（supply_chain），`relevance` 寫「關聯度高／中／低」，未知值寫「關係待核實」「關聯度待核實」；http(s) 的 `url` 顯示「證據來源」並開新分頁，否則寫「來源連結未提供」；沒有證據寫「證據待核實」。題材詳情另列「題材表版本 <definition_version>」。

### 8.6 新聞題材建議

[新聞題材建議](spec/theme_suggestions.md)是 LLM 推論，與族群榜分開呈現。

- **位置**：族群頁（`/themes`）排行之下另一區，眉標「新聞聚合 · AI 推論」、標題「新聞題材建議」，右側「{N} 個建議 · 最近更新 YYYY/MM/DD HH:mm」（`meta.updated_at` 換算台北時間；沒有帶時區的時間不顯示）。區塊說明固定一句「由 AI 從近期新聞判讀出的題材名稱彙整。題材名都已通過規則題材核對（出現在原文，或由規則命中的標的所屬產業推得），但尚未納入題材表；不列入族群排行、不計分，也不作為交易理由。」
- **每個建議**：放在 AI 推論樣式的區塊（左側強調色豎線，[DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)），名稱旁標「AI 推論」（accent badge），不標「待核實」（推論，[§1.1](#11-待核實推論與無資料)；#465）；新聞日期缺漏寫「新聞日期未提供」；下一行「{則數} 則新聞 · 首次 YYYY/MM/DD · 最近 YYYY/MM/DD · 模型未提供把握」，首末同日寫「新聞日 YYYY/MM/DD」；把握有值時寫「模型把握高／中／低」。不顯示排名、分數或 `theme_key` 等內部值。
- **關聯新聞**：預設收合「關聯新聞（{則數} 則）」，展開列最近 5 則：標題連到 `/news/:id`，下一行「{來源} · 新聞日 YYYY/MM/DD · 判讀題材「{模型寫法}」」，有理由再一行「理由：{理由}」。超過 5 則時給「顯示其餘 {N} 則」，載入中寫「載入其餘新聞中…」，失敗寫「其餘新聞暫時無法載入：{原因}」並保留按鈕。
- **版本**：每個建議底部「模型 {模型，多個以頓號分隔；沒有寫未記錄} · 提示版本 {prompt_version} · 彙整規則 {aggregation_version}」。
- **其他**：`meta.matched_total` > 0 時寫「另有 {N} 個建議與既有產業或題材同名，不另列出。」；列表被 `limit` 截斷時寫「依關聯新聞則數顯示前 {顯示數} 個，共 {total} 個。」
- **空狀態**：標題「目前沒有新聞題材建議」，原因「新聞 AI 判讀尚未提出與既有族群不同名的題材」。

## 9. 中文原因碼對照

reason code 的日常文案由 `backend/app/presentation.py`（`REASON_LABELS`、`display_reason`）與 `frontend/src/presentation.ts` 提供，下表只列原則與代表列。未知 code 一律顯示「研究條件需要人工核對」，原值只留稽核層；不同策略的 code 保留各自範圍。

| 理由碼 | 條件 | 文案 |

  - 其他（沒有分數列、`insufficient_members`、`insufficient_data`）：「{名稱}（{產業／題材}，當日未排名）」。
  - 沒有所屬產業或題材時寫「無所屬產業或題材」。
- **分數**：總分與分項為 0–1，日常以 0–100 整數呈現；分項為 null 顯示「—」並附 API 的 `null_explanation`，不寫 0。`partial_components=true` 時在總分旁註明「部分分項無資料，以有資料的分項計分」。
- **聲明**：清單頂端固定一句「評分只用於排序，不代表勝率或預期報酬」。
- **AI 進出點說明**（`llm_note`，[候選 AI 進出點說明](spec/candidate_score.md#候選-ai-進出點說明)）：每張候選卡在族群列之後、「評分細節」之前放 AI 推論樣式的區塊（左側強調色豎線，[DESIGN_SYSTEM §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)），標題「AI 進出點說明」，右側「AI 推論」（accent badge）。`status=done` 且三段都有字時依序列「為何入選」「進場區、停損與目標」「需留意的風險」與 API 文字；沒有說明（`llm_note` 為 null 或欄位不存在）寫「此檔尚未產生 AI 說明」，`pending` 寫「AI 說明這次未能產生」（不承諾自動重試，補跑見 [日誌與 run 記錄](ops/SCHEDULING.md#日誌與-run-記錄)）。區塊內固定一句「由 AI 依上方規則數值、理由與關聯新聞撰寫的推論，不是買賣建議；價位以規則數值為準。」；有 `llm_note` 時底部「模型 {model，沒有寫未記錄} · 提示版本 {prompt_version} · 產生於 YYYY/MM/DD HH:mm」（`generated_at` 換算台北時間，沒有時區時省略時間）；`pending` 不寫模型，時間改寫「嘗試於」。今日頁與個股頁相同。
- **零候選**：顯示 API 的 `zero_reason_text`；`no_actionable_signals`「當日沒有成立（條件成立）的策略訊號」、`all_excluded`「成立的訊號都因 ETF、價位不合法或評分資料不足被排除」。`status=not_computed` 寫「此交易日尚未產生候選清單」。空狀態標題分別為「當日零候選」與「尚無候選清單」，零候選保留資料日期 badge、not_computed 不顯示日期。

### 10.1 個股策略總表

`GET /api/stocks/{exchange}/{symbol}` 的 `strategy_board`（#274），個股頁「研究條件」分頁最上方，取代原本的候選面板與靜態條件清單。視覺見 [DESIGN_SYSTEM §5 策略總表與 §7](DESIGN_SYSTEM.md#7-資料與狀態的視覺語言)。

- **標題列**：眉標「研究條件 · 每個策略一列」、標題「策略總表」，右側「資料 {YYYY/MM/DD}」（`as_of`，該股最近一個策略判定日）與「價位規則 v1」（`levels_version`）。標題下固定一句「每個研究條件各自判定；「觀察價位」是條件尚未成立時，下一交易日收盤與成交量要達到的參考值，不是建議進出點。」沒有任何判定時寫「此股尚無策略判定資料。」不顯示勝率或成立機率。
- **欄位**（桌面表格；640px 以下每策略一張卡，內容相同）：策略（「突破條件」「回踩條件」，詞彙按鈕）→ 狀態 → 差哪個條件 → 價位；每列下方「{策略}條件明細」展開。
- **狀態**：`conditional`「成立」（下一行「最早執行日 {YYYY/MM/DD}」，沒有日期時省略）、`observation`「觀察」、`data_incomplete`「資料不足」、`not_applicable`「不適用」；未知值寫「狀態待核實」。成立是指資料日判定成立，之後追蹤狀態（觸發、達標、失效）不改這一欄。
- **條件表**：每個條件碼的文案只在這張表定義。程式各一份：「差哪個條件」「條件明細」「接近成立的差：句」在前端 `frontend/src/stock/strategyBoard.ts`（`CONDITIONS`），「短名」在策略 registry（`backend/app/strategies`，`Strategy.short_label`），API 把短名放進行動列表的 `nearness` 與 `primary_reason`，前端不另存短名。兩份的條件碼都要等於 registry 各策略的條件（測試核對）。未知碼一律寫「研究條件需要人工核對」。

  | 條件碼 | 短名 | 差哪個條件 | 條件明細 | 接近成立的差：句 |
  | --- | --- | --- | --- | --- |
  | `eligibility` | 適用標的 | 標的不適用 | 適用標的 | — |
  | `required_inputs` | 必要資料 | 資料待補 | 必要資料齊備 | — |
  | `breakout_price` | 價格 | 收盤未突破前 20 日高點 | 收盤突破前 20 日高點 | 差：收盤站上前 20 日高點（還差 {價格差距}%） |
  | `breakout_volume` | 量能 | 量比未達 {threshold} 倍 | 量比 {門檻} 倍 | 差：量能 {門檻} 倍（今日 {量比} 倍） |
  | `pullback_history` | 日線 | 日線未滿 {threshold} 日 | 日線滿 {threshold} 日 | — |
  | `pullback_trend` | 趨勢 | 20 日均線未站上 60 日均線 | 20 日均線在 60 日均線之上 | — |
  | `pullback_above_ma60` | 趨勢 | 收盤低於 60 日均線 | 收盤不低於 60 日均線 | — |
  | `pullback_support_zone` | 支撐區 | 收盤不在支撐區 | 收盤在 20 日均線支撐區 | 差：收盤回到 20 日均線支撐區（高於上緣 {價格差距}%）；低於下緣時寫「低於下緣」；資料日收盤不在當日支撐區、但已在下一交易日的區間內（`position=inside`，差距 0）時括號寫「最近收盤已在下一交易日的區間內」 |
  | `pullback_volume` | 量能 | 量比不在 {threshold}～{threshold_high} 倍 | 量比 {門檻} 倍 | 差：量能 {門檻} 倍（今日 {量比} 倍） |

  | `institutional_flow` | 法人 | 法人籌碼未達要求 | 法人 5 日淨額 ÷ 20 日均量 {門檻}% | — |
  | `margin_financing` | 融資 | 融資增加超過上限 | 融資 5 日變動 {門檻}% | — |

  「接近成立的差：句」只用於能接近的條件（價格、量能，§5）；其他條件未達成時不會判接近。{門檻} 的寫法見下方條件明細；{價格差距} 讀 `nearness` 的 `gap`（下一交易日距離，§5），v1 例：「差：收盤站上前 20 日高點（還差 2.10%）」「差：量能 ≥ 1.20 倍（今日 0.80 倍）」「差：量能 0.60～1.20 倍（今日 1.32 倍）」。
- **差哪個條件**：成立寫「全部達成」；觀察列出 `unmet` 的「差哪個條件」短句（條件表），以「、」連接；資料不足寫「缺：{missing_labels，以「、」連接}」；不適用直接寫 `missing_labels`（例：「債券、槓桿或反向 ETF 不適用一般突破／回踩研究條件」）。
- **成立價位**（`levels.kind=actionable`，讀訊號）：突破「觸發（元）」、回踩「進場區（元） {低}～{高}」，接「停損（元）」「目標一／目標二（元）」（值「{目標一}／{目標二}」；沒有目標二時標籤與值都只寫目標一）「RR」（值後接「倍」）；價位兩位小數，標籤與今日候選相同（詞彙按鈕）。

- **量的單位**：觀察價位與條件明細的成交量依 [§8.3](#83-張零股) 換成整數張，但這裡是條件的門檻：下限（最小量）無條件進位、上限（最大量）無條件捨去，顯示的門檻不會比實際條件寬鬆（例：15,110,400 股寫「≥ 15,111 張」）；API 保留原始股數。
- **條件明細**：每條一行，前置狀態 badge「已達成」（success）／「未達成」（warning）／「無資料」（muted）／「不適用」（muted），接條件名（條件表「條件明細」欄）。{門檻} 由 API 該條的 `operator`（`gt` >、`gte` ≥、`lt` <、`lte` ≤）與 `threshold` 組成，`between` 寫「{threshold}～{threshold_high}」，數字兩位小數（比率乘 100 為 %），前端不寫死規則數字；條件沒有門檻時改寫「達規則門檻」「在規則區間」等，不補數字（例：v1 為「量比 ≥ 1.20 倍」「量比 0.60～1.20 倍」「族群 20 日超額報酬 > 0.00%」「法人 5 日淨額 ÷ 20 日均量 ≥ -0.30%」「融資 5 日變動 ≤ 5.00%」）與資料日的實際值（價格兩位小數、量比兩位小數加「倍」、比率為帶正負號的 %、兩位小數）；未達成且可反推的條件另起一行「下一交易日收盤 ≥ {價}（距最近收盤 {±%}）」「下一交易日成交量 {最小}～{最大} 張」等。`eligibility`／`required_inputs` 未通過時列原因（§9）。
- **不適用的條件**（[#392](https://github.com/YiCheng0608/stock-lab/issues/392)）：非融資標的的融資條件（`satisfied` 為 null、`reasons` 含 `margin_financing_not_applicable`）badge 寫「不適用」，數值欄寫原因「非融資標的，融資條件不適用」，不寫「—」也不列下一交易日；它不算未達成，也不是缺資料，所以不出現在「差：」與「缺：」。行動頁不另列這一條：這類標的的卡片照其他條件分級，不再顯示「近 5 日融資變化資料待補」。缺資料的融資條件照舊是「無資料」。
- **候選列**：見 [§10](#10-每日候選) 個股頁候選列（總分旁有聲明句）；AI 說明只出現在候選列，策略列不放 AI 內容。

- **頁首資料列**：一行「資料截至 YYYY/MM/DD · {來源} · {快照模式}」（`dashboard.as_of`、`market.source_label`；模式寫「官方單日快照」「官方單日快照（資料仍待補）」「尚無官方快照」），右側品質 badge 與「資料說明」展開。「資料說明」依序列：掃描範圍與標的、日行情、行動摘要筆數；成交金額範圍「成交金額範圍：上市為{上市 `scope_label`}；上櫃為{上櫃 `scope_label`}」；上櫃漲跌幅為 `derived` 時「櫃買指數漲跌幅依前一日收市指數計算」；固定一句「紅色為上漲、綠色為下跌（台股慣例）」。
- **大盤概況**：讀 `dashboard.market_overview`（交易日與 `dashboard.as_of` 相同）。四格：
  | 格 | 標籤與單位 | 內容 |
  | --- | --- | --- |
  | 加權指數 | 「加權指數」，單位「點」 | 上市 `index.close` 兩位小數；下一行漲跌點數與漲跌幅「{±點數}（{±%}）」，兩位小數、正數帶 `+`、紅漲綠跌 |
  | 櫃買指數 | 「櫃買指數」，單位「點」 | 上櫃，同上 |
  | 成交金額 | 「成交金額」，單位「億元」 | 兩行「上市 {億元} {短範圍}」「上櫃 {億元} {短範圍}」：`turnover.value` ÷ 1 億、兩位小數、千分位；金額後常駐 muted 短範圍，`twse_all_securities` 寫「集中市場總計」、`tpex_stocks` 寫「上櫃股票」，其他值寫 API 的 `scope_label` |
  | 漲跌家數 | 「漲跌家數（股票）」，右側「括號為漲停／跌停」 | 兩行「上市 上漲 {n} · 下跌 {n} · 平盤 {n}（{漲停}／{跌停}）」，家數整數 |
- **範圍**：成交金額口徑依來源，上市為「集中市場總計（含 ETF、權證等）」、上櫃為「上櫃股票」。成交金額格每行常駐短範圍（上表），完整的 `turnover.scope_label` 寫在「資料說明」；家數兩邊都是股票。
- **缺資料**：某交易所 `status=unavailable` 時，該交易所的指數格與成交金額、漲跌家數的該行都寫「上市大盤資料未取得」或「上櫃大盤資料未取得」，另一交易所照常；欄位為 null 寫「—」，不寫 0。
- **手機**：640px 以下只顯示兩個指數格，成交金額與漲跌家數收進「成交金額與漲跌家數」展開。
- **持倉風險提示列**：只在行動摘要有已驗證持倉風險時出現（持倉的 `reduce_exit`，或持倉的策略判斷資料待補、庫存數量待核實）：「持倉風險 {N} 檔：{代號} {名稱}：{原因}」，多檔以「；」分隔、最多列 3 檔，其餘寫「等 {N} 檔」；原因依序為「減碼／退場條件」（`reduce_exit`）、「持倉風險資料待補」、「庫存數量待核實」；資料來自 `dashboard.actions`。右側連結「查看行動中心 →」到 `/actions`。

## 12. 追蹤計畫

使用者把成立的研究條件存成[追蹤計畫](spec/tracking.md#使用者追蹤計畫)；成交與結果都是依日線規則的**模擬**，不是實際成交，也不是 LLM 推論（不標「推論」）。文案常數在 `frontend/src/tracking/tracking.ts`，verify 的 actions A14～A17、today T13 依同一份字串比對。

- **加入追蹤**：今日頁每檔候選的明細（桌面展開的明細列、手機卡的「AI 說明」）在資料日期之前放 secondary 按鈕「加入追蹤」（送出中「加入中…」）；該訊號已有未取消的計畫時改成連結「已在追蹤」，連到 `/actions#plan-<id>`。個股頁的入口只有「研究條件」分頁的「追蹤計畫 · 模擬」卡，標題「把研究條件加入追蹤」：每個成立（`conditional`）的策略一列「{突破條件／回踩條件}成立」、`條件資料日 YYYY/MM/DD` 與同樣的按鈕；沒有成立的策略時只寫一行「目前沒有成立的研究條件，無法建立追蹤計畫」。卡底說明「加入後每日依日線規則模擬成交與出場，結果在行動頁「追蹤計畫」與「追蹤回看」；不是實際成交。」
- **拒絕原因**（API `detail`）：`stale_signal`「這個研究條件的資料日已過，請用最新資料日的條件建立」、`signal_not_conditional`「這個研究條件目前不成立，無法建立追蹤計畫」、`invalid_levels`「研究條件的價位不完整或不合理，無法建立追蹤計畫」、`candidate_signal_mismatch`「候選與研究條件不一致，請重新整理頁面」、`candidate_not_found`「找不到這筆候選，請重新整理頁面」、`signal_not_found`「找不到這個研究條件，請重新整理頁面」，其他「加入失敗，請稍後再試」。
- **行動頁區塊順序**：「我的庫存」（實際持倉）→「追蹤計畫」（眉標「模擬追蹤 · 進行中」，待觸發與已觸發）→「追蹤回看」（眉標「模擬追蹤 · 已結束」，含已取消）→ 行動列表（[§5](#5-行動中心的分級與預設篩選)）；三區不混排，區塊標題右側寫「{n} 筆」。「追蹤計畫」標題下固定一句「計畫價位來自建立當日的研究條件；成交與結果是依日線規則的模擬（買賣各 {滑價} bps 滑價、來回 {成本} bps 成本假設），不是實際成交，也不統計勝率。實際持股請看「我的庫存」。」（數字取 API `meta`）。空狀態「尚未建立追蹤計畫。可從今日候選或個股研究條件加入。」與「尚無已結束的計畫。」。每區每頁 20 筆，超過時下方「第 {頁}／{總頁} 頁 · 共 {總數} 筆」與上一頁／下一頁。
- **計畫卡**：眉標「{上市／上櫃} · {策略}」，標題代號與名稱（連個股頁），右上狀態 badge 與 `資料 YYYY/MM/DD`（追蹤到的最後交易日，還沒有就用計畫資料日）。狀態：`pending` 待觸發、`triggered` 已觸發、`target_hit` 達標、`invalidated` 失效、`incomparable` 無法比較、`expired` 到期、`closed` 期滿結算、`not_entered` 未進場、`cancelled` 已取消。`data_quality=transition_conflict` 時在價位上方加「行情有更正，狀態待核對」，狀態維持 API 的原狀態。價位列「進場區（元）」「失效價（元）」「目標一（元）」「RR」（值後接「倍」；失效價是策略失效價，不叫停損；計畫只追蹤目標一）。之後依序：`計畫資料日 YYYY/MM/DD · 建立 YYYY/MM/DD`（建立日為 `created_at` 的台北日期）、`第 {n}／{視窗} 個交易日`、`模擬成交 YYYY/MM/DD {價格}` 或「尚未模擬成交」、有出場時 `模擬出場 YYYY/MM/DD {價格}`。
- **模擬報酬**：只在已結束的卡。可比較時 `模擬報酬 {±x.xx%}`（`result_return × 100`，兩位小數，正數帶 `+`）；其餘寫 `模擬報酬：無法比較（{原因}）`：未進場「成交當日開盤已在目標以上，不模擬進場」（`gap_above_target`）或「成交當日開盤已在失效價以下，不模擬進場」（`gap_below_invalid`）、到期或未成交「視窗內未模擬成交」、已取消「已取消」、同日觸及「同一交易日失效價與目標一都觸及，先後順序不明」、`insufficient_sessions`「40 個交易日內該股不足 20 根日線」、停牌「期間有停牌或不可比較的日線」，其他「原因待核實」。不出現勝率、達標率或任何彙總比率。
- **取消**：進行中的卡有 ghost 按鈕「取消追蹤」，按下後改為「確定取消」「保留」與「取消後不再更新，計畫與明細會保留。」；拒絕時「計畫已結束，無法取消」「計畫狀態剛更新，請重新整理後再試」「找不到這個計畫，請重新整理頁面」，其他「取消失敗，請稍後再試」。
- **逐日明細**：每張卡底部收合「版本、來源與逐日明細」：一行 `來源 {今日候選／個股研究條件} · 策略版本 {id} · 公式 {formula_version} · 評分 {score_version，個股來源不寫} · 追蹤規則 {tracking_version}`；展開時才讀明細，表格欄「日期、第幾日、狀態、開、高、低、收、觸發」，表上註「價格為當日原始日線（報價幣別元），觸發依計畫價位換算到當日價格基準判定；成交為模擬。」。第幾日寫「第 {n} 日」；狀態 `not_triggered` 未觸發、`active` 已模擬成交、`target_1_hit` 達標、`invalidated` 失效、`ambiguous` 順序不明、`suspended` 停牌、`not_entered` 未進場；觸發列「進場」「目標」「失效」，沒有寫「—」。還沒有交易日寫「尚無追蹤的交易日。」。
