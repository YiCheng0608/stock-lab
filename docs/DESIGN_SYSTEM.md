# 前端設計規範

本文是前端唯一的視覺與互動規範，所有前端工作（新頁面、改版、元件）都必須遵守；偏離要先在 Issue 說明並經統籌同意。token 與元件規則源自 UI/UX Pro Max 的 investment-platform demo，以本文為準。

頁面資訊架構與各頁內容見 [PRODUCT_SPEC §2](PRODUCT_SPEC.md#2-主導航與資訊順序)、文案與單位見 [UI_COPY_SPEC](UI_COPY_SPEC.md)。

## 1. 整體氛圍

- **深色金融儀表板**：近黑的藍灰底、分層的卡片、細白邊線、單一藍色主色，資料數字用等寬字。安靜、專業、以數字為主角，不用插圖與大面積彩色。
- **層次靠底色而非陰影**：頁面底 → 區塊底 → 卡片 → 浮起元素四層底色；陰影只在 hover 與主按鈕出現。
- **點綴而非裝飾**：漸層只用在 logo、標題關鍵字（`gradient-text`）與主按鈕；不用背景柔光（blur 光暈）。
- **一眼可讀的漲跌**：漲跌只靠顏色與正負號，不加箭頭圖示或閃爍。數值與價位的紅綠只用於漲跌（台股慣例紅漲綠跌）；進出點等其他數值與價位語意不用紅綠（§7）。例外：狀態 badge 的 success／error 變體（§5，如「行情來源完整」）與籌碼理由色點的 `--color-secondary`（§7）表示狀態或分類，不是數值方向。
- **桌面優先、窄版可用**：內容寬 1280px 居中，16px 側邊留白，手機單欄。

## 3. 字級與數字

| 用途 | 字級／字重 | 說明 |
| --- | --- | --- |
| 頁面標題 h1 | 28px／700 | 今日頁不放頁面大標，第一行是頁首資料列（§4） |
| 區塊標題 h2 | 30–36px／700 | 置中或靠左，下方 8px 說明文字（muted，18px） |
| 卡片標題 h3 | 20px／600 | |
| 內文 | 16px／400 | 說明文字用 `--color-text-muted` |
| 標籤、表頭、註腳 | 14px／500；註腳 12px | 表頭 muted，不全大寫 |
| 主要數字（股價、淨值） | 30–36px／700，`--font-mono` | 卡片一個主數字 |
| 次要數字（表格、統計） | 14–16px／500–600，`--font-mono`，`tabular-nums` | 靠右對齊 |
| 漲跌 | 同欄位字級／600 | 色依 `--color-up`／`--color-down`／`--color-flat`，正數帶 `+` |
| 今日頁（#510） | 名單標題 `--text-2xl`／700；首頁卡標題 `--text-xl`／700；候選列代號名稱 `--text-lg`／600；進場句 `--text-md`；AI 說明第一段 `--text-base`；列內 meta、族群與新聞第二行 `--text-sm`；標籤 `--text-xs` | 新元件的字級寫 §2 的 `--text-*` token；其他頁沿用上列數值，不因 token 重排 |
| 個股頁（#519） | 頁首名稱 `--text-2xl`／700、代號 `--text-xl` mono；收盤 36px（手機 30px）mono 700；摘要卡判斷句 `--text-base`、欄標籤 `--text-xs`、差哪個條件 `--text-sm`；各分頁卡標題 `--text-xl`／700（`panel-head`）；說明小字 `--text-xs` | 研究條件、圖表、籌碼、財務、新聞、資料說明各分頁的卡標題與說明同此 |

所有金額與百分比用 `font-variant-numeric: tabular-nums` 對齊；千分位逗號。同一欄（表格的一欄、同類卡片的同一欄位）小數位數固定，不因數值而去掉尾端 0（`21.10` 不寫 `21.1`）：

| 數值 | 位數 |
| --- | --- |
| 單一標的的價格（K 線表、個股頁） | 依該標的最近收盤的 tick（`priceDigits`）：50 元以下 2 位、50～500 元 1 位、500 元以上 0 位；ETF 2 位；指數 2 位、單位「點」（#549）。漲跌金額與收盤同位數 |
| 跨標的的價格欄（個股清單、族群成員、行動列表與其手機卡） | 2 位；行動列表的漲跌只寫百分比（同候選列表） |
| 規則算出的價位（進場、觸發、停損、目標） | 2 位 |
| 百分比 | 2 位（另有規定者依 [UI_COPY_SPEC](UI_COPY_SPEC.md)） |
| 張數、筆數、檔數、日數 | 整數；張的換算見 [UI_COPY_SPEC §8.3](UI_COPY_SPEC.md#83-張零股) |

## 4. 版面與導航

- **Navbar**：固定頂部，高 64px，`backdrop-filter: blur(20px)`，底色 `--color-nav-bg`，下緣 1px `--color-border`。左側 40px 圓角 logo（主色→強調色漸層方塊＋白色折線圖示）加產品名；中間六個主導航連結（今日名單、大盤、我的追蹤、族群、個股、策略說明；#493、#549；新聞在 #631 移到頁尾的「系統」頁），顏色 muted、hover 轉主文字色、當前頁主文字色加 2px 主色底線；右側放搜尋（代號／名稱，輸入時列出建議，見 §5「導覽列搜尋建議」）與資料日期 badge；資料日期 badge 是每頁唯一的頁面日期（§7，#661），放在選單外，手機也在導覽列上。手機收成漢堡選單。
- **內容容器**：`max-width: var(--content-max)`，左右 padding 16／24／32px（手機／平板／桌面）。
- **區塊**：垂直 padding 64px，桌面 96px；相鄰區塊以 `--color-bg` 與 `--color-bg-alt` 交錯。
- **網格**：卡片列用 CSS grid，桌面 2–4 欄、平板 2 欄、手機 1 欄，gap 16–24px。
- **今日頁頁首**：沒有 hero 與光暈。第一行是一行資料列（來源 · 快照模式 · 品質 badge · 「資料說明」展開；資料截至日期只在與頁面日期不同天時寫在最前，#661），其下是大盤摘要列（§5，#549 起取代原本約 85px 高的四格大盤概況條，完整的大盤概況在大盤頁，下一條）。之後依序為持倉風險提示列（有才出現）、今日名單、熱門族群（下方「熱門族群」；首頁不放新聞卡，#625）（[PRODUCT_SPEC §2](PRODUCT_SPEC.md#2-主導航與資訊順序)）。名單標題列只有一行（#510，不放眉標）：「今日名單」、資料日期 badge、「{N} 檔」、T+1 句接聲明句（小字，占其餘寬度）與「順勢籌碼型 · 策略說明 →」（名稱在前，#577）；放不下時小字換到下一行；640px 以下小字自成一段，排在標題列下一行；標題列放不下連結時（390px 寬就是這樣），連結換到小字之上的一行、靠右。區塊間距 `--space-block`。全部收合時，1280×800 第一屏要完整看到至少 3 檔候選、390×844 至少 2 檔，每檔看得到代號名稱與進場句（句中有停損與目標；#510）。1280px 以上名單與 K 線卡並排（§5 候選列表盤後終端），每列改手機排列，列高約 168px，所以第一屏從 #510 的 5 檔降為 3 檔，用兩檔名單換一張選中個股的 K 線（#644 實測：1280×800 完整 3 檔、390×844 列高約 210px 完整 2 檔；#653 加走勢線後 1280 列高不變、390 約 219px，仍完整 2 檔；統籌決定 [6816855285](https://github.com/YiCheng0608/stock-lab/issues/644#issuecomment-6816855285)）。
- **大盤頁 `/market`**（#549）：集中大盤層級的資訊，今日名單頁只留一行摘要連過來。頁首一行：h1「大盤」與右側預設收合的「說明」`<details>`（#666 起說明句收在裡面，展開時占下一整行），不放眉標。其下區塊順序固定，每個區塊一張卡（自己的標題與右側資料日期 badge；大盤概況與指數總表是 `panel`＋`panel-head` h2 `--text-xl`／700，共用 K 線圖是個股頁 K 線的 `Card`），區塊間距 `--space-4`：
  1. **大盤概況**：標題列右側資料日期 badge（`market_overview.trading_date`；與頁面日期同一天時不畫，§7）與「資料說明」`<details>`（展開時換行占整列寬）。內容是四個雙列 `market-widget`（加權指數、櫃買指數、成交金額、漲跌家數）收在同一條框內（card 底與邊線、圓角 12px），格間以 1px `--color-border` 分隔、不各自成卡，指數的點數與漲跌排在同一行，桌面一列四格（約 85px 高）；1199px 以下一列兩格，800px 以下成交金額與漲跌家數兩格各占一列（四格同列會切掉上市／上櫃那一行，#493 review）。這頁就是看大盤的地方，640px 以下不收合：兩個指數一列兩格，成交金額、漲跌家數各占一列。四格之下隔 `--space-2` 是一條同樣框線與底色的「加權指數與季線（MA60）」（`market-ma60`，#561）：標籤列同 `market-widget-head`（右側單位「點」），下一行 `--text-md`（640px 以下 `--text-sm`）的收盤、資料日、位置與季線值，位置詞 600、`--color-text`；再下一行 12px muted 的區段。這條是背景資訊：不用紅綠或任何漲跌色、不用 badge；沒有位置時只寫 muted 原因（同 `market-widget-empty`）。
  2. **指數總表**（#564，取代 #547 的美股四格）：`panel`＋`panel-head`（h2「指數總表」、右側資料日期 badge `market_overview.trading_date`（與頁面日期同一天時不畫，§7）、「資料說明」`<details>`），內容是共用 `DataTable` 一張表（`market-index-table`）：3 列依序加權指數、櫃買指數、台指期近月，沒有分組標題（#633 起不列美股四列；資料照收）。欄位：指數、收盤（點）、漲跌、漲跌幅、相對季線（MA60）、來源（#661 起沒有資料日欄）；收盤、漲跌、漲跌幅是 `num` 欄，指數兩位小數、台指期整數（§3）。列高 44px、儲存格左右 padding `--space-3`。紅綠只用在漲跌與漲跌幅；列的資料日寫在指數名稱下一行（muted mono `--text-xs`，`.market-index-asof`），只在與頁面日期不同天或「非最新」時才有，「非最新」`--color-warning`、600；相對季線是位置詞（之上／之下／持平，600、`--color-text`）接 muted mono「季線 {值}」，資料不足與無資料只寫 muted 文字，不用漲跌色（背景資訊，同 `market-ma60`）；台指期名稱後接 muted mono `--text-xs`「合約 YYYY/MM」，換月日的漲跌、漲跌幅兩格寫 muted「換月」（不留白）；沒有資料的列數值格寫「—」、名稱下一行寫 muted 原因（可換行）。來源欄 muted、640px 以下隱藏（`wideOnly`）；「來源：…」句是該表「資料說明」的第一行（#666 起不在表下；640px 以下沒有來源欄，展開資料說明可見）；表下 `small-note` 依序：換月日的說明（有才出現）、操作提示。#666 在 verify 假資料庫實測：1280×800 共用 K 線圖 top 801→773，390×844 指數總表第一列 top 696→643（第 3 列 bottom 約 850，差 6px 未完整進第一屏）。

### 5.1 窄版與手機的表格呈現

640px 以下依內容二選一，同一個列表不兩者並用：

- **卡片**：一列是一個標的、族群或策略，使用者逐列掃讀再點進詳情的列表——行動列表、族群成員表、策略總表、個股清單。桌面仍是共用 `DataTable`；640px 以下改渲染卡片、隱藏表格，不用橫向捲動表格。今日名單與族群榜例外：所有寬度同一份清單（§5 候選列表、族群榜），不分表格與卡片。
- **橫捲**：同一標的的時間序列，或要逐欄比較的明細——K 線資料、法人與融資、原始行情、評分細節，以及研究頁、系統頁的表格。保留表格，照下方「橫捲表格」。

**手機卡片**（§5 各列表只寫自己有哪些欄位，順序與外觀照這裡）：

- 外觀：card 的底色與邊線，圓角 12px、padding 12px 16px。整張卡只有一個去處時整張是連結，否則標題是連結。
- 欄位順序：① 標題列——左側辨識（代號名稱、族群名或策略名，狀態 badge 接在後面），右側這一列的主數字（收盤與漲跌，或總分、分數）→ ② 分類行（muted 的「市場 · 類型」、策略或族群）→ ③ 數字格，muted 標籤在上、mono 數字在下，一列三格（放不下的格子自成一列）→ ④ 理由、說明或證據 → ⑤ 資料日與入口連結。沒有的欄位整段省略，不留空格。
- 數字與日期不換行、`tabular-nums`，位數與桌面同一欄相同（§3）；文字可換行。
- 超過 10 張時只列前 10 張，其餘收進「顯示其餘 N 檔」（族群寫「N 個族群」）`<details>`；候選與行動列表另有前 N 檔與「顯示更多」的規則（§5），照它們自己的。

**橫捲表格**：

- 表格寬度依內容，不設固定最小寬度；容器 `overflow-x: auto`，欄位放不下時只在表格內橫向捲動，頁面本身不得出現橫向捲動。
- 儲存格預設不換行，避免中文被擠成一字一行；只有長文字欄（子項說明、族群名稱）標記可換行（`DataTable` 欄位 `wrap`）。
- 640px 以下：儲存格左右 padding 8px、列高 44px；第一欄（日期、代號或子項名）固定在左側（`position: sticky`），捲動時仍看得到這一列是什麼；關鍵數字欄（收盤、買賣超）要在第一屏看得到，次要文字欄（交易所、類型、角色等）可在此寬度隱藏（欄位 `wideOnly`），完整內容在桌面版與詳情頁。
- 卡片內的表格（例如候選卡的評分細節）至多 4 欄，分組標題放在獨立的整列（`colSpan`），不另占一欄，讓數字欄在 390px 寬的卡片內完整可見。

## 6. 圖表（ECharts）

- 圖表顏色同樣只來自 tokens：ECharts 畫在 canvas 上不能解析 `var()`，元件在執行時以 `getComputedStyle(document.documentElement)` 讀取 §2 的變數再傳給 option。
- 背景透明，格線 `--chart-grid`，軸文字 `--color-text-muted` 12px mono。
- K 線：漲 `--color-up`、跌 `--color-down`，實體與影線同色；成交量柱同漲跌色、60% 透明。量能 y 軸標籤 1 萬以上縮寫成「萬」「億」（最多 1 位小數），在 64px 左邊界內不被切（PR #553 review）；個股以張、指數以億股、台指期以口。價格 y 軸與指標面板的 y 軸標籤 1,000 以上不帶小數（指數的 MACD 可到數千點；美股指數的「8,000.00」在手機的 64px 左邊界會被切，#547）。
- 均線固定色：MA5 `--chart-ma5`（`#f59e0b`）、MA10 `--chart-ma10`（`#8b5cf6`）、MA20 `--chart-ma20`（`#3b82f6`）、MA60 `--chart-ma60`（`#10b981`）、MA120 `--chart-ma120`（`#9ca3af`）。布林面板：中軌主色、上下軌強調色、收盤線 muted。
- 指標面板（MACD／RSI／KD／布林）：今日名單與大盤頁的 K 線卡置於主圖下方，高度為主圖 35%，共用 x 軸與 dataZoom；個股頁（#656）放在「走勢」分頁的技術指標卡（下方「個股頁的 K 線卡」一條）。MACD 柱用漲跌色，DIF／DEA 用主色與強調色；RSI／KD 參考線（20／80、30／70）用 `--color-text-subtle` 虛線。
- 單線圖（熱度走勢、淨值）：主色線寬 2px，下方用主色漸層填充（頂部 25% 透明到底部 0）。指數（大盤頁）不用單線圖，用個股頁同一套 K 線與指標面板（§4 大盤頁）。
- 只有收盤的序列（#547）：整個序列的每一根都沒有開高低（FRED 的美股指數列，#547；#568 起美股改用 FinMind，有開高低）時，主圖畫一條收盤線（`--color-text`、1.5px、無點），不畫 K 棒與成交量柱，圖下 `chart-note` 註明「來源只提供收盤價…」；指標面板照常（KD、量均線為 null 時照既有空狀態）。只有部分日子缺開高低的序列（台股指數、個股）不畫這條線，那些日子照舊留空、資料表照列收盤。
- 區間按鈕（#600）：K 線卡工具列在日K／週K 分頁籤之後放一列篩選膠囊（§5）「1M」「3M」「6M」「1Y」「全部」，預設「6M」，窄版與均線開關各自換行。按鈕只設定 x 軸 dataZoom（inside＋slider 同步）的起訖，選中變體表示目前的顯示範圍；拖動、滾輪或雙指縮放後沒有按鈕是選中。文案與「全部」何時另取資料見 [UI_COPY_SPEC §8.2](UI_COPY_SPEC.md#82-個股詳情的第一屏)。
- Tooltip：底 `--color-bg-card`、1px 邊、圓角 8px、mono 數字；滑鼠十字線 `--color-text-subtle`。tooltip 限制在圖表範圍內（`confine`），手機上點一下顯示同一個十字線與提示，不超出螢幕邊。圖表區 `touch-action: pan-y`、inside dataZoom `preventDefaultMouseMove: false`：直向滑動捲頁，橫向單指拖動平移圖表；一次觸控移動 8px 後判定方向，以直向為主的滑動不改顯示範圍（期間的 dataZoom 事件忽略，手指放開時還原），也不取消區間選取；只改動不到一根 K 棒的事件同樣不算手動縮放。Chromium Edge 被 zrender 5.6 當成舊版 Edge 時，元件改用與 Chrome 相同的觸控事件路徑（#600）。
- 個股頁的 K 線卡（#648）在頁首卡與摘要卡之間、每個分頁都在，頁面上只有這一張（§4 個股頁頁首與摘要卡）。#656 起個股頁把同一元件拆成兩處，今日名單並排的 K 線卡與大盤頁不拆、維持一張含指標面板與資料表的卡（眉標「技術指標 {公式版本}」、均線勾選在工具列）：
  - **K 線卡**（頁首下方）：標題「K 線」、不放眉標；只畫主圖（K 棒、均線、規則價位線）與成交量，slider 在成交量下方。主圖高 400px（640px 以下 280px），成交量為主圖 24%。工具列只有日K／週K 與區間按鈕；均線勾選移到圖下第一行（兼圖例），其下依序是規則價位說明與 `chart-meta`（來源、價格基準、最近 N 根）。tooltip 只列開高低收、成交量與勾選的均線。
  - **技術指標卡**（「走勢」分頁）：眉標「技術指標 {公式版本}」、標題「技術指標」、右側資料日期 badge；工具列是 MACD／RSI／KD／布林分頁籤（布林是第四個面板：收盤線＋三軌，不疊在主圖）；圖區一個指標 grid（桌面 200px、640px 以下 150px）與日期軸，沒有 slider；圖下是面板無資料註記、`chart-meta`（指標批次時間、最近 N 根，「區間與日K／週K 跟著上方 K 線卡」）與「查看圖表資料表（最近 30 根）」。
  - **同步**：兩張圖讀同一份 bars 與同一個顯示區間（`StockPage` 持有 `useBarsView`：區間按鈕、手動縮放、「全部」另取的長序列），日K／週K 也由頁面持有；兩個 ECharts 實例 `connect` 同一 group，十字線與 inside 縮放即時連動。在任一張圖拖動或滾輪縮放都更新共用區間；切到別的分頁再回到「走勢」，指標圖沿用目前區間。兩個圖區都帶 `data-bars-window`（`{interval}:{第一根}-{最後一根}`），供測試與 verify 對照。
- 規則價位線（個股頁）：策略總表有成立（`conditional`）且價位完整的策略時，主圖畫三條橫線並在線的左端上方標「名稱 價格」（12px mono、600）：進場 `--color-text` 虛線、停損 `--color-warning` 實線、目標（目標一）`--color-primary` 實線，線寬 1.5px；進場到目標、停損到進場各鋪一層同色 10% 透明的色帶。顏色與 §2 進出點語意相同，不用漲跌色。突破型的進場是觸發價，回踩型是進場價（`pullback_v4` 起為進場區中點）；取哪一個策略與摘要卡「最接近成立」相同。線上標籤與圖下文字的價格用策略總表同一個格式（`candidates.formatPrice`，千分位、固定兩位小數，如 335.71）；K 棒、軸與 tooltip 仍照 `priceDigits` 的檔位（50～500 元一位小數），所以軸上可能是 335.7、線上是 335.71（#647）。價格軸自動延伸到停損與目標，並在最高的價位線上方、最低的下方各留一個標籤高度（20px，依主圖高度換算成價差；K 棒本身已超出這個距離時不再加）：目標價等於區間高點時，「目標」標籤仍完整在圖內（#647，今日名單右側的 K 線卡同一張圖）；留邊後的軸頂不是整數刻度，有價位線時不標軸頂的值（軸底原本就不標）。線不攔截滑鼠（`silent`），十字線與 tooltip 照常。圖下 `chart-note` 以文字再寫一次三個價位並註明「條件成立當日的價位，不是成交價」。觀察中的策略（只有觀察價位）、資料不足、價位不完整或順序不對時不畫線；大盤頁的指數圖不畫。
- 資料日期顯示在圖右上角 badge，與頁面日期同一天時不畫（§7）；圖下的「來源」與個股頁頁首相同時不重複。

## 7. 資料與狀態的視覺語言

- 資料日期每頁一次（[#661](https://github.com/YiCheng0608/stock-lab/issues/661)）：導覽列的日期 badge「資料 YYYY/MM/DD」是每頁唯一的資料日期，放在導覽列上、不收進手機選單（640px 以下排在品牌與選單按鈕之間，品牌 logo 縮為 32px、間距縮為 `--space-3`，390px 不換行、不溢出、不蓋住選單按鈕）。資料卡右上角的日期 badge 只在卡片日期與頁面日期**不同天**時才畫（追蹤計畫卡較早的模擬日、個股頁選了研究截止日、族群榜未更新、財務卡的季別日期）；同一天不畫。卡內句子與表格列的日期同理（指數總表、行動列表的列：不同天時在名稱下一行寫「資料 YYYY/MM/DD」，沒有「資料日」欄）。頁面日期載入中、失敗或沒有值時，所有日期 badge 照舊畫。實作：`DateBadge` 讀 Shell 提供的頁面日期（`components/pageDate.tsx`），導覽列自己的 badge 帶 `always`。排程更新中的 warning badge「更新中」、「非最新」、停牌、無資料原因、「資料日期未提供」這些狀態與日期是否相同無關，一律照畫。
- 來源與單位同理：同頁（或同卡）來源相同只寫一處（個股頁 K 線卡的來源與頁首相同就不寫；指數總表的來源句只在該表「資料說明」一處，#666）；單位已寫在欄名「（元）」就不在每格重複，我的追蹤的「單位：…」只寫在第一張畫出來的價位表上方。
- 無資料：欄位留空顯示「—」加 muted 原因，不顯示 0。
- LLM 推論內容：左側 2px 強調色（`--color-accent`）豎線加「AI 推論」小 badge，與事實分區。區塊標一次、區塊內不重複（#661）：badge 只在區塊標題列一個，區塊內的段落不再逐項加；規則算出的事實（分數、價位、「來源：」行）不出現推論字樣。今日名單列上的「AI 推論 ▸」是收合時打開明細的入口，不算區塊內的重複。例外：新聞卡的 AI 候選行（[§5](#5-元件)「新聞卡 AI 候選行」）只用豎線，標題文字本身寫「推論」，不另加 badge，讓每張新聞卡只有方向後的那一個「AI 推論」。
- 進出點（全站：今日名單與其進場卡片、個股頁策略總表與研究動作、我的追蹤列表）：進場區主文字色 mono（`.level-entry`）；停損 `--color-warning`（`.level-stop`）；目標 `--color-primary`（`.level-target`）；RR 用 badge；每個價位都帶文字標籤。紅綠只用於漲跌，進出點不用 `--color-error`／`--color-success`，以免讀成漲跌。
- 觀察價位（個股頁策略總表與摘要卡，條件未成立時的參考價與量；策略總表內收合、摘要卡不收合，§5）：放在 1px 虛線（`--color-border-hover`）、圓角 8px 的區塊內，區塊第一行是 muted 小字標籤「條件未成立・觀察價位」，區塊文字 muted、價位字重 400；參考停損與參考目標沿用 `.level-stop`／`.level-target` 色並帶「參考」字樣。成立價位不加框、不加此標籤，兩者不放在同一個區塊。觀察價位未產生時區塊改為 warning 色邊與文字。不顯示勝率或成立機率。
- 接近成立（我的追蹤第 3 級）：只用 primary badge（「接近突破條件」「接近回踩條件」）與文字，除了每列都有的最近收盤，不顯示任何價位，連觀察價位也不放；每條未達成的條件一行「差：…」（主文字色），下一行 muted「…已達成」。數字只有價格差距 % 與量比倍數，不寫元。成立條件的列（第 0～2 級）才有 `.level-entry`／`.level-stop`／`.level-target` 價位，兩種列不共用價位格；要看價位走「價位見策略總表 →」到個股頁。
- 追蹤計畫卡（我的追蹤「追蹤計畫」「追蹤回看」）：版面同 `card` 網格（桌面 2 欄、手機 1 欄），價位列沿用進出點的顏色（`.level-entry`／`.level-stop`／`.level-target`）；右上狀態 badge 加資料日期 badge。狀態 badge 對照：待觸發 primary、已觸發 warning、達標 success、失效 error、無法比較 warning、到期／期滿結算／已取消 預設（無色）。行情更正待核對用 warning 框（`warning-box`），模擬報酬用 mono 600、不上漲跌色（模擬結果不是行情）。「加入追蹤」是 `btn-secondary`、「取消追蹤」是 `btn-ghost`，兩者都不用主按鈕。640px 以下（#649）卡上只留眉標（市場 · 策略）、標題、兩個 badge、進場區／停損／目標一三格（一列三格）、進度行與模擬報酬；RR、計畫資料日與建立日、模擬成交與出場、「取消追蹤」與逐日明細收進卡底的「更多」`<details>`（桌面不變）。沒有進行中的計畫時「追蹤計畫」只有說明句與一行空狀態小字（不放空狀態框）。「追蹤回看」預設收合：整個區塊標題列是 `summary`，右側「{n} 筆」後接主色 `--text-sm` 的「展開 ▸」／「收合 ▾」。
- 候選清單理由：照 API 順序（`candidate_score_v1` 每檔最多四條），每條一行，前綴 8px 色點（技術 primary、籌碼 secondary、新聞 accent、族群 `--color-text-muted`）；`inference=true` 的理由只標一次推論：API 文字已寫「（推論）」就不另加 badge，沒寫才同列加「推論」badge（accent 變體，#661）。今日頁列表的列上不放理由，明細的「分項分數與理由」顯示全部（#510）；個股頁策略總表的候選列顯示全部。

## 8. 無障礙與動效

- 文字對比至少 4.5:1；muted 文字只用於 14px 以上。
- 所有互動元件有 `:focus-visible` 外框（2px 主色、offset 2px）。
- 動效只用 transform 與 opacity，時長 200–300ms；`prefers-reduced-motion` 時全部關閉。
- 圖示用 24px 線條 SVG（stroke 2，`currentColor`），不用彩色圖示或 emoji。

## 9. 實作規則

- 樣式以 Tailwind utility 搭配上述 CSS 變數（`text-[var(--color-text-muted)]` 形式）或等價的 CSS class；禁止元件內 inline 色碼。色碼字面值（`#rgb`、`rgb()`、`rgba()`、`hsl()`）只出現在 `frontend/src/styles/tokens.css`，由 `frontend/src/noHardcodedColors.test.ts` 檢查。
- 共用元件放 `frontend/src/components/ui/`（Card、CardList、Badge、Button、Table、Tabs、Stat、EmptyState、Skeleton、ScoreBar／StrengthChip），頁面只組裝不重畫。
- 新元件先查本文是否已有對應規則；沒有就先補本文再實作。
- PR 附桌面（1280px）與手機（390px）截圖各一張，確認符合本文。
