# 台股事件、族群與交易研究產品規格

更新：2026-10-03。本文只定義現行產品方向與目標契約；能力狀態、優先順序與已驗收範圍見 [ROADMAP](ROADMAP.md)。個股頁與前端 UX 的有限已驗收範圍分別見 [STOCK_RESEARCH_PAGE](STOCK_RESEARCH_PAGE.md) 與 [UX_REVIEW](UX_REVIEW.md)。未被具名驗收的欄位或流程仍是目標，不得由文件推論已上線。

正式資料仍有市場別產業代碼與舊 membership 不一致。資料重建通過前，官方產業排行及其衍生研究條件必須標示「既有族群關聯待重新核實」；中文 `display_name` 只能以「（既有分類）」加待核實 badge 呈現。此缺陷不改寫 OHLCV、數量換算或新聞內容。

## 1. 產品目標與第一版範圍

產品以新聞／事件與近期強勢題材縮小研究範圍，再綜合個股籌碼、技術結構與公司證據，產出少量、可追溯的研究候選與條件式交易計畫；持倉風險與事後追蹤沿用同一證據鏈。

第一版假設為盤後研究、最早下一交易日執行、持有數天至數週的股票 long 策略。精確期間與個人風險預算尚待決定；日線不支援盤中精確進出。股票／ETF 的 v1 基準保留，ETF 專用新策略優先度較低。

公司品質、事件機會、交易位置與持倉風險必須分開呈現。熱度、利多與規則通過都不等於合適買點；缺資料時保留 unknown 或拒絕判斷，不用單一「好股分數」掩蓋矛盾。

## 2. 主導航與資訊順序

| 路由 | 名稱 | 優先回答 |
| --- | --- | --- |
| `/` | 今日 | 市場狀態、重大事件、值得觀察的族群／個股及持倉風險。 |
| `/news`、`/news/:id` | 新聞 | 新資訊、來源、相關標的與已知／推論／未知的影響。 |
| `/themes`、`/themes/:id` | 族群 | 官方產業與題材、熱度、廣度、集中度及資料限制。 |
| `/stocks`、`/stocks/:exchange/:symbol` | 個股 | 四個判斷面向、條件計畫與完整證據。 |
| `/actions` | 行動 | 持倉風險、有效計畫、待觸發／到期／暫無條件與資料待補。 |

主導航維持五個；研究、回測、coverage、策略、資料品質與詞彙保留為次要入口。舊 groups、instruments、signals、tracking、portfolio、backtest 路由可相容轉向，不再維護第二套主導航。

首頁依市場與事件 → 族群／題材 → 今日關注股票排列。持倉風險優先；同一 `exchange + symbol + as_of` 只顯示一張卡，正面保留辨識資訊、一個結論、一個主要原因、一至兩個核心數字、資料日期與詳情入口。候選為零是合法結果。

### 2.1 個股研究頁的近期交付

`/stocks/:exchange/:symbol` 先交代標的、實際資料區間、筆數、來源與價格口徑，再呈現圖表、行動摘要、族群、籌碼、事件／新聞、策略條件與資料品質。K 線只用 API 原始 OHLC；沒有調整 basis 與因子時固定標示「原始 API 價格；還原方式未提供」。120 根視窗、缺值、圖表互動、等效資料及未包含項目以 [個股研究頁契約](STOCK_RESEARCH_PAGE.md) 為準。

### 2.2 官方事件關注入口

M2-P1 已有限 review 本次官方事件觀測的關注清單；同股一張、保留各事件來源與生效日期，以固定代碼順序呈現並帶相同研究截止進已知標的的 M1 總覽。這是事件研究入口，不產生利多、排名或交易條件；零筆與來源不足分開，未知目錄標的不造連結。API／時間／去重與具名驗收範圍由[個股頁 §12](STOCK_RESEARCH_PAGE.md#12-m2-p1官方事件關注清單接個股總覽)負責；完整 M2 與 M1 未滿足的窗口／研究條件仍保留原完成條件。

M2-P2 搜尋／研究往返已有限接受：先搜尋完整合格原件的代碼／名稱，再套顯示上限；明列原件、符合、顯示與截斷，空原件／無符合／來源不可用分開。M1 返回保留原清單搜尋／截止，個股改截止不覆寫返回條件。精確 query、安全返回與具名範圍見[個股頁 §13](STOCK_RESEARCH_PAGE.md#13-m2-p2官方事件清單搜尋與研究往返)，不增加來源、排名或完整 M1／M2 完成度。

## 3. 事件與族群研究（下一版）

### 3.1 新聞不只計篇數

新聞要交代新增資訊、相關標的、影響與反證、來源、可用時間及判讀方法；轉載不重複計分，利空篇數也不能增加正向機會分數。「價格是否已反映」只作具名窗口的市場反應觀察。欄位、去重與時間規則見 [新聞規格](NEWS_SPEC.md)。

### 3.2 官方產業與市場題材分開

- 官方產業保留交易所 namespace、名稱來源與生效日；題材可跨產業且一家公司可多重歸屬。
- 每條題材 membership 需有原始證據、關聯方式、相關程度、生效／失效日及版本。模型提出的關聯先標待核實，不可變成官方分類或買賣理由。
- 族群卡呈現 1／5／20 日熱度變化、廣度、領漲集中度、籌碼分歧、價格延伸、事件方向與各域 coverage；同榜須對齊窗口、方法與可用性。
- 題材重疊時，候選與持倉曝險不得重複相加。

### 3.3 v1 相容邊界

`hot_group_v1` 仍依 [V1_SPEC](V1_SPEC.md) 的五分項、35／25／15／15／10 權重與至少三位合格成員執行。五分項完整才可稱完整熱門；事件缺失不可填 0。符合既有一致 coverage 條件的四分項結果只可標為 partial 技術與籌碼觀察，不得產生完整熱門候選。

新題材發現或事件方向需另立版本與驗收。完整熱門和事件脈絡是研究背景，不是個股 v1 策略的新硬 gate。

## 4. 籌碼與短線資金（下一版）

外資、投信與自營商分開觀察；「外資」沿用官方外資及陸資合計口徑。有資料時才區分自營商自行買賣／避險，並研究多日持續性與相對成交規模。

後續個股籌碼分為三大法人、由分點統計推導的主力進出、券商分點排行／歷史／券商彙總；融資維持獨立。現有能力只有法人資料與官方人工查詢入口，其餘待做。當沖與分點都不能辨識投資人，大買後次日轉賣也只能稱統計上的反轉特徵；完整定義見 [個股頁 §8](STOCK_RESEARCH_PAGE.md#8-籌碼三部分後續待做)。

## 5. 一檔一張行動摘要與完整交易計畫

現行 DecisionSummary 是聚合層，不是新策略。計畫、預測、模擬成交與使用者實際持倉必須分開。

| 資訊 | 最低契約 |
| --- | --- |
| 標的與時間 | exchange、symbol、as_of、generated_at、decision_at、必要資料可用時間及版本。 |
| 主狀態與理由 | 一個主要行動、主要條件、最多三個可追溯理由與可展開反證。 |
| 進場 | 觸發／確認、區間、不追價上限、最晚有效時間及最早可執行時段。 |
| 失效與退出 | 策略失效和使用者停損分開；目標、移動停利、時間停損與事件失效各有規則。 |
| 風險與部位 | 風險距離、成本／滑價、單筆與同題材曝險；風險預算未知時不給張數。 |
| 替代條件 | 保留各自策略、時間、價位、未通過理由與缺項，不跨策略拼數字。 |
| 資料與機率 | 完整度、規則狀態、關聯證據、校準機率分開；未驗證機率為空。 |
| 追蹤 | 建立、更新／到期、觸發、未成交、模擬成交、退出與結果均版本化。 |

量化規格與驗證以 [STRATEGIES](STRATEGIES.md) 為準；此表是目標契約，不代表現行 API 已提供。

## 6. 行動摘要合併契約

同一標的、同一 as-of 的兩條 v1 策略先各自檢查必要行情、membership／基準、籌碼、eligibility、公司行動、停牌、價位與時間，再聚合。`observation` 表示資料完整但條件未成立；沒有 entry／target／RR 是正常狀態。完整熱門與事件脈絡只作背景。

| 情境 | 主卡 | 次要呈現與限制 |
| --- | --- | --- |
| 一條 conditional；另一條 observation 或 data incomplete | 以 conditional 自己的觸發、失效、目標、RR 與 T+1 顯示「符合條件後可研究進場」。 | observation 有合法等待價位才顯示替代等待條件，否則只列未通過原因；另一策略缺項只作展開揭露，不得降級主卡或補 0。 |
| 兩條 conditional | 保留一張卡；先依最早 T+1，相同時固定以 `breakout_v1` 在 `pullback_v1` 前呈現。 | 另一條完整列為替代條件；兩套價位不可交叉混用。資料 cutoff、價格 basis、標的或執行證據不可調和時改為「需人工判讀」。固定排序不代表信心或採用優先。 |
| 至少一條 observation 有合法等待價位 | 顯示該策略的「等待突破條件」或「等待回踩條件」。 | 只接受 contract 輸出的有限正數門檻，或有限正數且下界不高於上界的區間；等待不是 entry，不補失效、目標或 RR。 |
| observation 無合法等待價位；另一條為 observation 或 data incomplete | 顯示「暫無研究條件／持續觀察」，摘要 `blocking_reasons=[]`。 | 保留各策略未通過理由與個別缺項；不得以高點、MA、最近收盤、0 或破折號造價位，也不得把替代缺項升為整張卡 blocker。 |
| 已驗證持倉風險與任何研究條件並存 | 主卡優先顯示「持倉風險：減碼／退場條件」。 | 使用者停損與策略失效分開；其他條件移到「其他研究條件」並提示不是新增／加碼指令。風險資料待補時不得虛構退場。 |

只有策略必要輸入缺失、已成立條件的價位無效、已知不可執行或證據不可調和，才阻擋該條件。舊、過期或不同 as-of 的策略列只留研究歷史。上述情境是回歸契約，不代表程式或真實市場案例均已驗收。

## 7. API、搜尋與資訊層級

- 目錄採 `page/page_size`；新聞與行動等列表依端點採 `cursor/limit`。列表回傳 items 與 meta，明示排序、分頁和資料截止；標的以 `exchange + symbol` 識別。
- 搜尋只在 Enter／按鈕提交，draft 不呼叫 API；清除後回預設列表。
- 持倉保留新增／更新／刪除、精確股數與每股成本；刪除需明確操作及結果／錯誤回饋。
- enum、raw 與規則版本只在研究／診斷層顯示；日常頁使用 [UI_COPY_SPEC](UI_COPY_SPEC.md) 的中文與單位。
- 自選、來源管理、AI、預測與交易計畫不得因 UI 或 model 有預留欄位就標為完成。

## 8. AI 的角色與完成條件

AI 只用於有來源的事件理解、具明確目標的量化評估及可重現的交易／風險規則；不得自由產生無計算依據的價位，外部內容也不能成為系統或下單指令。驗收方法、機率語意與拒絕判斷條件見 [STRATEGIES](STRATEGIES.md)。

## 9. 保留與暫緩

保留新聞、族群、個股、行動、持倉與追蹤；來源稽核、品質、版本與回測置於次要入口。第一版暫緩盤中即時交易、自動下單、完整財務記帳、大量技術指標與全類型 ETF 專用策略。來源採購、正式資料庫操作及未驗收的新功能不在本規格授權範圍。
