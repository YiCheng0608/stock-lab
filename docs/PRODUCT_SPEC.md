Round14 全站前端 UX 已通過統籌有限 review，輪末索引待複核；逐頁改法、證據與限制見 [Round14 UX review](UX_REVIEW.md)。本輪把列表卡片壓成「辨識資訊＋一個結論＋一至兩個核心數字＋資料日期＋詳情入口」，詳情頁依「結論、關鍵數字、證據／來源、原始診斷」展開。台股使用者介面的已知成交量與法人股數一律換算為「張」（1 張＝1,000 股，最多 3 位小數），負值保留正負號；來源或單位不明時不得臆算。導覽與操作文案採「上一頁／下一頁／儲存／庫存」。這只代表具名的前端呈現與互動，不新增或結清 API units、後端、DB、來源採購或整站資料正確性。

正式資料另已確認存在市場別產業代碼與舊族群 membership 不一致；在資料重建通過前，官方產業排行及其衍生研究條件只能標示「既有族群關聯待重新核實」。族群卡片／詳情可保留中文 `display_name` 供查閱，但須加「（既有分類）」與待核實 badge；原始英文 membership name／ID 留在資料說明，不得改名成看似已修復的分類。這項缺陷不改寫 OHLCV、張數換算或新聞內容的既有契約；修正市場別對照與隔離副本重建屬後續資料正確性工作。

## 1. 產品目標與第一版範圍

每日由新聞／事件與近期強勢題材縮小研究範圍，再綜合個股籌碼、技術結構與公司證據，產出少量可追溯的研究候選與條件式交易計畫。持倉風險與事後追蹤使用同一套證據鏈。

第一版暫以盤後研究、最早下一交易日執行、持有數天至數週的股票 long 策略為設計假設。精確期間和個人風險預算尚待決定；日線不支援盤中精確進出時刻。既有股票／ETF 資料與 v1 政策保留，新增 ETF 專用策略優先度較低。

產品需回答：

1. 有什麼新事件，來源何時可得，與過去消息相比新增了什麼？
2. 哪些產業／題材受影響，市場熱度在擴散還是集中？
3. 哪些個股的公司品質、事件機會、交易位置與風險值得研究？
4. 什麼條件成立才進、何時不追、何時退出、能承受多少損失？
5. 當時判斷的依據與後續結果如何，新增資料／AI 是否提供增益？

公司品質、事件機會、交易位置、持倉風險分開呈現，不用單一「好股分數」掩蓋矛盾。熱度與利多不等於合適買點；任何資料缺漏均保留其用途範圍。

## 2. 主導航與資訊順序

| 路由 | 名稱 | 優先回答 |
| --- | --- | --- |
| / | 今日 | 市場狀態、重大事件、值得觀察的族群／個股及持倉風險。 |
| /news、/news/:id | 新聞 | 新資訊、事件來源、相關標的與已知／推論／未知的影響。 |
| /themes、/themes/:id | 族群 | 官方產業與題材、熱度變化、擴散、領漲集中度和資料限制。 |
| /stocks、/stocks/:exchange/:symbol | 個股 | 四個判斷面向、條件計畫與完整證據。 |
| /actions | 行動 | 持倉風險、有效計畫、待觸發／到期／暫無條件與資料待補。 |

主導航仍只有五個。/research/backtest、/research/coverage、/research/strategies、/system/data-quality、/glossary 保留為研究／診斷入口。舊 groups、instruments、signals、tracking、portfolio、backtest 路由可相容轉向，不再維護兩套主導航。

首頁順序為市場與事件 → 族群／題材 → 今日關注股票。持倉風險在個股／行動排序中優先。以 exchange + symbol + as_of 去重，一檔最多一張壓縮卡；卡片只留一個結論、主要原因、關鍵價位及資料時間。詳細來源、替代條件與 raw 在詳情展開。

候選不足可以為零，不以填滿清單驗收。已核實事件可提高觀察或補資料優先度，但不能替代策略必要輸入。

### 2.1 個股研究頁的近期交付

`/stocks/:exchange/:symbol` 應先把既有資料整理成可完成一次研究判讀的頁面，而不是等待新 AI、完整交易計畫或策略換版：

1. 身分、最近資料日、實際回傳區間、筆數、來源與價格口徑先說清楚；最多 120 根只代表本次 API 視窗，不稱完整歷史。
2. 以既有 `bars` 的 `open`／`high`／`low`／`close`／`volume` 顯示日 K、成交量與 MA20／MA60。每個均線點須有足夠的既有收盤資料；不足、空值、無效 OHLC 或重複日期不可補值、猜測或跨缺口偽造。
3. 圖表提供日期與 OHLCV 提示、縮放與復位；圖表不是唯一資訊通道，鍵盤與輔助技術使用者須有等效可讀的日期／OHLCV 資料。
4. 依研究順序呈現既有行動摘要、族群、法人籌碼、官方事件／新聞、策略條件與資料品質。策略需求清單不等於條件已成立；事件列與新聞列也不能只因同頁呈現就混成同一種證據。
5. K 線直接使用 API 的原始 OHLC。現有 payload 雖另有 `adj_close`，卻沒有 OHLC 的還原／調整 basis 或因子，所以頁面須標「原始 API 價格；還原方式未提供」，不得宣稱已確認為還原價或未還原價，也不得用單一 `adj_close` 拼造調整後 K 線。

本批不新增評分、預測機率、外資身分推論、ATR 切換、策略績效、PIT 證據或完整 trade plan。原 B2 legacy／new comparison 與 B7 paired replay 只是延後，驗收條件不刪除。

## 3. 事件與族群研究（下一版）

### 3.1 新聞不只計篇數

新聞輸出須包含：事件類型、新增資訊、相關公司／題材、影響方向及期間、傳導理由、來源、反面證據、可用時間與判讀方法。同一事件轉載合併呈現，不重複加分；利空事件不能因公告數多而增加正向機會分數。

「價格是否已反映」以消息前後的相對報酬、量能、跳空與價格延伸作觀察，標明窗口和不確定性；不宣稱知道市場已完全定價。欄位與來源准入見 [新聞規格](NEWS_SPEC.md)。

### 3.2 官方產業與市場題材分開

- 官方產業沿用交易所映射，保留交易所 namespace、名稱來源與生效日。
- 題材可跨產業，一家公司可多重歸屬；每條 membership 需有原始證據、關聯方式、相關程度、生效／失效日及版本。
- 模型提出的題材關聯先標待核實，不直接轉為已確認的產業分類或買賣理由。
- 族群卡同時呈現熱度、1／5／20 日變化、廣度、領漲股與集中度、籌碼分歧、價格延伸、事件方向及各域 coverage。
- 同榜比較須對齊資料窗口、方法與可用性；題材重疊時，候選及持倉總曝險不得重複相加。

### 3.3 v1 相容邊界

hot_group_v1 仍按 [V1_SPEC](V1_SPEC.md) 的五分項、35／25／15／15／10 權重與至少三位合格成員規則執行。五分項完整才稱 v1 完整熱門；事件缺失不可填 0。四分項觀察僅在既有一致 coverage 規則下呈現為 partial，不能直接產生完整熱門候選。

這是 v1 規則，不是新題材模型已完成的證據。新題材發現／事件方向需另立版本和驗收，不可借新名稱放寬舊 gate。個股策略自身的完整條件，仍可獨立於完整熱門標籤出現在行動中心。

## 4. 籌碼與短線資金（下一版）

分開觀察外陸資、投信、自營商；資料可取得時再區分自營商自行買賣／避險。使用多日持續性、相對成交規模、分點集中／反轉及價格反應，不能只看三大法人合計正負。

當沖比例是股票層的交易活動；分點是交易通道的彙總，不能等同投資人身分。分點「前日大買、次日轉賣」可建立可重現的描述特徵，但只稱疑似短線資金／反轉風險，不確定指認某個外資在隔日沖。風險特徵也不必然代表股價將跌。

資料缺少時不給精確機率或主力標籤；欄位存在不代表已收集。來源、時間修訂與單位口徑見 [資料來源](DATA_SOURCES.md)。

## 5. 一檔一張行動摘要與完整交易計畫

現行 DecisionSummary 是產品聚合層，不是新的策略版本。下一版在保留聚合規則下加入交易計畫；計畫、預測、模擬成交與使用者實際持倉必須區分。

| 資訊 | 最低契約 |
| --- | --- |
| 標的／時間 | exchange、symbol、as_of、generated_at、決策時間、來源實際可用時間、版本。 |
| 主狀態／理由 | 一個主要行動、主要條件與最多三個可追溯理由；反面證據可展開。 |
| 進場 | 觸發類型、確認方式、進場區間、最晚有效時間、不追價上限、最早可執行時段。 |
| 失效／退出 | 策略失效與使用者停損分開；目標、移動停利、時間停損、事件失效各有判斷規則。 |
| 風險與部位 | 風險距離、成本／滑價假設、單筆與同題材曝險；風險預算未知時不給具體張數。 |
| 替代條件 | 每條保留自身策略、時間、價位、未通過理由、缺項；不跨策略拼數字。 |
| 資料與機率 | 資料完整度、規則狀態、關聯證據與已校準預測機率分開。無驗證的機率為空。 |
| 追蹤 | 計畫建立、更新／到期、觸發、未成交、模擬成交、退出及結果的版本化紀錄。 |

進出場計畫的量化規格與驗證以 [STRATEGIES](STRATEGIES.md) 為準。新計畫欄位是目標契約，不能假設現行 API 已提供。

## 6. 行動摘要合併契約

本節承接舊 Phase 3 §4.5 的 A–E 矩陣，適用同一標的、同一 as-of 的兩條 v1 策略，不受舊 2026-09-08 單日驗收限制。

先個別檢查必要行情、membership／基準、籌碼、標的資格、公司行動、停牌、價位及時間，再聚合。完整 observation 代表資料完整、條件尚未成立；沒有 entry／target／RR 是正常狀態。完整熱門與事件脈絡是背景，不是兩個 v1 策略的新硬 gate。

| 合併情境 | 主卡狀態與價位 | 次要條件／背景的呈現 | 不可做的事 |
| --- | --- | --- | --- |
| A．一條完整且已符合條件＋另一條完整觀察條件 | 以已符合條件的策略顯示「符合條件後可研究進場」、它自己的觸發／失效／目標／RR 與最早 T+1。 | 若 observation contract 有合法等待價位，才顯示「替代條件：等待突破／等待回踩」；沒有時寫「替代策略：本次條件未成立」，只保留未通過理由。觀察條件沒有 entry／目標是正常的，不列為缺項。 | 不得因替代 observation 沒有完整價位或等待價位，把主卡改成「策略判斷資料待補」。 |
| B．一條完整且已符合條件＋另一條策略資料待補 | 同 A；主卡仍由已完整條件產生。 | 在可展開區顯示「主研究條件資料完整；另一研究條件資料待補：<精確缺項>」。 | 不得把整張卡改為資料待補、隱藏主策略價位，或用另一策略的 0／空值補算。 |
| C．兩條都完整且已符合條件 | 若兩組證據可共存，維持一張卡。先取最早可執行的 T+1；相同時以 `breakout_v1` 在 `pullback_v1` 前作**固定呈現排序**，不是信心、報酬或採用排序。主條件照自身價位顯示。 | 另一組完整條件顯示為「替代條件」，保留自己的觸發／失效／目標／RR 與 T+1，並說明「兩組價位不可交叉混用」。 | 不得把兩組 entry、失效價、目標或 RR 拼成一組；不得因分數較高或預期報酬較大任意選主條件。若資料截止日、除權息調整基礎、標的識別或執行狀態互相無法調和，改為「需人工判讀」，不合成進場價位。 |
| D-1．至少一條完整 observation 有合法等待價位 | 只有該 observation contract 明確輸出有限、合法的等待突破門檻或回踩區間時，才顯示「等待突破條件」或「等待回踩條件」。 | 另一條若也有合法等待價位，顯示為替代等待條件；若資料待補，顯示其精確缺項。等待價位只作觀察，不替代 entry／失效／目標／RR。 | 不得以既有高點、MA 或最近收盤臆造等待價位，也不得把另一策略待補升格為整張卡的 blocker。 |
| D-2．一條完整觀察條件沒有合法等待價位＋另一條策略資料待補 | 主狀態為「暫無研究條件／繼續觀察」，摘要 `blocking_reasons=[]`。 | 保留完整觀察條件的未通過 rule reasons；另一策略的缺項只在該策略區塊顯示「另一研究條件資料待補：<精確缺項>」。 | 不得將整張卡標為資料待補、填入 0／破折號或虛構 entry、目標、RR。 |
| D-3．兩條完整觀察條件且都沒有合法等待價位 | 主狀態同為「暫無研究條件／繼續觀察」，摘要 `blocking_reasons=[]`。 | 保留 breakout 與 pullback 各自未通過理由，供研究詳細頁展開；沒有價位就不顯示價位區塊。 | 不得把「條件未成立」翻成缺少資料或把正常 observation 放入資料待補清單。 |
| E．已驗證持倉風險與任一策略條件同時存在 | 已驗證的使用者停損、策略失效或退場條件一律優先，主卡為「持倉風險：減碼／退場條件」。 | 原本完整的進場／等待條件可放在「其他研究條件」，並明示「持倉風險優先處理；此處不是新增／加碼指令」。使用者停損與策略失效價分別標示。 | 不得以新的進場條件壓過已驗證風險，也不得自動下單。若持倉風險資料本身待補，只能顯示「持倉風險資料待補」，不能虛構減碼／退場；其餘策略再依 A–D 判定。 |

合法等待價位必須由該策略的 observation contract 輸出；摘要層不可憑均線／高點補造。突破門檻須有限正數，回踩區間須有限正數且下界不高於上界；等待不是已成立進場。若現行規則未提供等待價位，就顯示「暫無研究條件」。

真正缺少該策略必要輸入、已成立條件卻價位無效、已知無法執行或不可調和的證據，才阻擋該條件。舊、過期或不同 as-of 的策略列保留歷史，不混入當日摘要。已核實持倉風險優先；未知風險不虛構退場。

A–E 是回歸驗收案例，不是每種情境都必須在真實市場當天發生，也不表示本輪已完成程式驗收。

## 7. API、搜尋與資訊層級

- 目錄採 page／page_size，新聞與行動等列表依端點採 cursor／limit；不得把目標欄位清單當現有完整能力。
- 搜尋只在 Enter／搜尋按鈕提交；draft 不觸發 API，清除後回到預設列表。
- 列表至少回傳 items 與 meta，明示排序、分頁、資料截止；exchange + symbol 為標的識別。
- 新聞詳情與來源時間 keyset 邏輯已在程式出現，完整規格及待驗收邊界見 [NEWS_SPEC](NEWS_SPEC.md)。
- 持倉保留新增／更新／刪除、精確股數與每股成本；刪除需明確操作及結果／錯誤回饋，可採確認或可恢復設計。
- API 中的 enum、raw、規則版本保留於研究／診斷，日常使用中文標籤。完整對照與單位規則見 [UI_COPY_SPEC](UI_COPY_SPEC.md)。
- 自選 API／來源管理／AI／預測及交易計畫擴充不得僅因 UI 或 model 有欄位就標為完成。

## 8. AI 的角色與完成條件

AI 分三部分：有來源的事件理解、明確預測目標的量化評估、可重現的交易／風險規則。LLM 不自由報出無計算依據的價位；外部文章內容當資料，不當操作或下單指令。

驗收關注：來源忠實與去重、時間無洩漏、樣本外表現、機率校準、成本後報酬／回撤與可成交性。固定規則分數不稱勝率，模型可以拒絕判斷，沒有候選是合法結果。完整驗證方案見 [STRATEGIES](STRATEGIES.md)，實作順序見 [ROADMAP](ROADMAP.md)。
