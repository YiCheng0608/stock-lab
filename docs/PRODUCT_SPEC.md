# 台股事件、族群與交易研究產品規格

本文只定義現行產品方向與目標契約；能力狀態與優先順序見 [ROADMAP](ROADMAP.md)，未列為已有能力的欄位或流程都是目標。

## 1. 產品目標與第一版範圍

產品以新聞／事件與近期強勢題材縮小研究範圍，再綜合個股籌碼、技術結構與公司證據，產出少量、可追溯的研究候選與條件式交易計畫；持倉風險與事後追蹤沿用同一證據鏈。第一版定位為研究輔助 app，範圍為台灣上市／上櫃全部普通股，每日排程更新行情、籌碼、新聞、熱門族群、候選與進出點；版本邊界與 gate 見 [ROADMAP V1 基線](ROADMAP.md#v1-範圍基線2026-10-17-核定)。第一版假設為盤後研究、最早下一交易日執行、持有數天至數週的股票 long 策略。精確期間與個人風險預算尚待決定；日線不支援盤中精確進出。來源政策見[資料來源](DATA_SOURCES.md)，ETF 適用範圍見 [V1_SPEC](V1_SPEC.md#價位etf-與生命週期)。

公司品質、事件機會、交易位置與持倉風險必須分開呈現。熱度、利多與規則通過都不等於合適買點，不用單一「好股分數」掩蓋矛盾；缺資料與 LLM 推論的顯示依 [ROADMAP 顯示原則](ROADMAP.md#v1-範圍基線2026-10-17-核定)。

## 2. 主導航與資訊順序

| 路由 | 名稱 | 優先回答 |
| --- | --- | --- |
| `/` | 今日 | 明日候選與其價位、大盤概況、熱門族群與重大事件、持倉風險提示。 |
| `/news`、`/news/:id` | 新聞 | 新資訊、來源、相關標的與已知／推論／未知的影響。 |
| `/themes`、`/themes/:id` | 族群 | 官方產業與題材、熱度、廣度、集中度及資料限制。 |
| `/stocks`、`/stocks/:exchange/:symbol` | 個股 | 四個判斷面向、條件計畫與完整證據。 |
| `/actions` | 行動 | 持倉風險、今日候選與其他成立條件、接近成立的標的；其他觀察與資料待補預設收合（[UI_COPY_SPEC §5](UI_COPY_SPEC.md#5-行動中心的分級與預設篩選)）。 |

行動頁的分級是列表排序，不改變 [§6](#action-merge) 的行動摘要判定；每列的狀態、價位與理由仍來自該檔的行動摘要。`/actions/:exchange/:symbol` 轉到個股頁的「研究條件」分頁（`/stocks/:exchange/:symbol?tab=research`），不另設行動詳情頁。

主導航維持五個；研究（`/research/*`）、系統資料品質（`/system/data-quality`）與詞彙（`/glossary`）為次要入口，不另設第二套主導航。

個股頁（`/stocks/:exchange/:symbol`）依序為：頁首（代號、名稱、最近收盤與資料日期）→ 分頁「圖表與指標／法人籌碼／新聞與公告／研究條件／資料說明」。「研究條件」分頁依序為：**策略總表**（每個已登錄的策略一列：狀態成立／觀察／資料不足／不適用、差哪個條件、價位；該股是資料日的每日候選時，最上方一列候選資訊與 AI 推論）→ 研究動作（行動摘要）→ 所屬族群。策略總表的成立價位讀訊號、觀察價位讀條件價位（[V1_SPEC](V1_SPEC.md#strategy_levels_v1)），兩者分開呈現，觀察價位只在個股頁出現，行動頁、今日頁、行動摘要與追蹤計畫都不讀（#268、#274）。文案見 [UI_COPY_SPEC §10.1](UI_COPY_SPEC.md#101-個股策略總表)。

首頁依序為：頁首資料列（資料日期、來源、品質）→ 大盤概況（上市／上櫃指數、成交金額、漲跌家數，壓成一列）→ 持倉風險提示 → 明日候選（第一焦點，依名次列出價位）→ 熱門族群與重點新聞 → 關注標的。有已驗證持倉風險時，在候選之上顯示一列提示並連到行動中心，不把候選推出第一屏。同一 `exchange + symbol + as_of` 只顯示一張卡，正面保留辨識資訊、一個結論、一個主要原因、一至兩個核心數字、資料日期與詳情入口。候選為零是合法結果。

## 3. 事件與族群研究

- **新聞不只計篇數**：交代新增資訊、相關標的、影響與反證、來源、可用時間及判讀方法；「價格是否已反映」只作具名窗口的市場反應觀察。去重、計分與時間規則見[新聞規格](NEWS_SPEC.md)。
- **官方產業與市場題材分開**：官方產業保留交易所 namespace、名稱來源與生效日；題材可跨產業且一家公司可多重歸屬，每條題材 membership 需有原始證據、關聯方式、相關程度、生效／失效日及版本。模型提出的關聯先標待核實，不可變成官方分類或買賣理由。
- **族群卡**：呈現 1／5／20 日熱度變化、廣度、領漲集中度、籌碼分歧、價格延伸、事件方向與各域 coverage；同榜須對齊窗口、方法與可用性。題材重疊時，候選與持倉曝險不得重複相加。
- **hot_group_v1**：分項、權重與完整熱門條件見 [V1_SPEC](V1_SPEC.md#hot_group_v1)；新題材發現或事件方向另立版本。完整熱門和事件脈絡是研究背景，不是個股 v1 策略的硬 gate。

## 4. 籌碼與短線資金

個股籌碼分為三大法人與融資，皆來自官方整批資料；外資、投信與自營商分開觀察（口徑見[資料來源](DATA_SOURCES.md#法人口徑)），有資料時才區分自營商自行買賣／避險，並研究多日持續性與相對成交規模。券商分點列後版。

## 5. 一檔一張行動摘要與完整交易計畫

DecisionSummary 是聚合層，不是新策略。計畫、預測、模擬成交與使用者實際持倉必須分開。

| 資訊 | 最低契約 |
| --- | --- |
| 標的與時間 | exchange、symbol、as_of、generated_at、decision_at、必要資料可用時間及版本。 |
| 主狀態與理由 | 一個主要行動、主要條件、最多三個可追溯理由與可展開反證。 |
| 進場 | 觸發／確認、區間、不追價上限、最晚有效時間及最早可執行時段。 |
| 失效與退出 | 策略失效和使用者停損分開；目標、移動停利、時間停損與事件失效各有規則。 |
| 風險與部位 | 風險距離、成本／滑價、單筆與同題材曝險；風險預算未知時不給張數。 |
| 替代條件 | 保留各自策略、時間、價位、未通過理由與缺項，不跨策略拼數字。 |
| 資料與機率 | 完整度、規則狀態、關聯證據、校準機率分開；未驗證機率為空。 |
| 追蹤 | 建立、更新／到期、觸發、未成交、模擬成交、退出與結果均版本化。 |

策略公式與口徑以 [V1_SPEC](V1_SPEC.md) 為準；此表是目標契約，不代表 API 已提供每個欄位。

## 6. 行動摘要合併契約

同一標的、同一 as-of 的兩條 v1 策略先各自檢查必要行情、membership／基準、籌碼、eligibility、公司行動、停牌、價位與時間，再聚合。`observation` 表示資料完整但條件未成立；沒有 entry／target／RR 是正常狀態。完整熱門與事件脈絡只作背景。

| 情境 | 主卡 | 次要呈現與限制 |
| --- | --- | --- |
| 一條 conditional；另一條 observation 或 data incomplete | 以 conditional 自己的觸發、失效、目標、RR 與 T+1 顯示「符合條件後可研究進場」。 | observation 有合法等待價位才顯示替代等待條件，否則只列未通過原因；另一策略缺項只作展開揭露，不得降級主卡或補 0。 |
| 兩條 conditional | 保留一張卡；先依最早 T+1，相同時固定以 `breakout_v1` 在 `pullback_v1` 前呈現。 | 另一條完整列為替代條件；兩套價位不可交叉混用。資料 cutoff、價格 basis、標的或執行證據不可調和時改為「需人工判讀」。固定排序不代表信心或採用優先。 |
| 至少一條 observation 有合法等待價位 | 顯示該策略的「等待突破條件」或「等待回踩條件」。 | 只接受 contract 輸出的有限正數門檻，或有限正數且下界不高於上界的區間；等待不是 entry，不補失效、目標或 RR。 |
| observation 無合法等待價位；另一條為 observation 或 data incomplete | 顯示「暫無研究條件／持續觀察」，摘要 `blocking_reasons=[]`。 | 保留各策略未通過理由與個別缺項；不得以高點、MA、最近收盤、0 或破折號造價位，也不得把替代缺項升為整張卡 blocker。 |
| 已驗證持倉風險與任何研究條件並存 | 主卡優先顯示「持倉風險：減碼／退場條件」。 | 使用者停損與策略失效分開；其他條件移到「其他研究條件」並提示不是新增／加碼指令。風險資料待補時不得虛構退場。 |

只有策略必要輸入缺失、已成立條件的價位無效、已知不可執行或證據不可調和，才阻擋該條件。舊、過期或不同 as-of 的策略列只留研究歷史。

## 7. API、搜尋與資訊層級

- 目錄採 `page/page_size`；新聞與行動等列表依端點採 `cursor/limit`。列表回傳 items 與 meta，明示排序、分頁和資料截止；標的以 `exchange + symbol` 識別。
- 搜尋只在 Enter／按鈕提交，draft 不呼叫 API；清除後回預設列表。
- 持倉保留新增／更新／刪除、精確股數與每股成本；刪除需明確操作及結果／錯誤回饋。
- enum、raw 與規則版本只在研究／診斷層顯示；日常頁使用 [UI_COPY_SPEC](UI_COPY_SPEC.md) 的中文與單位。
- 自選、AI、預測與交易計畫不得因 UI 或 model 有預留欄位就標為完成。

## 8. AI 的角色與完成條件

AI 只用於有來源的事件理解、具明確目標的量化評估及可重現的交易／風險規則；不得自由產生無計算依據的價位，外部內容也不能成為系統或下單指令。勝率或機率需事先定義目標、採用門檻與樣本外證據才可顯示，未驗證時為空。

## 9. 保留與暫緩

來源稽核、品質、版本與回測置於次要入口。第一版另不含完整財務記帳、V1 指標集以外的技術指標與全類型 ETF 專用策略；其他不做事項見 [ROADMAP](ROADMAP.md#保留的產品取捨)。
