# 策略證據

策略的每個條件與評分的每個權重，都要說得出「為什麼相信它有用」。本文定義什麼算證據、用哪兩個工具量、結果怎麼用。策略公式見 [Canonical v1 規格](README.md)，評分見 [candidate_score](candidate_score.md)，進出場模擬的口徑見 [tracking](tracking.md#tracking-與-technical-backtest-口徑)。

## 兩個問題、兩個工具

| 問題 | 工具 | 讀什麼 |
| --- | --- | --- |
| 上線以來實際列出的候選，之後表現如何？ | `tools/research/candidate_scorecard.py` | `daily` 當晚存下的 `daily_candidates`，不重算 |
| 某個特徵或條件，對之後的報酬有沒有預測力？ | `tools/research/feature_evidence.py` | 日線、籌碼、月營收 |

命令與參數見 [CLI](../ops/CLI.md#測試與驗證)。兩個工具都只讀正式 DB 的唯讀副本（`tools/ops/copy_db.py`），不需要先跑研究回測，全範圍約數分鐘。

## 共同口徑

- **報酬**：T 是資料日，T+1 開盤買進（含 5 bps 滑價），T+5 或 T+20 收盤計價，單純持有，不套用停損與目標。這量的是「選得好不好」，和「怎麼出場」分開；出場規則另以研究回測評估（[出場規則研究](#出場規則研究)）。
- **可比較**：T 之後的 N 個交易日每天都有日線、沒有停牌才算；其餘不計，不補值。T+N 還沒到的記「未到期」。
- **還原**：除權息與分割以產品自己的價格因子換算到同一基準。
- **母體**：當日有成交、沒有停牌、20 日均量達 1,000 張的股票與 IPO（與候選池的流動性門檻相同）。依 `instrument_type` 取，不看現在的 `status`，所以之後下市的股票在它有交易的日子仍在母體裡。
- **超額報酬**：減去同日母體的等權平均。它不受成本假設影響。
- **成本**：成績單另列扣成本的報酬，預設來回 58.5 bps（兩次手續費 0.1425% 加證交稅 0.3%，未折讓）。
- **切分**：探索段 2024-09-30～2025-12-31，驗證段 2026-01-01 起，與 #567 相同，在看任何結果前固定。
- **t 值**：N 日報酬逐日重疊，所以天數以「日數 ÷ N」計。這是保守的下限，不是精確檢定。

## 特徵的判定

每個交易日算特徵與之後報酬的排序相關（IC），以及依特徵排序分成五組的平均超額報酬與五分位差（最高一組減最低一組）；再對各段的日子取平均。

**分組**（`feature_evidence.day_spread`）：依名次分五組，同值共用平均名次、落在同一組。最高與最低一組都有股票時，五分位差＝最高一組減最低一組（中間某組為空不影響），與第 1 版相同。同值讓最高或最低一組整段為空、五分位差算不出時（離散值特徵，例如 0～5 的天數、0／1 的旗標），當日改成高低兩組：在相鄰兩個不同值之間切一刀，同值不拆開，取兩邊檔數最接近的切點（一樣接近取較低的），五分位差＝高的一邊減低的一邊。當日只有一種值時 IC 算不出來，那天不計。報告在五分位差旁標「兩組」與日數。

**判定**寫死在 `feature_evidence.judge`，由上往下取第一個符合的列：

| 判定 | 條件 |
| --- | --- |
| 無法判定 | 探索段不足 60 日 |
| 沒有證據 | 探索段 \|IC\| < 0.02、\|t\| < 2 或 IC 為 0（探索段沒有選出） |
| 無法判定 | 探索段五分位差缺值 |
| 沒有證據 | 探索段五分位差和 IC 異號或為 0（探索段沒有選出） |
| 無法判定 | 驗證段不足 60 日 |
| 驗證段反轉 | 驗證段 IC 和探索段異號 |
| 沒有證據 | 驗證段 IC 為 0 |
| 無法判定 | 驗證段五分位差缺值 |
| 方向一致但不顯著 | 驗證段五分位差和探索段 IC 異號或為 0 |
| 方向一致但不顯著 | 驗證段 \|t\| < 2 |
| 有證據 | 其餘：探索段至少 60 日、\|IC\| ≥ 0.02、\|t\| ≥ 2、五分位差同號；驗證段至少 60 日、IC 與五分位差都和探索段同號，且 \|t\| ≥ 2 |

「探索段選出」是前四列都不符合。條件（見下一段）沒有五分位差，跳過五分位差的四列，其餘相同（看平均超額報酬，探索段不設 0.02 的下限）。

IC 為負也可以是證據（例如某個值越低、之後越好），用的時候方向要跟著反過來。現行規則的各個條件（突破、回踩、法人、融資）以同一套規則判定，量的是符合條件者的每日平均超額報酬。

## 研究規則

1. **先有證據再進策略**。要新增條件或調整評分權重，先把特徵加進 `feature_evidence.FEATURES` 跑出判定；只有「有證據」可以當依據。「方向一致但不顯著」只記錄、之後重跑。
2. **現行條件一視同仁**。現行規則的條件若是「沒有證據」或「驗證段反轉」，在 Issue 提案移除或改為只顯示；採不採用屬範圍變更，由使用者決定。
3. **不看完結果再改尺**。門檻、切分、母體與報酬口徑在跑之前固定；要改就另開版本，並在報告寫明改了什麼、為什麼。
4. **記比較次數**。報告寫明同時比較了幾組特徵與期間；組數越多，碰巧通過的越多。新增特徵時組數跟著加。
5. **特徵升為條件時才跑研究回測**。`backtest_research.py` 回答的是進出場模擬後的結果，一次要數小時；先用本文的工具篩過再跑。
6. **停手條件**。連續兩輪研究都沒有新的「有證據」，就停止同一類研究（例如對現行兩條規則加減條件），在 [#1](https://github.com/YiCheng0608/stock-lab/issues/1) 向使用者回報並提出換方向或補資料的建議。
7. **成績單每月重跑一次**，結果貼在當期的研究 Issue；它是持續累積的紀錄，不是勝率，畫面不引用。
8. **照實寫**。報告列全部特徵與條件，不挑有利的；兩種看法結論不一致時兩個都寫。

| 版本 | 任務 | 改了什麼 |

| 1 | #616 | 第一版；#619 的第一輪報告用這版。離散值特徵的五分位差永遠缺值，五分位差缺值或異號一律記「沒有證據」 |

## 出場規則研究

這一段回答：現行兩條進場規則的訊號，用哪一種出場最好（[#673](https://github.com/YiCheng0608/stock-lab/issues/673)，規則與判定在統籌決定 [6846697843](https://github.com/YiCheng0608/stock-lab/issues/673#issuecomment-6846697843) 時固定，看結果前不改）。研究只產報告，不改產品的出場規則。

**樣本**
- 在 `copy_db.py` 副本上跑 `backtest_research.py --start 2024-09-30 --end <副本最新交易日> --slim`，只跑 canonical 策略。
- 取這個 run 的可行動訊號，以及訊號存的價位：觸發價或進場區、停損、目標一、目標二。

**工具**
- 命令：`python tools/research/exit_research.py --db <副本> --run-id <run> --out <目錄> [--min-free-gb 2]`。
- 只讀：`mode=ro`＋`query_only`。
- 拒絕的情況：正式 DB、台北 21:30～23:30、可用記憶體不足。
- run 必須是 `success`。
- 輸出：`summary.md`、`tables.json`、`trades.csv`。

**重現檢查**
- 先把現行出場（E0）照產品慣例重算：用 `app.tracking.track_path`／`settle` 與 run 的 20 根，逐筆對 run 寫的 T+20 settlement。
- 有任何一筆不一致就停下（exit 4，寫 `mismatches.json`），不算替代規則。

**進場**：每條出場規則都共用同一個進場，所以可以逐筆配對比較。
- 成交與不進場照 `tracking_v2`（[tracking](tracking.md#口徑版本)），視窗是訊號日後 20 根。
- 一字鎖漲停（當根最低 ≥ 漲停價）買不到，下一根再判斷。
- 漲跌停價：前一根收盤換到當根的價格基準後 ±10%，照升降單位取整。漲停往下取、跌停往上取，同 [strategy_levels](strategy_levels.md)。ETF 不判斷漲跌停。

**出場慣例**：所有規則都一樣，現行 E0 也套用。
- 停損與目標：開盤已越過價位就用開盤價，否則用價位，賣出扣 5 bps。
- 同一根停損與目標都碰到：當成停損先。
- 一字跌停（當根最高 ≤ 跌停價）賣不出去，順延到下一根開盤。
- 成交後有停牌或缺日線：該筆不可比較。日線不夠：記「未到期」。
- 成本：來回 58.5 bps（[共同口徑](#共同口徑)），報酬以訊號日的價格基準計。

**規則**（R＝(目標一 − 停損) ÷ 2.6，即 `risk_levels` 的 R）

| 代號 | 規則 |
| --- | --- |
| E0（現行） | 停損＝失效價；碰到目標一出場；都沒碰到，以訊號日後第 20 根收盤出場 |
| E1 | 同 E0，目標改成目標二（3R） |
| T1／T2／T3 | 移動停利：起始停損＝失效價，沒有目標；每根收盤後停損＝max(原停損, 成交以來最高收盤 − k·R)，下一根起生效，k＝1.0／1.5／2.0；都沒觸發，以第 20 根收盤出場 |
| H5／H10／H20 | 時間出場：停損＝失效價，沒有目標；成交那一根算第 1 根，第 N 根收盤出場 |

**指標**：依訊號日分探索段與驗證段（[共同口徑](#共同口徑)的切分）。每個「策略 × 規則 × 段」列出：
- 筆數
- 每筆扣成本報酬的平均與中位
- 勝率（報酬 > 0）
- 平均持有根數
- 最大回撤：每筆等額，依出場日累加報酬，取這條曲線的最大回撤
- 每日平均的 t：同一訊號日先平均，天數以「日數 ÷ 20」計，每條規則都一樣

**配對差**
- 每條替代規則：逐筆算「替代 − E0」，只取兩條規則都可比較的筆，依訊號日平均。
- 另列「E0 研究慣例 − E0 產品慣例」（產品慣例的報酬換成同樣 58.5 bps 的成本），量化產品追蹤沒有處理的三件事：跳空越過停損仍用停損價、沒有漲跌停、同根兩者都碰到記不可比較。各情況的筆數一併列出。

**判定**：寫死在 `exit_research.judge`，對每個「策略 × 替代規則」由上往下取第一個符合的列。

| 判定 | 條件 |
| --- | --- |
| 無法判定 | 任一段有配對的訊號日 < 60 |
| 勝過現行 | 兩段的配對差日均都 > 0，且 t 都 ≥ 2 |
| 不如現行 | 兩段的配對差日均都 < 0，且 t 都 ≤ −2 |
| 沒有差異 | 探索段 \|t\| < 2 |
| 驗證段反轉 | 驗證段與探索段異號 |
| 方向一致但不顯著 | 其餘：驗證段同號但 \|t\| < 2 |

**怎麼讀結果**
- 「穩定勝過現行」只認「勝過現行」。勝率與回撤只列出，不參與判定。
- 同時比較 7 條替代規則 × 2 條策略＝14 組（研究規則第 4 條）。
- 結果支持改出場時，另開單由使用者決定。

## 組合層級回測

這一段回答：照名單每天買前 N 檔、持有 K 天，資金曲線贏不贏加權指數（[#682](https://github.com/YiCheng0608/stock-lab/issues/682)，設計在統籌決定 [6870690506](https://github.com/YiCheng0608/stock-lab/issues/682#issuecomment-6870690506) 時固定，看結果前不改）。它是之後評分改版與任何規則改動有沒有用的尺；研究只產報告，不改產品。

**樣本**
- 訊號：[出場規則研究](#出場規則研究)那次研究回測 run 的可行動訊號，讀 `exit_research.py` 輸出的 `trades.csv`（`signal_id`、策略、`instrument_id`、代號、訊號日），不重跑研究回測。報告寫明 CSV 的來源 commit 與 sha256。
- 價格、還原因子、籌碼：新的 `copy_db.py` 唯讀副本。CSV 每一列的代號都要和副本的同一個 `instrument_id` 相同，否則停下（exit 4，寫 `mismatches.json`）。
- 期間：第一個訊號日的下一個交易日起，到 `--cutoff`（預設最後一個訊號日）收盤；之後的日線不用。

**工具**
- 命令：`python tools/research/portfolio_research.py --db <副本> --signals <trades.csv> --signals-source <來源> --out <目錄> [--cutoff <日>] [--min-free-gb 2]`。
- 只讀：`mode=ro`＋`query_only`。拒絕的情況同[出場規則研究](#出場規則研究)：正式 DB、台北 21:30～23:30、可用記憶體不足。
- 輸出：`summary.md`、`tables.json`、`equity.csv`（每日淨值）、`picks.csv`（每日排序）、`trades.csv`（前 N 名與候選池的每筆，母體只列計數）。

**排序**：`candidate_score_v7` 去掉新聞與族群，報告標題與每張表都寫明，不當成當晚實際名單。
- 候選池照 v7：run 的可行動訊號、`stock`／`ipo`、T 日有非停牌日線、20 日均量 ≥ 1,000 張。run 的可行動訊號含 ETF，不入池，報告的候選池計數列為 `not_stock_or_ipo`。
- technical（0.35）與 chips（0.30）照 v7 公式重算（`worker.candidates` 的子項、percentile 母體與方向），權重只在兩者之間重新正規化。
- news（0.15）與 group（0.20）拿掉：新聞 AI 判讀只有近期才有，歷史族群分數不保證當日可得，重放會偷看未來或大部分日子缺值。
- technical 沒有值的訊號不入池。同一檔兩策略都入池留總分高者（同分取 breakout），排序鍵與 tie-break 照 v7。

**持有與資金**（`portfolio_research.simulate`）
- N ∈ {5, 10, 20}，K ∈ {5, 10, 20} 個交易日。
- 資金分成 K 份子帳戶，第 i 份只在期間的第 i、i+K、i+2K… 個交易日進場：T 日的名單在 T+1 開盤買，該子帳戶當時的現金等權分給入選的檔，每檔上限是子帳戶的 1/N，不足 N 檔的部分留現金。
- 成交那根算第 1 根，第 K 根收盤賣，回收的錢在該子帳戶下一輪再投入。純持有，不套停損與目標。
- 不考慮整張、零股與成交量限制，金額按比例。

**成本與漲跌停**
- 買：開盤價＋5 bps 滑價，手續費 0.1425%。賣：收盤價（或順延的開盤價）−5 bps，手續費 0.1425% 與證交稅 0.3%。來回 58.5 bps 同[共同口徑](#共同口徑)。
- 漲跌停價照[出場規則研究](#出場規則研究)（`exit_research.price_limits`，前一根收盤換到當根價格基準）。
- 買進那根一字鎖漲停（最低 ≥ 漲停價）不買，那份錢留現金到下一輪；停牌或沒有日線也不買。
- 賣出那根一字鎖跌停（最高 ≤ 跌停價）、停牌或沒有日線：順延到下一根都不是的開盤賣，期間以最後收盤計價。順延的賣出在開盤成交，回收的錢當根可用。
- 到 cutoff 還沒賣的部位以最後收盤計（報告列「期末未賣」，含正常持有中的部位）。
- 報酬以還原後價格計（除權息計入報酬）。

**基準與參考線**
- 母體（基準）：同一套引擎，每日名單換成當日全部母體（[共同口徑](#共同口徑)），同樣的 K、子帳戶、成本與漲跌停。兩者的差只來自選股。
- 加權指數（基準）：`TAIEX` 收盤，不扣成本。它是價格指數、不含股利，組合用還原價，所以對加權指數的超額偏高約一年股利率。
- 候選池全部等權（參考線）：同一套引擎，每日買排序後的整個候選池。只列出，不判定、不算比較組數。「前 N 名 − 候選池」是排序本身的貢獻，「候選池 − 母體」是入池條件的貢獻。

**指標**：每組 N × K、候選池與母體，在全期、探索段、驗證段（依日期，[共同口徑](#共同口徑)的切分）各列：
- 年化報酬（每日淨值，252 日年化）、年化波動、最大回撤、平均投入比例、年化換手（買進金額 ÷ 前一日淨值的總和，年化）、買進筆數。
- 超額報酬：每日組合報酬 − 每日基準報酬，取日均與年化（日均 × 252）；t＝日均 ÷（標準差 ÷ √日數）。每日淨值的報酬不像 T+N 報酬逐日重疊，所以用一般 t。
- 漲停買不到、跌停順延、停牌順延、期末未賣的筆數。

**判定**：寫死在 `portfolio_research.judge`，每組 N × K 對母體與對加權指數各判一次，由上往下取第一個符合的列。

| 判定 | 條件 |
| --- | --- |
| 無法判定 | 任一段交易日 < 60 |
| 贏過基準 | 兩段超額日均都 > 0，且 t 都 ≥ 2 |
| 輸給基準 | 兩段超額日均都 < 0，且 t 都 ≤ −2 |
| 沒有差異 | 探索段 \|t\| < 2 |
| 驗證段反轉 | 驗證段與探索段異號 |
| 方向一致但不顯著 | 其餘 |

**怎麼讀結果**
- 「照名單做贏」只認「贏過基準」；回撤、換手只列出，不參與判定。
- 同時比較 9 組 × 2 個基準＝18 組（研究規則第 4 條）。
- 之後的評分改版或規則改動，用同一個工具、同一組 N × K 與判定比較改前改後。

## 評分改版研究

這一段回答：用有證據的特徵排序，照名單買能不能贏過母體（[#689](https://github.com/YiCheng0608/stock-lab/issues/689)，設計在統籌決定 [6872130373](https://github.com/YiCheng0608/stock-lab/issues/689#issuecomment-6872130373) 時固定，看結果前不改）。只產報告，不改產品評分。

**工具**：`portfolio_research.py` 加 `--rankings 689`。先照[組合層級回測](#組合層級回測)跑第 1 版，輸出不變（不帶旗標時與 #682 逐位元組相同，測試以金樣鎖住）；再跑下面 3 個排序 × 2 個母體，各寫在 `<out>/<排序>-<母體>/`（檔案同第 1 版），並列總表在 `rankings.md`／`rankings.json`。

**排序**（字典序，特徵都是 `feature_evidence` 現有函式，T 日收盤後計算，T+1 開盤買）：

| 代號 | 主鍵 | 次鍵 |
| --- | --- | --- |
| `trust` | 投信近 5 日買超天數（大者先） | — |
| `trust_rev` | 同上 | 月營收創近 12 個月新高（1 先於 0） |
| `trust_eps` | 同上 | 最新一季 EPS 年化 ÷ 股價（大者先） |

- 主鍵是 T+5 唯一「有證據」的特徵；次鍵是 T+5「方向一致但不顯著」，只當對照。
- 特徵缺值排最後、不剔除。同分（主鍵只有 0～5，同分很多）以 `sha256("<T>:<instrument_id>")` 排序：固定、可重現、不帶任何特徵，「前 N 名」量到的只有特徵本身。

**母體**
- (a) 候選池內重排序：入池同第 1 版（同一批檔，只換順序），「前 N 名 − 候選池」是新排序的貢獻，可與第 1 版並列。
- (b) 全部可交易母體：每天的[共同口徑](#共同口徑)母體直接依特徵排序，不依賴現行進場規則；它的候選池就是母體，不另列參考線。`picks.csv` 每天只列前 20 名。

**其餘全部沿用第 1 版**：N × K 9 組、K 份子帳戶、成本、漲跌停、還原價、兩個基準、分段、指標與 `judge`。母體與候選池全部的模擬直接沿用第 1 版那次。

**怎麼讀結果**
- 比較組數：3 個排序 × 2 個母體 × 9 組 × 2 個基準＝108 組（研究規則第 4 條）。沒有真實效果時單組碰巧「贏過基準」約 0.05%（兩段 t 都 ≥ 2），108 組視為獨立時至少一組約 5%；各組共用主鍵與母體，實際更低。報告寫明。
- 結論以 `trust` 為主；`trust_rev`／`trust_eps` 只在 `trust` 也站得住時才看次鍵有沒有加分。
- 每組的 `summary.md` 的「候選池計數」是排序對象的計數（日數、檔次、各特徵缺值、主鍵＝5 的檔次）；耗時是排序部分從開始累計。

### 分段

所有假設共用同一組日期，不依回補補到哪一年而變。這一段的切分取代[共同口徑](#共同口徑)的切分，只用於本段的假設。

| 段 | 期間 | 用途 |
| --- | --- | --- |
| 探索段 | 假設的起日～2019-12-31 | 判定第一關 |
| 驗證段 | 2020-01-02～2024-09-27 | 探索通過的假設只跑一次（約 1,150 個交易日，含 2020 年 3 月急跌、2022 年空頭、2023～2024 多頭） |
| 已用段 | 2024-09-30～2026-11-13 | [#619](https://github.com/YiCheng0608/stock-lab/issues/619)～[#689](https://github.com/YiCheng0608/stock-lab/issues/689) 用過、第一批的籌碼方向也和它有關，只列出、不參與判定 |
| 保留段 | 2026-11-14 以後的新資料 | 就是前瞻驗證（照[前瞻驗證 H1](#前瞻驗證-h1)），不另切 |

- **起日**：假設需要的每一類資料，在上市與上櫃**都有值**的最晚起始日（#692 評估 [6873790108](https://github.com/YiCheng0608/stock-lab/issues/692#issuecomment-6873790108) 的表），加上特徵需要的暖機交易日數。寫在登記表，不看資料決定。
- **段長下限**：探索段 ≥ 500 個交易日、驗證段 ≥ 250 個交易日，不足記「無法判定」、不跑。
- **先決條件（倖存者偏差）**：研究 DB 要含期間內已下市公司的標的與日線；沒有就記「無法判定」、不跑。
- **只用當時已公開的資料**：月營收在法定期限（次月 10 日，遇休市順延到下一個交易日）之後才可用，季報在法定申報期限之後才可用（回補列的 `announcement_date` 就是這兩個日子）。事件日的 T 一律用這個可用日，不用資料的所屬月份或季度。

### 判定

引擎照[組合層級回測](#組合層級回測)第 1 版：`portfolio_research.simulate`（K 份子帳戶、T 日收盤後選、T+1 開盤買、成交那根算第 1 根、第 K 根收盤賣）、成本（買 5 bps 滑價＋手續費 0.1425%，賣 −5 bps＋手續費 0.1425%＋證交稅 0.3%，來回 58.5 bps）、漲跌停、停牌順延、還原價。基準是同一引擎、同一 N 以外條件相同的母體（每天買當日全部[共同口徑](#共同口徑)母體，`evidence_lib.universe`）；事件日調倉的假設，母體也在同一天以同一方式買賣。加權指數只列出。

每個假設在每一段算兩個量：
- **超額**：每日組合報酬 − 每日母體報酬，取日均與一般 t（日均 ÷（標準差 ÷ √日數）），同 `portfolio_research.judge`。
- **絕對報酬**：每日組合報酬（淨值已扣成本）的日均。它 > 0 就是「扣成本後期望值為正」；母體本身短持有就是負的（[#682](https://github.com/YiCheng0608/stock-lab/issues/682)：K＝5 年化 −30%），只贏母體不夠。

判定寫死在 `explore_judge`（工具另開單），由上往下取第一個符合的列：

| 階段 | 判定 | 條件 |
| --- | --- | --- |
| — | 無法判定 | 探索段 < 500 日、驗證段 < 250 日，或研究 DB 沒有已下市公司 |
| 探索 | 沒有通過（探索段） | 不是「超額日均 > 0 且 t ≥ 2，且絕對報酬日均 > 0」 |
| 驗證（只跑一次） | 通過 | 超額日均 > 0 且 t ≥ 2，且絕對報酬日均 > 0 |
| 驗證 | 驗證段反轉 | 超額日均 < 0 |
| 驗證 | 沒有通過（驗證段） | 其餘 |

勝率、回撤、換手、平均投入比例、對加權指數的超額、已用段的數字都列出，不參與判定。

### 多重比較

- 每個假設只登記**一組**參數（一個母體、一個排序或條件、一個 N、一個 K、一個基準），沒有參數格。#689 的問題是 108 組裡事後挑出 2 組，不是門檻太低。
- 一輪最多 8 個假設，門檻維持兩段 t ≥ 2。沒有真實效果時，單一假設兩段 t 都 ≥ 2 的機率約 0.023 × 0.023 ≈ 0.05%；一輪 8 個視為獨立，至少一個碰巧通過約 0.4%。
- 報告寫明「本輪 m 個、累計 M 個」；H1 與 #619～#689 的比較次數另列。累計超過 20 個之後，驗證段的門檻改用 Bonferroni：t ≥ 單尾 0.025 ÷ 累計數對應的常態分位數（例如 20 個約 3.0）。
- 沒有通過的假設的變形（換 N、K、門檻或母體）是新代號，在下一輪登記、計入累計。

#### 實作釋義

文件沒寫、由統籌決定 [6874888073](https://github.com/YiCheng0608/stock-lab/issues/703#issuecomment-6874888073)（2026-11-14，回覆設計提問 [6874879471](https://github.com/YiCheng0608/stock-lab/issues/703#issuecomment-6874879471)）補上的釋義；在任何人對回補資料跑工具之前決定。登記表與定義細節的原文不動。

- **起日**：「某日起第 N 個交易日」以有個股日線的交易日計，那一天（不是交易日時取之後第一個交易日）算第 1 個。起日是第一個訊號日 T，T+1 才有淨值。照登記表逐字：`momentum_120` 要 121 根日線，所以 X1 第一天的上櫃股多半缺值（排最後），不改成第 121 個。X4、X7 的起日不是交易日時取之後第一個交易日。
- **兩段各自獨立模擬**：探索段的訊號日從起日到 2019-12-31 的前一個交易日，淨值到 2019-12-31 收盤；驗證段從 1 重新開始，訊號日從 2020-01-02 的前一個交易日起（第一筆 2020-01-02 開盤買），淨值到 2024-09-27 收盤；已用段同樣從 2024-09-30 起。各段期末還沒賣的部位以最後收盤計（期末未賣）。段長以該段有淨值的交易日數計，在模擬之前算。
- **已下市公司**：該段有淨值的期間內，至少要有 1 檔 `stock`／`ipo`、`status = 'delisted'`、最後一根日線落在期間內的標的；只讀日期、不讀價格。`transferred`（轉板）不算。
- **60 日平均成交金額**：往前 60 根日線（停牌的根也算一根）中，任一根的 `turnover_status` 不是 `available` 就缺值（舊資料的 `turnover` 預設是 0，不能當成真的 0）。缺值不進前 50／150 名，同金額以雜湊排序。
- **X7 的金額與順延**：一個帳戶；每檔＝事件日 T+1 開盤時帳戶現金 ÷ 20，不足 20 檔留現金。T′ 跌停一字鎖、停牌或沒有日線時，順延到下一根可賣的開盤；順延回來的錢留現金，到下一個事件日才用。T′ 在段外的部位以段末收盤計。驗證段第一個事件日是 2020-01-10（淨值從 2020-01-13 起）。「最新已知月份是上個月」＝`announcement_date ≤ T` 的最新 `revenue_month` 是 T 的前一個月。母體用同一個帳戶規則、同一組事件日。
- **X8 的順延與「選過」**：清單日期不是交易日（週末、休市日）時，T＝之後第一個交易日。「選過」＝進入當日名單（在母體內、經 20 檔上限後），不論有沒有買到；「前 20 個交易日」＝T 之前的 20 個交易日（不含 T）。先去掉 20 日內選過的，再以雜湊取前 20 名；同一檔同一天多則只算一檔。選股紀錄從假設起日（或讀到的第一個交易日）連續算，不因分段重設。調倉用 `simulate`（K＝20），沒有公告的日子該子帳戶留現金，所以 X8 的平均投入比例遠低於母體。
- **勝率**（只列出）：該段買進的每一筆，賣出所得 ÷ 成本 − 1 > 0 的比例；期末未賣以最後收盤（不扣賣出成本）計，另列筆數。

**定義細節**
- **60 日平均成交金額**：T 日（含）前 60 根日線 `market_bars.turnover`（官方成交金額，未還原）的平均；不足 60 根缺值。它是大型股的**代理，不是市值**：DB 沒有歷史發行股數。不用「還原價 × 成交量」，因為還原價會壓低早年的金額。
- **X7 事件日調倉**：事件日 T＝每月 10 日（遇休市順延到下一個交易日），即上個月營收的法定期限。T 日只取最新已知月份是上個月、且 `revenue_high_12`＝1 的股票，依 `revenue_yoy` 大者先取前 20 名。單一帳戶：全部資金在 T+1 開盤等權買（每檔上限 1／20，不足 20 檔留現金），持有到下一個事件日 T′ 的收盤賣，T′ 選出的新名單在 T′+1 開盤買。母體同樣在 T+1 全買、T′ 收盤賣。成本、漲跌停、停牌順延同 `simulate`。工具要新增這種調倉。
- **X8 主旨規則**：T＝重大訊息清單（`t05st02`）的日期；主旨同時含「董事會」、「決議」或「通過」、「買回」，以及「庫藏股」或「股份」，且不含下列任何一個詞：`註銷`、`轉讓`、`執行情形`、`執行完畢`、`已執行`、`執行期限`、`辦法`、`減資`、`屆滿`、`完畢`、`達`、`變更`、`公司債`、`子公司`、`更正`、`補充`、`取消`。符合且 T 日在母體內的公司，T+1 開盤買，持有 K＝20；同一天超過 20 檔依雜湊取前 20 名；同一檔在前 20 個交易日內已被選過就略過（只算第一次公告）。

## 限制

- 歷史只有 2024-09-30 起的一段，驗證段只有一段；結論可能只適用這段市況。
- 回補的月營收與季報是現在抓到的數字；事後更正過的值無法還原成當時公布的版本，可用日也是法定期限而不是實際公告日。[新策略探索](#新策略探索)用到它們的假設都有這個限制。
- 等權的母體平均不是可交易的基準；報酬不含部位大小、漲跌停買不到與成交量限制。
- 當日籌碼視為收盤後已知，與現行規則的假設相同（[共通原則](README.md#共通原則)）。
- 月營收自 `announcement_date` 起才算已知；正式 DB 自 2023-09 起（2026-11-13 回補，[#1](https://github.com/YiCheng0608/stock-lab/issues/1#issuecomment-6846371519)），2024-09-30 起每一日都有往前 12 個月的值。
- 季報的 EPS 是年度累計值，單季值由相鄰兩季相減；自 `announcement_date`（回補的季度是法定申報期限）起才算已知。正式 DB 自 2023Q1 起（2026-11-13 回補），年增需要的去年同季與它的前一季在探索段全程都有（[#671](https://github.com/YiCheng0608/stock-lab/issues/671) 重跑：探索段 287 日都有值）。EPS 除以還原後的收盤價，分割前後會有落差。ROE 目前沒有資料，不在特徵裡。
- 族群條件與新聞情緒需要當日的榜單與 AI 判讀，不在特徵證據工具裡；它們由成績單的分項排序相關間接檢查。
